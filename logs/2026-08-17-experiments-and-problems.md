## 一、新增两个实验

选这两个是有理由的：

| 实验 | 为什么选它 |
|---|---|
| **页面置换**（FIFO/LRU/OPT/CLOCK） | OS 核心考点；结构跟 Cache 极近（都是"有限容量 + 替换策略"），复用度高；**Belady 异常**是绝佳教学点 |
| **磁盘调度**（FCFS/SSTF/SCAN/C-SCAN/LOOK） | 视觉形态跟已有的全都不同（一维磁头轨迹折线），**再验一次渲染层可替换** |

### 验证方式：不抄记忆里的教科书数字

纪律：**不写"教科书说 FCFS 是 640"这种从记忆里来的断言。**
要么在测试里用**跟内核无关的简单公式独立算一遍**，要么验**性质**。

| 判据 | 怎么立的 |
|---|---|
| FCFS 总寻道 | 测试里独立按顺序累加 `Σ\|req[i] − prev\|` → 640，与内核一致 |
| SSTF 总寻道 | 测试里独立写一遍贪心 → 236，与内核一致 |
| Belady 异常 | 断言的是**性质**（4 块 > 3 块），不是记住的数字。实测 9 → 10 ✅ |
| LRU 无异常 | 栈式算法，块多不会更差。实测 10 → 8 ✅ |
| OPT 是下界 | 断言 OPT ≤ 其余全部。实测 OPT 7 ≤ FIFO 9 / LRU 10 / CLOCK 9 ✅ |
| LOOK ≤ SCAN | LOOK 省掉走到边界的空跑。实测 299 ≤ 331 ✅ |

640 / 236 跟经典教材数字吻合 —— 但那是**独立算出来之后的额外佐证**，不是断言的来源。

### 自检也带了

- FCFS 的独立公式：改动 1 个单位即不等 → 有鉴别力
- 下界判据：FIFO 9 ≥ OPT 7 → 若内核把 OPT 写成 FIFO，第 3 项会红

## 二、验证器踩到的一个坑

加新 kind 时发现 `ENUMS` 是**扁平表**（按字段名索引）：

```ts
// 错的
const ENUMS = { algorithm: ['FCFS','SJF','SRTF','RR'], ... }
```

但 `algorithm` 在三个实验里意思完全不同：

| kind | algorithm 的合法取值 |
|---|---|
| scheduler | FCFS / SJF / SRTF / RR |
| page | FIFO / LRU / OPT / CLOCK |
| disk | FCFS / SSTF / SCAN / C-SCAN / LOOK |

扁平表会把页面置换的 `LRU` 判成非法。**改成按 kind 分表。**

> 教训跟前面那条同源：**同名字段在不同领域下含义不同，索引就不能只用字段名。**
> 这跟 `Tone='hit'|'miss'` 泄漏 Cache 词汇是同一类错误的两个面。

## 三、真题系统

### 核心设计：答案不手写，从轨迹派生

```ts
type Question = {
  prompt: string
  answer: (trace, doc, runDoc) => string   // ← 派生，不是常量
  revealStep?: (trace) => number           // ← 答完跳到哪一步看原因
  hint?: string
}
```

三个理由：
1. **人手写答案会写错**
2. **配置一改，答案自动跟着变** —— 学生改参数探索时，答案仍然正确
3. **这是验证器在为学生工作**，而不只是为 AI 把关

第一版我在两道题里写了硬编码答案（Belady 的 `'10'`、FCFS 的 `'640'`），
因为那两问要"改个参数再算一遍"。**这违反了自己定的规矩**，
所以给答案函数补了一个 `runDoc` —— 能跑任意配置，答案仍然是派生的。

### 杀手锏：跳到那一步看为什么

答错之后有个「跳到第 N 步看为什么 →」按钮，直接把时间轴移到能看出答案的那一步。

**这是仿真器能做而课本做不到的事**，也是"有题的实验才是产品"的具体形态。

### 偏离原题要明说

选了真题就用真题的配置，但**参数仍可改**（改了就是在探索变体）。
一旦改动，面板上明说「配置已被改动，下面的答案是按当前配置算的」，并给「恢复原题配置」。

不这么做就会出现"学生改了参数，还在对着原题答案"的静默错误。

## 五、测试覆盖

引擎侧 6 套：

```
阶段 0 · 收敛与确定性（标准 2 / 4）
parameter 轴 · 高阶内核
标准 5 · 内核可插拔
标准 6 · DSL 是唯一入口
L2 · 组合原语 compare
新内核 · 页面置换 / 磁盘调度      ← 本轮新增
```

前端冒烟 6 组：

```
【1】5 个实验都能起来 + 五个舞台的 DOM 结构互不相同   ← 新增后半句
【2】标准 3：改一个状态多视图一起变
【3】参数改动 → 重跑仿真
【4】验证器直通 UI
【5】第二个 tab 真的是另一个视图
【6】真题：选题 → 载入配置 → 判题 → 跳转 → 偏离提示   ← 本轮新增
```

第 6 组里有一条特别设计的检查：**先故意填错，拿到它给出的"正确答案"，再填回去必须判对。**
这验证的不是判题逻辑，而是**答案确实是从轨迹派生的**（如果是硬编码，这条一样会过 ——
所以它配合第一条"改参数后答案跟着变"才完整）。

第 1 组新增的"五个舞台 DOM 结构互不相同"也是同理：
防止"五个实验其实长一个样"这种退化。

## 六、仍然没做的

- **访问序列 / 引用串 / 请求队列都不可编辑** —— 这三个实验最该让学生改的恰恰是它们
- **每个实验只有 1 道题** —— 离"够刷"还差得远
- **没有真实出处** —— 等有可核对来源
- **没有学习进度 / 错题本** —— 留存的关键，还没动
- **分享链接 + 录制导出** —— 按你的意思放到最后
