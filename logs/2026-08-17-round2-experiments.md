## 二、为什么是这四个

| 实验 | 选它的理由 |
|---|---|
| **排序逐趟** | 数据结构考频第一，几乎必考"第 N 趟结果"。**一个内核吃下 7 种算法**，性价比最高 |
| **Dijkstra** | 图论考频第一。顺带证明**图结构能用现有 entities 表达**，DSL 不用加顶层概念 |

## 三、内核测试逮到的三个真 bug

判据一律"跟内核无关的独立算法"或"性质"，不抄记忆里的教科书数字。

| 判据 | 怎么立的 |
|---|---|
| 7 种排序末态 | 用 JS 自带 `sort` 独立算 —— 与被测内核完全无关 |
| 冒泡逐趟 | 测试里独立再写一遍冒泡，逐趟比对 |
| Dijkstra 全对 | 用 **Bellman-Ford**（另一个算法）算 7 源点 × 7 终点 |
| 银行家安全序列 | 拿它给的序列，用独立代码重放一遍资源收放 |
| SR vs GBN | 验**性质**：同一次丢包下 SR 重传严格少于 GBN |

### bug 1：插入排序/快排"凭空多一个数"

第 2 条判据（每步都必须是原数组的排列）直接红了。原因是**挖坑法**：
`a[j+1] = a[j]` 时真正的值被端在手里，数组里留下的是旧副本。

我原来把那格照原样画出来 —— 学生会以为数组里凭空多了一个数。
**教科书画的是空位 + 手持值**，所以加了 `hole` / `held` 两个字段，
不变式也跟着改成「数组挖掉空位、补上手持值 = 原多重集」。

> 判据红了不一定是内核错，也可能是**判据本身没描述对领域**。这次两边都要改。

### bug 2：`settled` 对插入排序在撒谎

我给插入排序标了"前 p 个已就位"。**假的** —— 插入排序的前缀只是*局部有序*，
后面还会被挤动。这跟冒泡/选择/快排/堆的"最终位置"是两回事。

拆成两个字段：

| 字段 | 含义 | 谁有 |
|---|---|---|
| `settled` | **已定最终位置**，之后不再动 | 冒泡 / 选择 / 快排 / 堆 |
| `sorted` | **局部有序但还会移动** | 插入 / 希尔 / 归并 |

这恰好是学生最容易混的一处，现在颜色上就分开了。
希尔的 `sorted` 还是**跳跃下标集**（同增量子序列），不是连续区间 —— 这才是希尔的可视化重点。

### bug 3：SR 的 ACK 发错了，协议死循环

`transmissions = 505`，交付卡在 6/8。原因：SR 收到失序帧后，我回的是
累积确认 `expected-1`，导致发送方永远收不到 2/3/4 各自的确认 → 无限重传。

**SR 必须逐帧确认，收到哪个确认哪个**（重复帧也要再确认一次，否则发送方死等）。
改成 `ackSeq = protocol === 'SR' ? f.seq : expected - 1` 之后：GBN 12 次 / SR 9 次，
两个协议的差别正好显出来了。

## 四、视图层逮到的四个真 bug（都是"数据对、教出来的东西错"）

### bug 4：银行家第 1 步就把答案摊开了

`bverdict` 取的是 `trace.at(-1)`，所以刚打开就写着
「安全状态 · 安全序列 P1→P3→P4→P0→P2」，而下面还是「还没开始试探」。

**学生还没推，答案先到了 —— 这个实验就白做了。**
改成只在走到末步才出结论，之前显示「推演中 N/5」。

> 跟上一轮 Cache「换出语义画反」是同一类错误：**数据没错，但教出来的东西是错的。**
> 冒烟测试里补了一条会红的检查：第 1 步的判定必须是「推演中」且序列为空。

### bug 5：丢失的帧被画成了绿色

CSS 特异性打架：`.amsg.frame.seen`（0,3,0）压过了 `.amsg.lost`（0,2,0）。
丢的帧画成正常绿色 —— 时空图里最该看见的东西看不见了。
改成 `.amsg.frame.lost, .amsg.ack.lost`。

### bug 6：GBN 回退重传的 4 帧精确重合，看不见

超时后 GBN 一次重发 base..next-1 全部帧，它们同一时隙发出 → 同一 y →
**四条线精确重合成一条**。而"回退 N 帧"这个名字的全部含义恰恰就在那一刻。

给同时隙的报文加了纵向扇形偏移 + 标签横向错开，现在那一簇一眼能看出来。

### bug 7：「帧0」读成"零帧"

读数栏里 `帧0` 是"帧 0 号"的意思，但读起来像"零帧"。补了空格。
另有两处：快排的"趟"其实叫**划分**、希尔的"趟"对应**增量**，
一律写"第 N 趟"会跟教材对不上 —— 按算法给不同的说法。

## 五、顺带解决的架构问题

- **图结构进 DSL**：`{type:'node'}` + `{type:'edge', attrs:{from,to,w}}`，
  顶点坐标也放 attrs —— **让文档定布局**，换个前端也画得一样。没有新增顶层概念。
- **参数面板可以为空**：银行家的自由度在资源矩阵里，不在标量参数。
  与其造个假参数凑一栏，不如留空并说明白（`paramsNote`）。
- **验证器新增四类规则**，都是"schema 管不了"的那种：
  Dijkstra 拒负权边（算法前提）· 银行家拒"已分配超过总量"（状态本身非法，不是"不安全"）·
  ARQ 拒 `timeout ≤ 2×delay`（ACK 还没回来就重传，永远收敛不了）。
