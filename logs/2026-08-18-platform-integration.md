# 2026-08-18 · 并入虾米伙伴（虾米做实验 · /lab/）

**结论**：本仓从一个单跑的 Vite 站，变成虾米伙伴的第五个模块。
路由、身份、外观、数据四件落地，计费**不适用**（运行时不调模型）。
引擎测试 **15 套**、独立形态冒烟 **12 组**、并入形态冒烟 **14 项**全绿，控制台零错误。

参照 [wiki/27 · 虾米看股并入虾米伙伴](../../wiki/27-stock-lab-platform-integration.md)
的五件事表格，本仓的落点：

| | 要解决的 | 本仓落点 |
|---|---|---|
| 路由 | 用户从主站点进来，URL 得对 | `VITE_BASE=/lab/` + Caddy `handle_path` |
| 身份 | 谁在用 | 同源 Cookie，**不设门**（页面公开，登录只影响进度同步） |
| 外观 | 看着得像同一个产品 | 运行时加载主站 `/chrome` 制品 + 令牌同步进仓 |
| 数据 | 换台设备还认得你 | `app.lab_progress` + `/v1/lab/progress`，合并在前端 |
| 计费 | — | **不适用**：本仓运行时一次模型都不调 |

---

## 一、没有自己的后端，是这次最大的简化

虾米看股要 `/stocks-api/*` 反代前缀，是因为它有一个自己的 FastAPI 进程。
本仓一个都没有：**纯静态 + 主站的 `/v1/lab/progress`**，同源 Cookie 自动带上。
于是 Caddy 片段里只有一条 `handle_path /lab/*`，没有第二条。

代价是学习进度这件事要在主站后端开一组接口 —— 换来的是不用再守一个进程、
不用再配一份 systemd、不用再想它的日志去哪。

## 二、云端只存整份 JSON，合并放在前端

`app.lab_progress` 一个用户一行，`payload JSONB` + `rev BIGINT`。
后端**不懂**记录的语义，只做「整份读 / 带版本号整份写」。

合并规则要判断「同一问在两台设备上，哪一次作答更近」—— 那是前端的事。
两处各写一套规则，迟早不一致。

### rev 是必须的

没有它的话，两台设备各写一次 = 后写的把先写的整份盖掉，
而这份数据是「昨天做的 20 道题」，盖掉了没有任何地方找得回来。
客户端提交时带上自己读到的 rev，对不上就 409 + **把当前值一起回给它**，
由它重新合并再提交（只重试一次；还撞就等下一次改动，本地那份没丢）。

### 合并不精确，而且说清楚了

- **次数取较大值，不是相加。** 两台设备第一次登录时带着同一段本地历史，
  相加会把一次作答数成两次 —— 错题本显示「错过 6 次」而你只错过 3 次，
  比少数更糟，因为这个数字是用来判断「我是不是真不会」的。
- 代价是**真·分头做题时会少算**。进度面板上原话写着这一条。
  要精确就得每次作答带唯一 id 存成事件流，那是另一个量级的东西，
  而「该复习哪些题」根本不需要精确的次数。
- 「最近答对没有」这类**状态**字段整组取自更近的一次，不逐字段各取各的 ——
  那会造出 `streak=2` 却 `lastCorrect=false` 这种两边都不曾发生过的状态。

## 三、这一轮逮到的三个问题

### 1. 合并不满足交换律，而随机用例跑 40 组全绿

`lastAt` 相同时固定取左边，于是 `merge(a,b)` 与 `merge(b,a)` 结果不同 ——
**谁先登录决定了你的错题本长什么样**。

绿灯的原因是我把 `lastAt` 的取值范围造到了十万，40 组样本一次平局都没撞上。
`Date.now()` 在同一毫秒里能返回两次，而合并的两份记录本来就常常同源，
平局根本不是假想的情况。

修法两件：平局改成**全序**比较（先比 lastCorrect，再比 streak，取更保守的那条）；
样本的 `lastAt` 只取 6 个值，**往可疑的地方压**。
并加了一条自检：拿旧规则跑同一批样本，必须报出不对称 —— 现在报 20 处。

> 随机用例的覆盖面不是越宽越好。

第一版的修法还只修了一半：`rank = lastCorrect ? streak : -1`，
两条都「最近答错了」时 rank 都是 -1，又退回取左边。**判据第二次才真的会红。**

### 2. 一条 `INSERT … SELECT … WHERE` 让所有正常更新变成 409

想让「新建」这条路也受 `base_rev` 约束，写成了

```sql
INSERT … SELECT %s, %s::jsonb, 1, NOW() WHERE %s = 0
ON CONFLICT (user_id) DO UPDATE SET … WHERE rev = %s
```

`base_rev ≠ 0` 时 SELECT 选不出行，**INSERT 压根不执行**，`ON CONFLICT` 自然轮不到 ——
更新路径整条死掉。改成两个互斥的 CTE（`ins` 管新建、`upd` 管更新）。

### 3. 平台页眉一打开就被滚出屏幕

本仓的逐步日志用 `scrollIntoView({ block: 'nearest' })` 跟着当前步走。
`nearest` 听起来克制，其实它会把**每一层**可滚动祖先都调整到位，**包括视口本身**：
日志卡片在首屏之下时，浏览器就把整页往下滚一段。

单看本仓时这只是「开页面自己往下挪了 28px」，没人在意。
并入之后挪的量变成 80px（多出来的正好是平台页眉那 52px）——
**打开 /lab/ 的第一眼，平台页眉已经不在了**，而它存在的全部意义就是让人认出这是虾米伙伴。

改成自己算 `box.scrollTop`，窗口一次都不碰。

## 四、判据本身修了两次

| 缺陷 | 修法 |
|---|---|
| 「不存在的资源要回 404」在 dev 模式下必然红 —— Vite 自己会回退 index.html，跟线上的 Caddy 无关 | 检测到 dev 就**如实说「这一条没验」**，不判红也不判绿 |
| 跨设备合并的用例随手编了个题号 `zzz-别的题#0`：云端两条都在（合并是对的），错题本却只有 1 条 | 错题本只列得出题库里有的题 —— 换成真实题号 `page-1#0`。**判据当场看着像 bug，其实是我给的数据不在题库里** |

## 五、探测会在控制台留下红字

第一版判断「有没有主站」是去 `fetch('/chrome/manifest.json')`，404 就当没有。
逻辑没问题，但浏览器对任何 404 都会打一条 `Failed to load resource` ——
独立跑的时候一开页面就是两条红的（另一条是 `/v1/session`），
而本仓的冒烟有一条判据正是**「控制台无错误」**。它立刻就被这两条噪声废掉了。

改成抄虾米看股那条：**判据用挂载路径**（`web/src/platform.ts`）。
`VITE_BASE=/lab/` 出来的产物才去打主站，独立形态与单文件产物一次请求都不发。
实测单文件产物在 `file://` 下：30 个实验都在、对外请求 0 条、控制台 0 错误。

> 一个必然失败的请求不该让一条真判据变成噪声。

## 六、有意没做的

- **字号缩放旋钮（`--xm-font-scale`）在本仓不生效。** 253 处字号是手调的硬编码 px，
  10px 的等宽标签、9.5px 的分组名 —— 密度是这套仪表盘的设计本身。
  逐个套 `calc()` 会得到 253 行噪声，换一个没人要求过的旋钮。
  要做就整套重排字阶，不是加一层乘法。**这是明说的，不是漏做的。**
- **配色不统一。** 令牌文件自己写着不放各应用的 surface / ink：
  本仓是深色仪表台，主站是浅色平台页，压成一个用户反而分不清自己在哪。
  唯一补的一处是平台页脚的背景 —— 它本来没有背景色（主站正文是浅色，继承就够了），
  挂在本仓的 `#14141C` 上就是深底深灰字。补的时候取 `var(--surface-card)` 而不是抄色号。
- **`status` 保持 `planned`。** 和虾米看股、虾米看AI 同一条纪律：这个字段只是
  「运营台还没保存过时」的兜底默认值，兜底要偏安全。本仓页面是公开的，
  **藏入口是唯一的一道门**，翻成 live 就等于对外公布。
