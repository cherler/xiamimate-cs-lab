# 2026-08-17 · 阶段 0：DSL 收敛验证

**目的**：拿三个差异最大的实验同时挤一个 DSL，看抽象立不立得住。
挤不动的话，现在改比三个月后改便宜得多。

**结论**：**通过**。一个 `SimDocument` 表达了三个实验，轨迹跟独立参考实现逐字段一致。

---

## 做法

1. 先各自独立写三个实验的 DSL + 参考实现，**不预设任何统一抽象**，让它们长成本来该长的样子
2. 找公共骨架和真正的差异点
3. 收敛成一个 schema
4. 判决标准：统一管线产出的轨迹，必须跟独立实现**逐字段相同**（`exact` 比较器）

选这三个是因为它们的"驱动输入"形状最不一样：

| | 驱动输入 | 轴 | 状态大小 | 终止条件 |
|---|---|---|---|---|
| Cache 命中率 | 密集序列 `number[]` | step | 大（整个 cache 数组） | 序列耗尽 |
| 进程调度 | 实体集合带时间属性 | time | 中（队列 + 剩余表） | 全部完成 |
| TCP 拥塞窗口 | 参数 + 稀疏事件 | time | 小（3 个标量） | 轮次上限 |

---

## 结果

```
【测试 1】统一 schema vs 独立参考实现（exact）
  ✅ Cache  8 步    ✅ 调度 16 步    ✅ TCP 14 步

【测试 2】确定性重放（第 k 步截断 → JSON 往返 → 续跑）
  ✅ Cache（第 4 步）  ✅ 调度（第 7 步）  ✅ TCP（第 6 步）

【测试 3】自检必须能红
  ✅ 标准4：中间过程被篡改，抓到 5 处
  ✅ 标准2：step 里有随机源，两次运行对不上
  ✅ tolerance：放过 1e-7 噪声，抓住 0.5 真差异
```

补测 parameter 轴（四种轴里最后一个没跑过的）：

```
  ✅ 轴 = { kind: 'parameter', label: 'associativity' }
     associativity=1  → 命中率  0.0%（0/12）
     associativity=2  → 命中率  0.0%（0/12）
     associativity=4  → 命中率 75.0%（9/12）
     associativity=8  → 命中率 75.0%（9/12）
     associativity=16 → 命中率 75.0%（9/12）
  ✅ 曲线单调不降   ✅ 确定性重放   ✅ 自检变红
```

手验：256B/16B，三个地址 `0x000/0x100/0x200` 在任何相联度下都落同一组。
1 路互踢 → 0%；**2 路仍 0%（3 个地址挤 2 路，LRU 抖动）**；≥4 路装得下 → 3 次冷缺失 + 9 次命中 = 75%。
相联度 2 那个 0% 是个好教学点。

## 收敛逼出的真问题（本次最大收获）

**三个独立参考实现全都违反了验收标准 2。** 它们把状态藏在闭包里：

| 实现 | 藏了什么 | 后果 |
|---|---|---|
| Cache | `sets` 数组 | 中途 dump 拿不到 cache 内容 |
| 调度 | `sliceLeft` | RR 的时间片续不上 |
| TCP | "push 之后才更新的 cwnd" | 藏在控制流里，根本序列化不了 |

三个跑起来都完全正确，但**都没法中途存档再续跑**。
如果不做这次收敛，这个问题要等到实现时间轴回放时才炸 —— 那时候三个内核全要返工。

修法：状态改成自足的（深拷贝 + 把隐藏变量提到 state 上），测试 2 才过得去。
TCP 那个尤其别扭 —— 得同时记 `cwnd`（本轮显示值）和 `nextCwnd`（下轮起点），
因为无事件轮次里这两个不是同一个值。

**这就是"建架构本身就是在检验想没想明白"的具体形态。**

## 被数据证实的设计判断

### `entities` + `streams` 的二分是必要的，不是凑数

- 调度的 `processes` 和 TCP 的 `lossEvents` **确实是同一个形状** —— 带 `at` 时间锚点的记录 → 合并成 `entities` ✅
- Cache 的 `accessSequence` **确实不是** —— 1000 个地址写成 1000 个 entity 对象会把 JSON 撑爆，
  而且每项没有独立元数据 → 必须留 `streams` ✅

原本担心这是"为了统一而拼接"，测下来是真的两种东西。

### 高阶内核成立，"step 内部是内核私事"扛住了压力

`sweep.ts` 的 `step()` 里跑了一整个子仿真（一次完整的 cache 模拟），
外层 `run()` 完全无感。这是对验收标准 5（内核可插拔）最强的一次验证。

### 结构化输出的三条硬约束都满足

| 约束 | 现状 |
|---|---|
| 不能递归 | Document 深度固定 3 层（doc → entities[] → attrs）✅ |
| 不能有数值约束 | "cacheSizeBytes 必须是 2 的幂"不在 schema 里，交给验证器 ✅ |
| 扁平 | `attrs` 是 `Record<string, number\|string\|boolean>` ✅ |

## 过程中翻的车

1. **`npx tsx` 能跑 ≠ 依赖装好了。** 子进程 `node --import tsx` 解析不到包，两套测试全炸。
   根因是没 `npm install`。
2. **写出了一个假绿。** `tsc --noEmit 2>&1 | head -20 && echo "typecheck 通过"` ——
   `head` 成功了 `&&` 就成立，echo 照样打印"通过"。而 `tsc` 当时根本没装。
   *现场版的"不会红的检查等于没有检查"。* 改成看退出码。
3. **50 条 tsc 报错，根因只有一个**：`@types/node` 没装。装完退出码 0。

## 还没验的

- **验收标准 3（单向数据流）** —— 还没有视图层，阶段 1 补
- **验收标准 5 的空内核自检** —— 高阶内核是强验证，但"什么都不做的空内核"还没塞过
- **验收标准 6 的自检** —— "删掉代码只留 JSON 能重建"还没实测
- **AI 真的能填这个 schema** —— 需要把 TS 类型转成 JSON Schema，接真实 API 打一发（要花钱）
- **`compile()` 的真实形态** —— 三个都近乎恒等映射，接缝存在但没被真正拉伸过。
  `sweep.ts` 里由外层 doc 派生 N 个内层 doc 算是第一次轻度拉伸；
  真正的考验要等手搓 CPU 的网表提取
