# 2026-08-17 · 实体表可编辑

**结论**：进程表 / 图的边 / 银行家资源矩阵 / 丢包事件（TCP + ARQ）全部可编辑，
带 19 个实体预置。至此**九个实验的输入全部开放**。
引擎测试 8 套 + 前端冒烟 10 组全绿。

---

## 一、跟序列编辑器同源，纪律照搬

改的仍是 `doc.entities`，没有绕过文档层（标准 6）。三条纪律原样搬过来：

1. **半截输入不喂给仿真** —— 正在敲的那一格用本地草稿显示，`cellOk()` 通过才提交。
   清空一格会标红，但轨迹停在上一次有效值。
2. **编辑器永远在「配置不合法」分支之外** —— 否则学生把进程表改坏了就再也改不回来。
3. **预置的 note 是能被证伪的主张**，由测试逐条验。

两个新形状带来的额外设计：

| 问题 | 处置 |
|---|---|
| 银行家的列数取决于 `params.resources` | `columns` 做成 `(doc) => EntityColumn[]` 的函数 |
| 银行家有资源表 + 进程表两张表共用一个 `entities` 数组 | `replaceType()` 整组插回该类实体**首次出现的位置** |
| Dijkstra 顶点坐标是布局信息，学生填 x/y 没有教学价值 | 只开放边（端点 + 权），顶点固定 A–G，写进边界栏 |

## 二、React key 的坑

第一版用 `key={row.id}`。编辑「进程名」那一列时，id 每敲一个字符就变
→ key 变 → 输入框被重建 → **焦点当场丢掉，只能敲一个字**。
改成按下标做 key。

## 三、实体表可编辑之后，验证器得补四类规则

这些状态在实体不可编辑时根本到不了，现在都成了一键可达：

| 规则 | 为什么 |
|---|---|
| 进程名 / 事件编号重复 | 甘特图会把两个 P1 画成一个 |
| 图的自环 A→A | 最短路里没有意义 |
| 图的重边 | 无向图下 A-B 与 B-A 是同一条；重边会让「松弛一次」变成两次，步骤对不上教材 |
| 银行家已分配 > 总量 | 这是**状态本身非法**，不是「不安全」—— 两者必须分开 |

最后那条在冒烟测试里专门验了一次：把 A 总量降到 7 → 判定变「不安全」；
降到 1 → 判定变「配置不合法」。**同一个操作方向，两种完全不同的结论。**

## 四、逮到的两个真 bug

### bug 1：调度器轨迹少跑一步，末态永远显示「已完成 3/4」

`step()` 结算完最后一个进程之后直接 `return null` ——
**「全部完成」这件事被算出来又扔掉了**，轨迹里没有任何一步记录它。
界面上那句「已完成 3/4」就是它的可见症状，一直挂在那儿没人注意。

修完 phase0 的 exact 比较立刻红了：统一内核 17 步，独立参考实现 16 步。

**两份独立实现撞了同一个盲点。** 这不是实现分歧，是规格问题 ——
「轨迹必须包含全部完成的那一刻」。两边按同一条理由各自补上，
exact 比较随即恢复通过（16 → 16）。

> 阶段 0 那次是参考实现帮统一内核抓出了三个 bug。这次反过来：
> 两边一起错，只有**盯着界面**才发现。测试互相印证挡不住共同的盲点。

### bug 2：舞台识别选择器第三次误报

冒烟测试用「中列第几张卡片」认舞台，每加一个编辑器就误判一次
（序列编辑器一次，实体编辑器一次）。
**判据写在根因上**：给舞台套一层 `.stagewrap` 容器，选择器认容器，不再靠数卡片。

## 五、预置说法被证伪的两条

19 个实体预置逐条验，当场倒了两条：

| 原说法 | 实测 | 处置 |
|---|---|---|
| 护航效应「FCFS 平均周转远大于 SJF」 | **21.50 = 21.50，一模一样** | 改说法：长作业已经在跑，非抢占 SJF 插不进来。只有抢占式 SRTF 能救（降到 8.75） |
| 连丢两帧「GBN 要回退两次，差距拉大」 | GBN **12 → 12，一点没变** | 改说法：5 号帧的重发本来就在 2 号帧那次回退的批次里，一次回退补两个洞；反倒是 SR 多补一帧（9 → 10） |

第二条改完反而更有意思：它说明 **GBN 的批量重传会"吸收"多个丢包**，
这是只有跑起来才看得见的性质。

判据一律用相对关系或独立算法：
```
调度      平均周转独立算（完成时刻 − 到达时刻），不看内核内部怎么记账
图        每个预置先过验证器（自环/重边/负权），再验最短距离
银行家    拿它给的安全序列独立重放一遍资源收放
TCP       只有超时时 Tahoe 与 Reno 的 cwnd 序列必须逐轮完全一致
ARQ       丢 ACK 时 GBN 必须零重传（累积确认补上）
```

顺带修了测试自己的两个错：完成时刻取 `st.t` 而非 `st.t+1`（内核补了末步之后）；
`SW` 的窗口只能是 1，之前一律传 4，被验证器拦下 —— **是测试传错参数，验证器没错**。

## 六、界面上调了三处

- **表格不再强制 100% 宽**：两列的资源表会被拉成两条巨长的输入框
- **宽度钉在输入框上**：靠 `width:100%` 的话，输入框的固有宽度（`size` 默认 20 字符）会把表撑开
- **窄表折栏**：12 条边挤成细长一条、右边全空 → 每 6 行折一栏并排放。
  折栏最容易错的是下标映射，冒烟里专门验了一次（改第二栏第 2 行 = 全表第 8 行，图上同步变）
