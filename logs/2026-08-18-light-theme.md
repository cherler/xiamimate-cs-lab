# 2026-08-18 · 浅色外观，跟平台的开关联动

**结论**：本仓从「永远深色」变成跟平台的「随系统 / 白天 / 黑夜」走。
浅色下 30 个实验、每一个承载文字的元素都过 AA 4.5:1；深色一处没动
（逐条比对，**没有一处新增的失败位置**）。

真源是平台的 `localStorage["xm-theme"]`（主站 `lib/theme.ts`）→ `<html data-theme>`。
**本仓不自己做开关**：设置在账户中心那一处，多一个入口就等于多一份要同步的状态。

---

## 一、首屏那一帧只能由内联脚本定

`web/index.html` 里加了一段与主站 `THEME_BOOT_SCRIPT` 逐字相同的脚本。
React 挂载时浏览器已经画过一帧了 —— 选了黑夜的人每翻一页都要先被闪一下白，
而闪白正是这个功能要消灭的东西。

「随系统」= **把标记删掉**，不是在脚本里算出一个 light/dark 写进去。
算出来的是一张拍下来那一刻的快照，系统入夜自动转深色时页面反而不跟了。

## 二、浅色的强调色是另一套色号，不是同一个色号调亮度

琥珀 `#F0B429` 压在白纸上只有 **1.86:1** —— 它本来就是为暗底选的。
六个强调色在浅色下全部换成加深版，每个都实测过：

| | 深色 | 浅色 | 浅色对白卡 |
|---|---|---|---|
| 当前步 | `#F0B429` | `#8A5A00` | 5.93:1 |
| 命中 | `#45B39A` | `#0E7561` | 5.62:1 |
| 缺失 | `#E2664A` | `#B33B25` | 5.88:1 |
| tag 位域 | `#5B7FD4` | `#3A5FB8` | 5.98:1 |
| index 位域 | `#9B6FCC` | `#7B4CB0` | 6.00:1 |
| offset 位域 | `#4E7C8F` | `#356274` | 6.67:1 |

但**色块的底色不换**：`#F0B429xx` 这类半透明色块仍用原色号 ——
浅底上是一层淡琥珀，暗底上是一层暗琥珀，两边都成立。要换的只有当**文字**用的那一档。
这跟平台令牌里那条「同一个色号不能既当色块又当小字」是同一件事。

## 三、写死在组件里的色号躲过了整套令牌

甘特图的进程配色是 `SchedulerStage.tsx` 里一个 `const HUES = [...]`，
TCP 的阶段色是 `TcpStage.tsx` 里一个 `PHASE_COLOR`。它们既当色块又当文字
（`.glbl` 是纯文字），浅色下当场露馅：**P2 那一行在白纸上只有 2.57:1**。

改成 `var(--p1)…var(--p6)`，色号回到令牌里，深浅各一套。
> 令牌只管得住 CSS 里的东西。写在 tsx 里的色号是另一套真源，而且不会有人想起它。

## 四、判据自己错了三次 —— 这一节比配色重要

体检脚本 `scripts/theme-contrast.mjs` 在真浏览器里量**合成之后**的颜色。
它三次给出了假结论，每次都很像真的：

| # | 报出来的 | 实际 | 根因 |
|---|---|---|---|
| 1 | 位域格子 `1.26:1` | `4.6:1`，好的 | alpha 合成写成 `.concat(1)` —— 两层半透明一叠就当成不透明，往上真正的白卡片根本没参与运算 |
| 2 | 磁盘刻度 `1:1` | 清清楚楚 | 照 DOM 找底色。那些标签是 `position:absolute` 从 9px 的圆点里探出来的，**DOM 上的父子不等于画面上的上下** |
| 3 | 进度面板两处 `2.3:1` | 好的 | 修 #2 时加的几何判断**无差别地用**，把滚出可视区的行也判成"没盖在祖先上" |

**错的测量比没有测量更糟**：#1 那次我差点按 1.26 这个数去改一个没问题的配色。

### 基线也错了两次

「深色没被碰过」这件事要能证明，所以拿 `git show 66e30cb:` 换回改动前的样式、
用同一个脚本量一遍。这个基线数我写错过两次：

- 第一次**按印象填 51**（拿总数减去页眉那几处心算的），真值 58 —— 没量过的数别写；
- 第二次量出 99 / 100，看着像"改坏一处"。真因是**去重键漏了实验名**：
  磁盘调度的一个 `em` 是 2.67:1、散列表的另一个 `em` 也是 2.67:1，
  两处不相干的问题被当成同一条；后者本来就一直在，只是被前者遮住了。
  底色差了 0.4 个 RGB 让前者变成 2.66，碰撞解开，计数就"多了一条"。

修好去重之后，前后都是 **617 处**，逐条比对**新增 0 处**。

## 五、把黑色透明度换成令牌时，能不合并就别合并

49 处 `#000000XX` 是"比所在面板更深的一层"（输入框、表格格子、轨道）。
在深底上黑色 19% 几乎看不出来，在白底上是明显的灰 —— 必须分深浅。

第一版把 `0x28` 和 `0x30` 并成一个桶，看着无害（深底上差 ≤1 个 RGB 阶），
结果散列表里那个「空」字从 4.51:1 掉到 4.49:1，凭空多一条欠账。
现在只合并了两处不承载文字的（18/24/26、48/55），其余各用各的值。

## 六、一条补丁换了理由，旧理由已经不成立

`#xm-chrome-footer>.site-footer{background:var(--surface-card)}` 当初是为了
「本仓永远深色、平台制品永远浅色 → 深底深灰字读不出来」。现在两边一起换深浅，
那种情况不会发生了。留着它是**另一个理由**：页脚是平台的横条，
给它一块与正文不同的底，「这是虾米伙伴」和「这是实验室」在视觉上分开
（顶上的页眉本来就是这样），顺带把小字从 4.03:1 提到 4.73:1。

注释一并改了 —— **旧理由留在那儿会误导下一个人**。

## 七、没做的

- **深色的 617 处欠账没修。** 主要是 `--faint(#5D5A73)` 压在 `--panel` 上只有
  2.55:1，波及 9~12px 的等宽标签。修它等于改一个用户已经看惯的界面，
  要单独拍板。体检脚本会一直把这个数报出来。
- **平台页眉页脚自己有 7 处不达标**（`switch-sup` 3.05:1、`credit-pill` 3.68:1、
  页脚小字与备案号 3.05:1…）。深浅两套下是同一批数字，说明跟主题无关。
  颜色定在 `tools-frontend/app/globals.css`，本仓改不动，体检里单列一栏。

# 补记 · 把「没做的」两笔账做掉

上面第七节列的两笔欠账，同一天补完了。**病因是同一个：靠"更暗"分层，分到了读不出来。**

## 一、cs-lab：617 → 0

按文字颜色归类，94% 是**一个令牌**：

| 颜色 | 令牌 | 实例数 | 比值 |
|---|---|---|---|
| `#5D5A73` | `--faint` | 3135（94%） | 2.20 ~ 2.72 |
| `#4E7C8F` | `--f-off` | 76 | 3.26 ~ 3.94 |
| `#5B7FD4` | `--f-tag` | 70 | 3.62 ~ 4.36 |
| `#9B6FCC` | `--f-idx` | 15 | 3.84 ~ 4.45 |

但**不是把 `--faint` 调亮就行**：要够 4.5 它得亮到 `#8A87A6`，而 `--dim` 是 `#8E8BA6`
—— 亮度差 0.015，肉眼是同一个灰。
**在这个深度的面板上，靠明暗只装得下两级，装不下三级。**

所以整条字阶往上挪，层级差异改由**形态**承担（第三级本来就几乎都是 9~10px 等宽、
全大写、字距 .16em，那个形态已经在说"我是标签不是正文"了，颜色只是在重复它）：

```
ink   #E8E6F2  13.68   （不动）
dim   #A6A3BE   6.91   ← 5.14
faint #9895B4   5.86   ← 2.55
ghost #6A6785   3.13   ← 1.92（"空/还没轮到"仍最弱，但不再是看不见）
```

位域三色与进程调色板同时提亮：三色 3.4~4.1 → 5.4~5.5；p1/p3/p6 提亮后
六个进程色落在 5.65~6.56，**比原来（4.36~6.56）更齐** —— 原来进程名的醒目程度
跟进程编号有关，那没有道理。

## 二、同一个病换了个实现绕过了令牌

字阶刚挪完，体检里冒出 72 处「被 opacity 压淡」的。逐条看才发现这一栏**混了两件事**：

- 「还没轮到 / 不适用 / 禁用」—— `.future`、`:disabled`、`.unk`、空槽。这是**语义**，留。
- 「次要」—— 位宽「8 位」、系统总量、单位「KB」、说明小字。这是**层级**，
  而且是用 `opacity` 绕过令牌做的：`--faint` 刚提到 5.86，一个 `opacity:.6`
  立刻把它拉回 3.5。

9 条规则改掉 opacity、回到令牌。**`opacity` 从此只表示状态，不表示层级** —— 写进注释了。

## 三、平台那 7 处

`--gold-ink` 的值是**照错的底色配的**：文档里量的是「对白卡 4.10:1」，
但它在页面上几乎总是压在一层 12% 金底上（38 处引用里绝大多数自带
`rgba(200,135,31,.05~.13)` 的背景），真实底色下只有 **3.65:1**。
判据的底色选错，一个"合格"的值在页面上就是不合格的。

`--gold-f` 只服务积分胶囊里的「未登录」，原来 **2.71:1** ——
整个页眉上最该被游客看见的一句话，是最模糊的那一句。

文字五级同样重排（三、四两级原本只差 0.8，本来就不太分得开）：

```
        浅色              深色
text    #16212c 16.30    #ccd6e0 11.52   （不动）
muted   #3a4753  9.52    #b6c3d0  9.46   （不动）
text-3  #4d5a67  7.06    #9aa7b4  6.92   ← 5.54 / 5.77
text-4  #596774  5.81    #8c97a4  5.72   ← 4.73 / 4.82
text-5  #6c7784  4.56    #7d8993  4.74   ← 3.05 / 3.12
```

实测主站（用同一套算法，换回改动前的 `globals.css` 对照）：

| 页面 | 改前不达标 | 改后 |
|---|---|---|
| 首页 浅 / 深 | 10 / 9 | 4 / 4 |
| 虾米跨境 浅 / 深 | 17 / 9 | 9 / 1 |

**清掉的全是共用令牌那一批，一处新增都没有。**

## 四、判据在这一轮又漏了一件事

体检脚本只在 `opacity === '0'` 时跳过元素，其余按 `color` 原值算 ——
于是 `.ptab td.future{opacity:.34}` 被量成 4.14:1，实际接近 1.5:1。
**九处用 opacity 表意的地方全部被高估。** 补上之后（自己和祖先的 opacity 连乘），
才看见上面第二节那件事。

判据到今天为止改对了四次：alpha 合成、DOM 父子 ≠ 画面上下、几何判断误伤滚动区、
element opacity。**每修一次都要重新问一遍「它现在会不会说谎」。**

## 五、一条补丁的理由换到第三次，判据也跟着换

`#xm-chrome-footer>.site-footer{background:var(--surface-card)}` 这条：
第一个理由（深底深灰字读不出来）在接主题时就失效了；
第二个理由（顺带把 4.03 提到 4.73）在主站字阶重排后也失效了 ——
现在页脚小字坐在正文底上有 4.94:1，补丁对**可读性**已经不是必需的。

只剩一个纯视觉的理由：页眉用的就是 `--surface-card`，页脚跟它同一块底，
上下两条横条才是一对。判据也跟着改成量这件事（页脚底 = 页眉底 ≠ 正文底），
不再量对比度。

> **判据必须验它真正在做的那件事。** 理由换了判据不换，它就在验一个
> 已经不存在的问题 —— 而且会红，红得毫无意义。这次是自检自己报出来的。

## 六、还剩什么

主站还有各页面**自己写死的颜色**不达标（首页 `hm-kicker` / `hm-hint` 2.93、
虾米跨境的 `rr-*` 一族 1.77~2.66、`tc-go` 3.75）。它们不走共用令牌，
是另一笔账，这次没动。其中 `rr-tn` 量出 **1.00:1**（字色与底色完全相同）——
可能是悬停/滚动才显形的元素，值得单独看一眼再判。
