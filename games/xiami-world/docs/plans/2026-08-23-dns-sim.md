> 目标：一个**功能完善**的 DNS 仿真——真正建模 DNS、能反复探索、把这门知识玩透。不是"点三下通关"的玩具。
> 纪律（见记忆 simulation-is-the-core）：**先把求解器盖到完善再碰画面；副本主体=程序实时画的活工程图，不是静态背景+文字log。**
> 每个子任务：做扎实 → 单测/验收钉住"只有真仿真才有的性质" → 通过了才走下一步。不中途拿半成品邀功。

## 阶段一 · 求解器（真核心，不碰任何画面）

### ✅ S1　解析链骨架 + 逐跳时间线
- 客户端 → 本机缓存 → hosts → 递归DNS → 根 → TLD(.com) → 权威
- 一次查询产出**完整时间线**：每跳=去哪/耗时/命中未命中/返回什么。**不是返回一个结论，是返回一条可回放的过程。**
- 单测：时间线跳数、顺序、总耗时正确；命中缓存时跳数变少。

### ✅ S2　多级缓存 + TTL（深度的核心）
- 浏览器 / 系统 / 递归服务器 三级缓存，各自 TTL，**会过期**。
- 写缓存、按 TTL 过期、清某一级缓存。
- 单测（钉死"只有真仿真才有的性质"）：
  - 同一查询第二次因命中缓存**更快**（跳数少、耗时低）
  - **清缓存后下次又变慢**（回到全程）——反直觉的密
  - **TTL 到期后重查变慢**；未到期第二次更快

### ✅ S3　记录类型：A / CNAME / NS
- CNAME **要跟着链再查一次**（www→别名→真身），时间线里能看到折返。
- 单测：CNAME 折返使跳数增加；CNAME 死循环被检出、不死机。

### ✅ S4　故障模型（可组合、可随机，每局不同）
- 递归服务器宕 / 超时 / 脏缓存 / TTL 过长改了不生效 / hosts 劫持 / 上游污染 / CNAME 环。
- 随机挑一个或几个（参数随机=防刷）。
- 单测：每种故障的时间线特征可区分（断点落在正确的跳；脏缓存"解析成功却连不上"）。

### ✅ S5　旋钮 + 可观测收口
- 换DNS服务器 / 清各级缓存 / 改TTL / 改超时 / 编辑hosts / 开关缓存。
- 一个干净的查询 API：给状态 → 返回时间线。整层求解器单测全绿、覆盖上面每条性质。
- **验收：这一层完善了才进阶段二。** 给用户看的是单测 + 时间线数据，不是截图。

## 阶段二 · 可视化（破坏王式微观世界，由求解器状态驱动）

> 视觉靶子：`web/assets/gen/dns-concept.png`（破坏王式送信世界）。生成插画只衬底当氛围，
> **主体永远是程序实时画的活层**（信使精灵沿链跑、便签TTL真倒数、卡住站真闪红、缓存条目跟 caches() 变）。
> 布局：**V1 先拉直成一条横链（把"活"立起来、可玩）→ V2 再进化成爬塔纵深（忠于概念图）**。每阶段都可玩。

### V1　横链活场景（先立"活"，保证可玩）
- 节点一字排开：电脑 → 浏览器缓存 → 系统缓存 → hosts → 门房(递归) → 根 → .com → 权威。程序画的线条/精灵，衬底用概念图氛围。
- 发起查询 → **信使精灵沿链逐跳移动**（DnsSim 时间线驱动），到站停顿、命中/miss 有反馈、卡在故障那跳**闪红**、CNAME **折返再跑一趟**。
- 三级缓存=记事本，条目 + **TTL 实时倒计时**（caches() 驱动），过期条目消失。
- 旋钮：换DNS/清缓存/改超时/编辑hosts/推进时钟 → 图和后续查询**当场变**。
- **V1 结束即可玩一整局**：施随机故障 → 发查询看信使卡哪 → 观察 → 对症修 → 信使跑通 → 网页开。

### V2　爬塔纵深（忠于概念图，进化不是重来）
- 把横链弯成盘旋上爬的路，塔有高低纵深，信使沿弯路爬塔。复用 V1 的时间线驱动，只换布局与路径。
