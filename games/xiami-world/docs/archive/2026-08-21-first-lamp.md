# 第一盏灯

目标只有一句：**屏幕里一盏坏灯；你碰对了地方，它按照真实规则亮起来；
旁边那个 AI 人物知道你刚刚做了什么。** 三件同时成立，项目才算出生。

## 结果

冒烟 12 条全绿，关键那条是从**帧缓冲直接读像素**量出来的：

```
开局      平均亮度 36.9 / 255
合上开关  平均亮度 126.8 / 255      ← 3.4 倍
再拨一次  平均亮度 36.9 / 255
```

这个数不信任何 DOM 状态、也不信前端自己写的 data-*，
它读的是 WebGL 真正画出来的那些像素。

## 两个不报错的坏

### 一、整块画布是纯黑的

「屋里没开灯」被我做成了环境光 0.13 + 深色材质 —— 结果玩家连要点哪儿都看不见。
真实的夜间车间也有天光、有门缝：**暗的是氛围，不是信息。**
改成冷色天光打底（0.62）+ 一道斜射平行光，暖色只留给那盏灯。

### 二、镜头站在后墙外面

`ArcRotateCamera` 的 alpha 写成了 `-π/2`，镜头跑到后墙背后。
墙的背面被剔除，于是画布上什么都没有 —— 而且：

```
activeMeshes: 16      ← 全在
inFrustum:    true    ← 全在视锥里
frames:       60      ← 一直在渲
lights:       全亮
```

**没有任何一项报错，没有任何一项是红的。** 靠看截图才发现。
这条记下来：三维里"什么都没画出来"和"画对了"在日志上长得一模一样。

## 这一集的题眼

开关断开和灯丝烧断，**给玩家看到的画面是同一个**（都是不亮、电流 0）。
区别只有拿电压表量才看得出来 —— 而且规律是：**哪儿有电压，哪儿就是断的**。
玩家不用背这句话，量三次自己就发现了。

单测里专门有一条钉这个：

```ts
ok(a.lamp!.lit === r.lamp!.lit && a.current === r.current,
   '开关断开与灯丝烧断，肉眼现象必须无法区分')
```

## 边界（现在算不了什么）

- 只有一条串联回路，没有并联 —— 「一开多个设备就跳闸」那一集要先补这个
- 纯电阻，没有电容电感，所以结果是稳态不是过程
- 灯丝电阻当常数 —— 所以"开灯那一下最容易烧"现在算不出来

写在求解器头上不是免责声明：**玩家会问的第一批问题就藏在边界外面。**
