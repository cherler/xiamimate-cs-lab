# 计算机网络 · 元素周期表 + 反应表

> 评审稿 · 供产品负责人过目 · 已按各层对抗式自检(verify)的判决修正原子/组件,并补入 missing 项

---

## 一、总览

这是一款**化学合成游戏**:玩家手里最底层的东西是「概念原子」——像元素周期表里的元素,拼不出来、只能指着说「就是它」(比特、电平、名字、密钥……)。玩家不是按形状硬拼(那是乐高),而是**要懂那条网络原理才知道什么能和什么合**(那是化学):每一条「反应式」就是一条网络原理,拼错了不反应。合成物不是并排堆着,而是几个原子经动画**变态**成一个全新形象——帧、ARP、IP 分组、TCP、DNS、路由器,都是真东西;合成过程中会**涌现**出任何单个原子都没有的新性质(可靠、能寻址、能跨网)。最终,组件叠组件,收敛成一件**有真实规格的唯一实物**——「千兆 8 口路由器」「2U8G+100G 的服务器」,规格由拼进去的组件当场定死。吉祥物**咕噜**全程带你反应。

课程对齐:谢希仁《计算机网络》 / Kurose-Ross,自底向上五层,**下探到物理层的比特、信号、电平、调制、介质**,不回避底层。

## 二、元素周期表(概念原子)

> 排列自底(物理层)向上(应用层)。这些是玩家能拿到的、拼不出来的最底层「元素」。已标注 ★ 的是本轮按 verify 补入的新原子。

### 第 1 层 · 物理层(Physical Layer)

| 概念原子 | 一句话定义 | 为什么不可再分 | 形象 |
|---|---|---|---|
| 比特 | 信息的最小单位,只有 0/1,是真正要送到对面的东西 | 它是「信息」的底,再往下没有更小的信息;电平/波只是载它的工具 | 只有黑白两面、能翻面的小方块精灵,排队等上路 |
| 电平(信号幅值) | 介质里那个物理量此刻有多强:铜线电压、光的亮暗、场强 | 物理世界的原始量,拿仪表一量就是个数,拼不出「几伏」 | 一根发光液柱/调光旋钮,咕噜拧它调高低 |
| 时间 | 一切「多久/何时/每秒几次」的底座 | 最原始的物理轴,频率/速率/相位都从它派生,自己造不出 | 匀速摆头滴答的节拍器精灵「嘀嗒」 |
| 距离(线长) | 信号要跨过的空间长度 | 与时间正交的原始物理量,只能拿尺量 | 咕噜手里会伸缩的黄色卷尺精灵 |
| 介质 | 信号赖以传播的实物:铜双绞线、玻璃光纤、空气 | 一样具体物件,只能指着那根铜线说「就是它」 | 三根可互换的管子:红铜管/玻璃管/虚线空气管 |
| 噪声 | 系统之外硬塞进信号的、不可预测的随机抖动 | 本质是「来自外部的随机性」,列表里没有「随机」这个原子,只能承认它在 | 浑身电视雪花、沙沙作响的噪点小妖 |
| ★ 双工 | 同一时刻能否双向收发:单工/半双工(轮流)/全双工(同时) | 「方向能否并发」是一条独立的物理设定,直接决定要不要跑冲突检测;被链路层多处引用却从未定义,故显式立为原子 | 管子上的箭头:单向/来回翻转配红绿灯/上下两条各走各的 |

> 修正说明:原稿把「双工方式」当成 介质+时间 的组件,但数据链路层的交换机、以太网、CSMA/CD 都把它当**前提配料**引用。按 link 层 verify,升为物理层原子。

### 第 2 层 · 数据链路层(Data Link Layer)

| 概念原子 | 一句话定义 | 为什么不可再分 | 形象 |
|---|---|---|---|
| 界标(定界符) | 在连绵比特流里约定一个特殊记号,表示「一段从这起/到这止」 | 「哪算一段」是人为划的界,比特本身只有 0/1,推不出来 | 一对金色小书立,成对夹住中间那串比特 |
| 标识(身份标识符) | 把「这一个节点」从共享线上唯一挑出来的记号——一个名字 | 「这串比特代表那台机器」只能被指派,不能被计算 | 一块空白椭圆号码牌胚子,冲压出字样才有身份 |
| 冗余校验 | 由数据本身算出几位验算位一起发,收方重算对账 | 「自算一笔账、收方对账」是检错的最小想法;它只管检、不管纠 | 一枚火漆封印,内容改一字花纹就对不上 |
| 侦听(载波侦听) | 发送前先感知介质忙闲,忙就先不发 | 「先感知再行动」这一下是接入的感知原语 | 咕噜把大耳朵贴在电缆上听信号球 |
| 退避(随机退避) | 撞了或忙就各等一段**随机**时间再试 | 「用随机打破对称」是独立策略原语;固定等待不是退避,随机才是它的身份 | 咕噜掏骰子,掷几点数几秒,邻座点数不同于是错开 |
| 确认(回执/ACK) | 收到后回一个「收到了」信号,不含数据 | 「凭一记回声判断收没收到」是可靠性最小反馈原语 | 一只回声铃铛,信到叮一声弹回寄件人 |
| 封装 | 把上层数据当黑盒,前加首部、后加尾部,包成本层单元 | 「分层接力」的根本动作,首部/尾部只是它的部件 | 信封精灵吞下上层包裹,自动印地址、盖封条 |
| ★ 定时器/超时 | 一寄出就倒数、到点还没等到回执就「叮」报警 | 「时间流逝到上限即触发事件」是超时重传与随机退避的共同底座,原稿藏进了确认/退避却没单列 | 会走动的发条沙漏,漏干就叮地跳起来 |

> 修正说明:`定时器` 与传输层原子表里的 `定时器` 是**同一个跨层原子**(TTL、表项老化也用它),此处显式补列。

### 第 3 层 · 网络层(Network Layer)

| 概念原子 | 一句话定义 | 为什么不可再分 | 形象 |
|---|---|---|---|
| IP 地址(逻辑地址) | 分给一个接口的、可软配置的逻辑标识号(v4 32 位 / v6 128 位) | 网络层最底的「命名」;掩码/路由都预设「先有地址」,反拆只剩一串比特 | 能拧上拆下的会亮门牌灯牌,和刻死的钢制 MAC 正相反 |
| 子网掩码(前缀) | 一条「从第几位切开」的分界线(/n) | 纯粹的「切点」原语,网络号/主机号是它切出来的 | 暖黄镂空卡尺,卡进哪一位就把地址切成两半 |
| TTL(跳数限制) | 分组随身携带的生存值,每转发一次减 1,到 0 销毁 | 自带的「自毁引信」,转发只是拨扳机,造不出「随身寿命」本身 | 插在包裹上的一截燃着的引信/小沙漏 |
| 路由度量(代价) | 给一段路贴的、可比较的代价数(跳数/开销/带宽反比) | 「给路贴价、越小越好」归约成一个可比较的数,再拆只剩「一个数」 | 钉在路上的小价签/挂路口的小砝码 |
| 尽力而为交付(best-effort) | 网络层最低承诺:尽力送,丢了不吭声、不确认、不重传、不保序 | 用「拒绝做什么」定义的服务地板,上层机制都是对它的反应 | 墙上邮件投递口:「尽力投递·丢了不赔·不回执」 |
| ★ 无连接(connectionless) | 无需事先建连,每个分组独立选路,路由器不为流存状态 | 与「不可靠」正交的另一条独立设计轴(可有面向连接的 best-effort,也可无连接之上加可靠),原稿只当涌现性质 | 每个包各自上路、谁也不记得谁的散兵 |
| ★ 下一跳/直接·间接交付 | 同网直接由链路层直送,异网就交给「下一跳」,我只知下一跳、不知全程 | 逐跳转发「没人管全程却能到达」的最小前提,被埋在路由表里未点出 | 岔路口只认「下一扇门」的指路牌 |

### 第 4 层 · 传输层(Transport Layer)

| 概念原子 | 一句话定义 | 为什么不可再分 | 形象 |
|---|---|---|---|
| 端口号 | 16 位纯标识,回答「这份数据归本机哪个程序」——进程级地址 | IP 只到主机,认到「主机里某进程」这一维必须从零引入 | 大楼外墙一扇编号黄铜小窗,一扇归一个程序 |
| 序号 | 给流里每个字节烫一个只增不减的顺序号 | 「第几个/位置」这个计数本身,有它才谈得上乱序/丢号/重复 | 排队机吐出的顺序小票,烫金 #1001 #1002 |
| 确认 | 接收方回弹的「我收到了」,不含数据(与链路层同族原语) | 「回话/反馈」这一原始动作,和号码/时间/校验都不是一回事 | 绿色「收到!」橡皮印章,啪地弹回 |
| 定时器 | 一寄出就倒数,数到头没等回执就「叮」报警(跨层原子) | 「时间与上限」原语,别的原子里没有半点时间维度 | 发条沙漏,翻一次开始漏,漏干就叮 |
| 校验和 | 把一段字节按规则加成一个冗余数带上,收方重算比对(与链路层冗余校验同族) | 「加冗余以查错」原语,与编号/回执/计时无关 | 封口一枚小铅封,称过所有字节,对不上就知磕坏了 |
| 接收缓存 | 容量有限的暂存区,收进来没被取走的先堆着——它会满 | 「有限暂存容量」存储原语,流量控制的必要性全立在「它会满」上 | 带刻度的木桶,水位见顶就得喊停 |

### 第 5 层 · 应用层(Application Layer)

| 概念原子 | 一句话定义 | 为什么不可再分 | 形象 |
|---|---|---|---|
| 进程 | 一个正在运行的程序实例,通信中主动收发消息的一端 | 「谁在通信」的那个谁,再拆是操作系统与字节 | 戴耳机、面前摆收发件筐的小工作精灵 |
| 名字 | 人取给人记的标签,只答「是谁/是什么」,不含「在哪/怎么去」 | 命名是最原始的动作,地址/路由拼不出「能被人记住」 | 手写牛皮纸吊牌,正面写名、背面空白 |
| ★ 内容/数据 | 真正被通信的那团载荷:文本、像素、字节的应用级意义 | 报文正文、加/解密/摘要/签名的对象都是它,才是最基本的「什么」 | 一坨暖色泥料,尚未被命名、被封装 |
| 发起 | 「主动发出第一条消息」的权利与动作 | 对话最原始的不对称——总得有人先开口,角色由「发起权归谁」定义 | 暖橙色发令枪/哨子,谁叼着谁先发话 |
| ★ 推/拉(push-pull) | 发起方是内容的源(推,SMTP)还是内容的汇(拉,HTTP/POP) | 与「发起」正交的另一根轴:同样先开口,一个在送货、一个在取货 | 发令枪上两个方向的小箭头:塞给你 / 要过来 |
| 约定码 | 从事先约好的清单里取一个记号,意义全来自「清单第几条」 | 意义只来自约定,拆开什么都不是——正是到底 | 刻着记号的小徽章,背面拴对照卡片 |
| ★ 编码/表示 | 「内容↔字节」的可逆表示约定(ASCII/UTF-8/Base64/字符集) | OSI 表示层原语,不是查表映射,而是「如何序列化成可传字节」 | 暖色打字机,把内容敲成一排可传的符号 |
| 状态 | 把「上一条之后发生了什么」记在心里,使下一条依赖之前 | 「记住」是最原始的时间粘连,有/无状态是应用协议分水岭 | 暖色记事本(有状态) vs 转头就忘的小金鱼(无状态) |
| 权威 | 对某块命名/某份数据,「谁说了算、谁的回答才作数」的资格 | 「可信来源」的原始点,信任/委派/签名/证书全建在它上 | 暖色蜡封图章/小皇冠,盖过就作数 |
| 映射 | 一张「把 A 换成 B」的对应(名字→地址、名字→记录、号→记忆) | 「对应/查表」是最原始的间接一跳,把两者钩住的那条线 | 暖色查号簿,左页「要查的」右页「查到的」,中间发光线缝住 |
| 副本 | 内容可一模一样复制,复制品与原件不可区分 | 「可无损复制」是数字信息的原始性质,缓存/CDN/P2P 的共同地基 | 暖色复印机,吐出的每张与原稿分毫不差 |
| 有效期 | 一份存下来的信息带一个「到点作废、该重取」的倒计时(TTL) | 「信息会过期」的最小刻度,缓存一致性全靠它 | 趴在副本上的小沙漏,漏光副本就发灰 |
| 密钥 | 只有该知道的人才知道的一串信息,「知道它」=有权限/是本人 | 保密的原点是「知/不知」的二分,加密都从「有一个秘密」开始 | 暖金小钥匙,插进锁才转得动 |
| 非对称密钥对 | 成对的两把钥匙,一把锁的只另一把能开;由公钥算不出私钥 | 一种「单向陷门」数学性质,不是两把密钥的叠加 | 一对镜像钥匙,一把只顺时针一把只逆时针,照不出对方齿形 |
| 哈希 | 把任意长内容压成固定长指纹:同内容同指纹、改一位全变、不可逆 | 「易算难逆」的原始数学性质,完整性/签名/证书都以它为基 | 暖色封蜡机,塞进什么都吐一枚固定大小蜡封指纹,回不去 |
| 元数据 | 不是内容本身,而是「描述内容/指示怎么处理它」的旁注 | 「信封上的字」对「信里的话」的区分只能约定 | 贴在包裹外的便利贴:易碎/23kg/送三楼/别转存 |

> 关键修正(应用层):按 verify,原「资源」被判为**组件**(它自己的定义里已用到「名字」)。故拆为 **内容/数据(真原子)+ 名字**,并新补 `内容/数据`、`编码/表示`、`推/拉` 三个原子。凡下文出现「资源」一律理解为 `内容/数据 + 名字` 的合成物。

## 三、反应表(合成规则)

> 每行=一条反应。**反应规则**写成「玩家必须懂的那句话」,这是解谜性所在——不懂原理就配不出来。按层分段呈现,合起来即完整反应表。★=按 verify 补入的组件。

### 3.1 物理层反应

| 反应物 | → 产物 | 反应规则(必须懂) | 涌现性质 | 变态后形象 |
|---|---|---|---|---|
| 电平 + 时间 | 信号 | 信号=电平关于时间的函数;静止的电平不算信号,得随时间动 | 出现「波形」,形状里能藏信息 | 暖色坐标纸上起伏爬行的发光曲线蛇 |
| 时间 | 时钟 | 时钟不是时间本身,是「按固定周期给时间打等距刻度」的机器 | 冒出「可数的节拍」+「共同起点」 | 咔哒摆动的黄铜节拍器,摆到头弹出一个亮点 |
| 电平 + 时间 | 载波 | 一条纯正弦空车,恰有三个旋钮:幅/频/相 | 三个正交调制旋钮,后面才长出 ASK/FSK/PSK | 匀速抖动的正弦波跳绳,挂三个旋钮 |
| 比特 + 电平 + 时间 | NRZ 编码 | 1 抬高 0 压低,整个比特时隙保持;基带、不骑载波 | 比特第一次变成能跑的物理信号;但长串同码时钟会飘 | 小方块跳上高/低两级台阶站着不动 |
| 比特 + 电平 + 时间 + 时钟 | 曼彻斯特编码 | 用「中点跳变方向」表比特,每个比特必有一跳 | **自带时钟(自同步)**,代价是两倍带宽 | 每格正中一道上/下折线,接收端闭眼踩折线也跟上拍 |
| 比特 + 电平 + 时间 + 时钟 | ★ 差分曼彻斯特编码 | 用「比特开头有没有跳变」表 0/1,中点仍保证一跳 | 判「变没变」而非绝对高低,**抗极性反接** | 每格开头有无跳变+中点必跳,几乎永远和曼彻斯特成对考 |
| 信号 + 比特 | 码元(符号) | 码元=一次发的最小信号单位;N 态=log₂N 比特/码元 | 波特率与比特率**分家** | 多面骰子信号块,面数越多刻的比特越多 |
| 载波 + 比特 | ASK 振幅键控 | 只拧「幅」旋钮:1 大振幅 0 关掉 | 比特第一次骑上载波能上空中;但抗噪最差 | 跳绳按比特忽粗忽细 |
| 载波 + 比特 | FSK 频移键控 | 只拧「频」旋钮:1 高频 0 低频,振幅不变 | 信息藏在快慢里,抗噪强于 ASK(拨号 Modem 的滴嘟) | 跳绳按比特忽快忽慢,粗细不变 |
| 载波 + 比特 | PSK 相移键控 | 只拧「相」旋钮:0°/180°;四相位一格装 2 比特(QPSK) | 又抗噪又能一格塞多比特,现代 WiFi/4G 基石 | 切换处啪地错半格,相位盘指针弹跳 |
| ASK + PSK(幅+相) | ★ QAM 正交振幅调制 | 同时拧幅+相两个旋钮,16/64/256-QAM 一格塞更多比特 | 每码元比特数往上顶信道容量,现代 WiFi/LTE/有线电视全靠它 | 星座图上一格格发光点阵,越密塞越多 |
| 电平 + 比特 | ★ 量化 | 把连续电平切成有限档,每档对应一组比特(N 档=log₂N 比特/样本) | 冒出「量化误差/量化噪声」;信噪比越高能切越多档 | 把液柱高度卡进一格格阶梯,落哪格记哪码 |
| 信号 + 时间(+量化+比特) | ★ PCM 脉码调制(采样定理) | 采样(fs≥2×信号带宽)→量化→编码;注意此奈奎斯特≠信道奈奎斯特 | 模拟→数字整条链路;PCM 64kbps 电话语音 | 曲线蛇被等距竖线采样,每点量化成一串比特 |
| 电平 + 介质 + 距离 | 衰减 | 越走电平越小,随距离累积,光纤最省铜线次之空气最费 | 冒出「传输距离上限」(弱到淹进噪声就读不出) | 曲线蛇每爬一段暗一截矮一截,远端快被淹没 |
| 信号 + 介质 | ★ 失真 | 波形本身被介质扭歪(不同频率分量走得不一样→码间串扰 ISI) | 第三种独立损伤,既非均匀衰减也非外来噪声 | 曲线蛇形状被拧歪,相邻码元糊在一起 |
| 距离 + 介质(传播速度) | ★ 传播时延 | 传播时延=距离/传播速度(~2×10⁸ m/s);≠传输时延(=帧长/比特率) | 再长出「时延带宽积=链路里此刻有多少比特在飞」 | 卷尺量出线长,信号球在管里飞一段的耗时 |
| 信号 + 噪声 | 信噪比 | 决定能否读对的不是信号多强,是它比噪声强几倍(功率比取分贝) | 冒出「能把电平切多细」;香农容量的一半原料 | 天平一头信号蛇一头噪点妖,指针指分贝 |
| 载波 + 介质 | 带宽 | 信道只让某段频率顺利通过,这段宽窄(Hz)就是带宽;≠口语「100 兆比特/秒」 | 冒出「每秒最多发几码元」(奈奎斯特);香农容量另一半原料 | 介质入口一道频率梳子闸门 |
| 码元 + 时间 | 波特率 | 每秒发多少码元,不管每格装几比特 | 被带宽死死卡住(Rs≤2×带宽) | 传送带每秒咔地送固定个骰子 |
| 波特率 + 码元 | 比特率 | 比特率=波特率×每码元比特数;提速两条路:发更快 or 每格装更多 | 比特率可远高于波特率(老 Modem 越做越快) | 出口把骰子拆开,比特计数器跳得快好几倍 |
| 带宽 + 信噪比 | 信道容量 | 香农 C=带宽×log₂(1+信噪比);带宽给「每秒几格」上限,信噪比给「每格几比特」上限 | 一条不可逾越的物理天花板,把「能多快」变成可算的数 | 刻着 C 的天花板,各路小车顶不破只能贴着跑 |
| 信噪比(+调制/编码) | ★ 误码率 BER | 每传 N 比特错几个,由信噪比与调制方式定 | 把抽象的信噪比翻译成用户在乎的「传对传错」 | 一块计数板,每错一比特跳一格 |
| 时钟 + 信号 | 同步 | 收发时钟频率+相位对齐,才会在每比特正中采样;采样时刻错了全读错 | 冒出「共享的时间线」,曼彻斯特把它焊进了数据 | 两台节拍器对拍,采样箭头稳稳落每比特正中 |
| 带宽 + 载波 | 频分复用 FDM | 把带宽切成互不重叠的子带,各用一个频率载波,同时发不干扰 | 一条介质同时跑多条独立逻辑信道 | 管里并排流几条不同颜色的波,入口分频梳子梳开 |
| 时间 + 介质 | 时分复用 TDM | 时间切成一轮轮时隙,轮到谁谁独占整条介质发一小段,飞快轮转 | 「轮流独占」,共享坐标从频率换成时间 | 入口飞转的分配转盘,转到谁谁的比特灌进去一段 |
| 载波 + 比特(+正交码/波长) | ★ CDMA 码分复用 / WDM 波分复用 | CDMA 给每人一串正交码片,同时同频发靠码字正交分离;WDM=光纤上的 FDM(不同波长) | 复用四件套补齐(FDM/TDM/WDM/CDM) | 每人一套彩色码片叠在一起,收端靠正交解开;光纤里多色波长并跑 |
| 介质 + (曼彻斯特或 ASK 任选一路) + 同步 + 双工 | **物理链路** | 选介质+选编码/调制+做好同步+定好双工,两端各装收发器(PHY) | 涌现出**有真实规格牌的唯一实物**;对上层只暴露「给我一串比特,原样送到对面」 | 插主板的网卡/光模块,烫金规格牌,一头咬管子一头吐干净比特队列 |
| 物理链路 + 物理链路(+放大/再生) | ★ 中继器/集线器 | 接两段物理链路,把衰减失真的信号放大(模拟,连噪声一起放)或再生(数字,重新判决整形);集线器=多口中继器 | 突破「最多拉多长线」的距离上限 | 笨笨的多头三通,信号从一口进往其余每口全吐 |

### 3.2 数据链路层反应

| 反应物 | → 产物 | 反应规则(必须懂) | 涌现性质 | 变态后形象 |
|---|---|---|---|---|
| 封装 + 界标 + 标识(→MAC) + 冗余校验(→FCS) + 比特 + IP 分组(载荷) | **帧(Frame)** | 物理层只吐比特;靠界标知「哪段是一帧」、靠地址知「给谁」、靠校验知「坏没坏」 | 一个有头有尾、能寻址、可自检的离散单元 | 小火车厢:车头界标旗、侧面两块 MAC 门牌、车尾 FCS 火漆、肚里包裹 |
| 帧 + 标识(源/目的 MAC) + 冗余校验(→CRC-32) | 以太网帧 | 前导码只给物理层打拍子不是数据;最小帧长 64 字节是被 CSMA/CD 逼出来的 | 全球统一、任意厂商网卡都认的标准信封,帧长 64~1518 | 标准涂装火车厢,车头前导码节拍灯,五格明确分区 |
| 界标 + 帧 | 透明传输(字节/比特填充) | 数据里若出现跟界标一样的位,发端插转义符(或连 5 个 1 塞一个 0),收端抠掉 | 任何比特组合都能安全当数据发,界标永不被内容误触发 | 咕噜给长得像书立的位贴「这不是边界哦」黄便利贴 |
| 标识 + 比特(48 位) | MAC 地址 | 前 24 位厂商号段(OUI)+后 24 位流水号,出厂烧死;它是**扁平**的,认人却无法寻路 | 全球唯一、出厂固化、扁平的硬件身份 | 冷冲压钢制铭牌,六段十六进制刻痕,刮不掉 |
| 标识(全 1) + 帧 | 广播地址 | 目的 MAC=FF:FF:FF:FF:FF:FF 意为「喊给本段所有人」,每块网卡必收 | 本段一对全体的能力;埋下广播风暴隐患 | 画大喇叭、刻全 F 的号码牌 |
| 标识(组地址,MAC 最低位=1) + 帧 | ★ 组播/多播地址 | 目的=组地址,只有加入该组的网卡才收下 | 补齐单播/广播/组播三件套里的「一对一组」 | 刻着 01:00:5E.. 的号码牌,只有戴同色臂章的收 |
| 冗余校验 + 比特(1 位) | 奇偶校验 | 添 1 位让 1 的总数凑成偶(或奇),收方数一遍 | 能查奇数个翻转,偶数个抵消查不出,最弱但几乎零成本 | 算盘最右一颗「奇偶珠」 |
| 冗余校验 + 比特 | 校验和 | 分块反码求和取反带上,收方全加应得全 1;两错相抵仍免疫 | 比奇偶强、软件快算,但弱于 CRC | 账房把每行加总,末尾盖「合计」戳 |
| 冗余校验 + 比特 + 生成多项式 | CRC | 整帧当大二进制数,模 2 除以约定多项式,余数附帧尾;收方再除余 0 则认对 | 擅长抓突发错、天生适合硬件流水线,故以太网 FCS 用它 | 带摇把的除法机,吐一小截余数压进火漆 |
| 冗余校验 + 比特位置编码 | ★ 海明码(FEC) | 多个按位置摆放的校验位,不但发现错还能定位并翻转改回,无需重传 | 检错→**纠错**;接收方自己把错位纠回来 | 校验位站在 2 的幂位置,交叉投票指出哪位翻了 |
| 侦听 + 退避 + 共享信道 + 帧 | CSMA/CD | 先听后发、边发边听,撞了立刻停+发拥塞信号,再指数退避 | 无中央调度也能分布式基本不撞地轮流用一条线;逼出最小帧长 | 独木桥,上桥前探头,途中盯着,双双退回各掷骰子 |
| 侦听 + 退避 + 确认 + 共享信道(无线) | CSMA/CA | 测不到自己的碰撞→改成事前避让+事后 ACK;紧张时先 RTS/CTS 预约 | 在测不到冲突的介质上仍能协调,可靠性从 ACK 涌现 | 浓雾吊桥:招手 RTS、回招 CTS、掷骰过桥、对面挥旗 ACK |
| 确认 + 定时器 + 序号 + 帧(重发) | ★ 超时重传/ARQ(停止-等待) | 发出即开定时器,超时或收否认就重传,用序号去重 | 会丢会错的链路上得到「不重不漏一定送达」 | 抱包出门死等回执,沙漏叮了照存根补寄 |
| ARQ + 序号 + 窗口 | ★ 滑动窗口与流量控制 | 用序号+窗口连续发多帧(回退 N/选择重传);窗口大小=接收方吃得下多少 | 提利用率+天然流控,逼发端别淹没收端 | 卡在编号纸带上的镂空滑尺,收印章就往前挪 |
| 标识(→MAC) + 端口 + 帧 | 转发表(MAC 地址表) | 目的 MAC 查表:查到只往那口送,查不到泛洪;表项有老化 | 把「广播式共享」升级成「点名式投递」 | 门房桌上对照册,左栏门牌右栏「走第几门」 |
| 转发表 + 帧(源 MAC) + 端口(收帧口) | 自学习(反向学习) | 每收一帧就把「源 MAC↔从哪口进来」反着记进表;一问一答后双方位置全进表 | 即插即用,自动长出拓扑知识,配老化能纠错 | 门房瞄寄件人门牌+记下从几号门进,下次直接走对门 |
| 自学习 + 转发表 + 帧(+生成树) | ★ 网桥(透明网桥) | 自学习+转发+生成树避环;交换机本质就是「多接口网桥」 | 点明「交换机=多口网桥」的来历,补上原理断层 | 两段网之间的门房小亭,连着一棵无环树 |
| 网桥/交换机 + BPDU 帧 + 无环树 | ★ 生成树协议 STP | 网桥互相协商、阻断冗余链路、长成无环转发树 | 「环路→广播风暴」的解药 | 多台门房互投 BPDU,红叉封掉会成环的那条线 |
| 转发表 + 自学习 + 多端口 + 帧 + 全双工 | **交换机(Switch)** | 每口独立冲突域(点到点全双工),按 MAC 精准投递,查不到才泛洪 | 分割冲突域(总带宽随口数叠加);但所有口仍在同一广播域 | 多门智能分拣柜,规格牌「24 口·千兆」 |
| 交换机 + 帧 + 标识(→VLAN Tag) + 广播域 | VLAN | 给口/帧打 12 位 VID,只有同 VLAN 才互转互广播;跨 VLAN 必须上三层 | 不重新布线就把广播域逻辑切开、按部门隔离 | 不同颜色腕带,红只走红口,红绿间凭空立墙 |
| 广播地址 + 交换机 + 局域网 | 广播域 | 交换机转发广播(不分割)、路由器不转发(天然边界)、VLAN 逻辑切开 | 划定「广播能传多远」;域越大风暴破坏面越大 | 院子中央石墩喊一嗓子,声音盖住的整院=一个广播域 |
| 标识 + 帧(令牌) + 轮流规则 | ★ 受控接入/令牌传递 | 谁攥着令牌谁才能发,无冲突、时延确定 | 补齐 MAC 三分法的第三类(静态划分/随机接入/受控接入) | 一枚令牌沿环传,接到才准发一帧 |
| 物理介质 + 共享信道 | 信道划分(时分/频分/码分) | 静态预先分成互不干扰的份,每人固定用自己那份,根本不撞 | 无冲突无退避、时延确定;代价是有人没话说也空占 | 大水管竖隔板分几条,或管口按时段轮流开合 |
| IP 地址 + MAC + 广播地址 + 帧 | **ARP** | 同一 LAN 内广播「谁是 192.168.1.5」,对方单播回 MAC,缓存进 ARP 表(有老化) | 把逻辑地址(IP)翻译成硬件地址(MAC),是三层落到二层的接线口;广播可信故可被欺骗 | 举 IP 门牌灯大喊「这门牌哪位」,对应那家回喊钢制铭牌 |
| 帧 + 界标(0x7E) + 透明传输 + 冗余校验(→FCS) | PPP | 两点一根专线,不用寻址/抢介质;重点是 0x7E 成帧+透明传输+FCS+LCP/NCP 协商+PAP/CHAP | 一条「拨通就能跑 IP」的点到点链路 | 两咕噜间软管,首尾插 7E 旗,接通前握手对暗号 |
| 以太网 + 交换机 + 网卡(多台) + 广播域 + VLAN(可选) | **局域网(LAN)** | 同广播域内靠 MAC+ARP 直接可达不需路由器;一个 IP 子网通常正好映射一个 LAN | 内部人人可直达、对外统一走网关的本地网 | 一间办公室,几台机器接中央 24 口交换机,墙角一道网关门 |
| 以太网帧 + MAC + CSMA/CD(经典)或交换机(现代) + 物理介质 + FCS | 以太网 | 一套帧格式+一套接入布线规格;10BASE-T/1000BASE-T 把规格编进型号 | 可平滑升速(10M→10G)、全球通用的局域网技术 | 带水晶头双绞线,帧小火车飞驰,铭牌「1000BASE-T」 |

### 3.3 网络层反应

| 反应物 | → 产物 | 反应规则(必须懂) | 涌现性质 | 变态后形象 |
|---|---|---|---|---|
| IP 地址 + 子网掩码 | 网络前缀(网络号/主机号) | 地址与掩码按位 AND:高位=网络号、低位=主机号;主机号全 0=网络地址、全 1=广播 | 地址第一次**分层**,让「一大片地址用一条短前缀概括」成为可能 | 门牌灯被卡尺一夹,左金色街区名、右门牌号 |
| IP 地址 + 网络位边界 | ★ A/B/C/D/E 分类编址 | 按首位判类:A/B/C 默认掩码、D 组播、E 保留 | 理解「为何要子网划分与 CIDR」的前置基础 | 五种颜色号段格子,按首几位落进对应格 |
| 网络前缀 + 局域网 + ARP | 子网(网段) | 前缀相同=直连邻居,靠链路层+ARP 直送;去别的前缀才交给网络层 | 划出「直连 vs 需路由」的边界(二层到此、三层从此) | 一圈共用街名牌、围成死胡同的小屋 |
| 网络前缀 + 最长前缀匹配 + 聚合规则 | ★ CIDR/路由聚合 | 可变长前缀+把多条路由合并成一条短前缀对外通告 | 路由表可扩展、BGP 通告可压缩的核心 | 一把大伞把一片小门牌收成一条短前缀 |
| IP 地址 + 网络前缀 + 不可全局路由 | ★ 私有地址(RFC1918) | 10/8、172.16/12、192.168/16 只在本地有意义,公网不可路由 | 「为何需要 NAT/VPN」的根 | 只在自家院墙内有效的内部门牌 |
| IP 地址 + TTL(+ToS/DSCP) | IP 首部(header) | 定长封面标签区:版本、源/目的 IP、TTL、协议号、分片字段、首部校验和 | 路由器只读封面不拆信,转发与内容彻底解耦 | 包裹正面一排冷压标签槽 |
| IP 首部 + 尽力而为 + 上层报文 | **IP 分组(数据报)** | 把上层报文裹进带源/目的逻辑地址的首部,每段临时塞进「帧」投递,分组本身不动 | **跨网能力**:穿过一连串异构网,首部收发地址全程不变 | 暖黄牛皮纸包裹,每到路由器换一层当地「帧」外包装 |
| IP 分组 + MTU + IP 首部 | 分片与重组 | 大于 MTU 就切片,靠标识+片偏移+MF 定位;中途只切,终点按标识拼回 | 对异构链路透明;但丢一片整包重组失败且不重传 | 窄门口切成小包盖同批次火漆,终点按段号拼回 |
| 网络前缀 + 子网掩码 + 路由度量 + 网卡/接口 | 路由表 | 每行=(目的前缀/掩码→下一跳+出接口+度量);压缩成「拿目的地址查一下」 | **本地知识驱动全局递送**:只知下一跳,全程由各表接力涌现 | 邮局墙上翻牌分拣板 |
| 路由表 + 子网掩码 | 最长前缀匹配 | 多行命中时选前缀最长(最具体)那行——越具体越懂怎么走 | 让「聚合」与「例外」无歧义共存 | 一摞长短镂空尺套向门牌,卡最紧那把亮灯 |
| IP 分组 + 路由表 + 最长前缀匹配 + 帧 + ARP | 分组转发 | 读目的 IP→最长前缀匹配→下一跳+出接口→ARP 查 MAC→重封进出接口的帧;逐跳、无连接、每包独立 | 逐跳递送:没人管全程却能到达,同目的两包可走不同路甚至乱序 | 岔路口读 TO 灯牌选门,扒旧帧换当地新帧抛进去 |
| 路由表 + 最长前缀匹配 + 分组转发 | 默认网关(默认路由) | 放一条 0.0.0.0/0 兜底行,前缀最短,只在无更具体命中时才落它 | 端点只需知道「自己街区+一扇出门」就全球可达 | 死胡同墙上最大的 EXIT 门 |
| 路由表 + 路由度量 + 子网 | 路由协议·距离向量(RIP) | 周期性把「我到各目的几跳」告诉邻居,邻居套「我=邻居+1」取最小;16 跳=不可达 | 纯邻里传话也能收敛到最短;通病「坏消息传得慢」(计数到无穷) | 各家递小纸条,收到就把数字+1 和自己比 |
| 路由表 + 路由度量 + IP 分组 | 路由协议·链路状态(OSPF) | 只描述自己每条直连链路的开销,洪泛全 AS→人人拼出同一张全网图,各自跑 Dijkstra | 传「链路事实」而非「我算好的结论」,收敛快、不互相传染错误 | 举牌广播「我这几条路各多重」,拼成整片地图描最短路 |
| 网络前缀 + 子网 | 自治系统(AS) | 同一管理机构+全球唯一 AS 号;域内用 IGP、域间用 EGP(BGP) | 两级路由,把「每台懂全世界」降维成「域内细算+域间谈策略」 | 插同一面旗、围栅栏的领地,门口牌「AS 65001」 |
| 自治系统 + 路由表 + 路由度量 | 路由协议·路径向量(BGP) | AS 间通告「到某前缀要经过哪串 AS(AS-PATH)」,按策略与商业关系选,扫 AS-PATH 防环 | 全球可达+各自为政;**策略优先于最短** | 大门间互递盖满领地印章串的卷轴 |
| IP 分组 + TTL + 尽力而为 + 分组转发 | **ICMP** | IP 不给反馈,用装在 IP 分组里的控制报文补:不可达、TTL 超时、需分片被禁、回显(ping) | 从纯尽力而为里长出**可诊断性** | 咕噜口袋红哨,包被丢就吹哨塞回执逆流送回源头 |
| TTL + ICMP + 分组转发 | Traceroute | 发一串 TTL 递增的分组,每台把包烧断的路由器用 ICMP 超时报自己是谁 | 用两个原语反推出协议从没打算提供的东西——整条路径可见性 | 连发引信一个比一个长的小包,谁烧断谁报名 |
| IP 地址 + 端口 + 分组转发 | NAT | 出网时把私网源(IP+端口)改成公网(IP+新端口)记进表,回包反向改回;多机靠端口复用一个公网 IP | 地址复用+私网隐身;副作用:打破端到端,外部无法主动进来 | 小区门房守进出登记簿,外人只看见大门一个门牌 |
| IP 地址 + 子网掩码 + 默认网关 + 分组转发 | DHCP | 开机广播「谁能给我配网」,服务器出租 IP+掩码+网关+DNS+租期;因 IP 天生软分配才能这样发 | 即插即用入网;地址从固定资产变成可回收公共资源 | 物业发号窗口,递带到期日的门牌灯 |
| IP 分组 + 封装(+私有地址) | ★ VPN/隧道 | 把一份 IP 分组再封进另一份 IP 分组;VPN、IPv6 过渡(6to4)、移动 IP 共用此机制 | 在公网上凿出一条私有专用通道 | 包裹外再套一层公网信封,穿过公网到对端拆开 |
| 连接建立 + 每跳 VC 状态表 + VC 标签转发 | ★ 虚电路服务 | 先建路、沿途每跳存 VC 状态、按 VC 号转发、保序;与数据报服务对立 | 「面向连接 vs 无连接」的另一半,理解 IP 为何选无状态逐跳 | 先铺好一条固定轨道,车厢按轨道号鱼贯而行 |
| 网络前缀 + 组管理(IGMP) + 组播转发 | ★ IP 组播 + IGMP | 一次发送、组内都收;D 类地址 224/4,IGMP 维护组成员,组播树分发 | 网络层三种交付里补上「一对一组」 | 一次投递沿组播树分叉送到每个订户 |
| 转发(数据面) + 控制器 + 流表 | ★ 控制/数据平面分离 + SDN | 把控制平面从每台设备抽到逻辑集中控制器,用流表做多字段匹配+动作的通用转发 | 现代网络层主线,转发不再只按目的 IP | 中央大脑下发流表,交换机只照表执行 |
| IP 地址 + IP 首部 + ICMP | IPv6 | 地址扩到 128 位、简化首部去校验和、取消途中分片(源端按 PMTU 切)、内建自动配置 | 近乎无限地址→**端到端可达性回归**,不再需要 NAT | 门牌从 4 段升成 8 段冒号缩写的超长灯牌 |
| 网卡×N + 路由表 + 分组转发 + 最长前缀匹配 + OSPF + BGP + ICMP + 默认网关 | **路由器(终极实物)** | 全部组件装进有 N 个接口、标称转发吞吐的盒子;规格由塞进的组件决定 | 一台把多张异构网缝在一起、自主为每个分组选路的实物 | 暖黄机箱,一排接口灯+翻牌分拣板+RIP/OSPF/BGP 徽章+红哨 |

### 3.4 传输层反应

| 反应物 | → 产物 | 反应规则(必须懂) | 涌现性质 | 变态后形象 |
|---|---|---|---|---|
| IP 地址 + 端口号 | 套接字 socket | IP 只到主机、端口只是空窗号;钉成一对才是程序能握住、能读写的端点 | 一个可被 OS 交给某程序独占、能收发的通信端点 | 门牌灯(IP)下挂编号窗(端口),拼成插座 |
| 端口号 + 套接字 | 复用分用 | 出门汇成一股贴源端口(复用);进门按目的端口(TCP 看四元组)分派回套接字 | 一条网线被全机所有程序同时共享互不串味 | 电话总机,出门拧成一股贴标签,进门按标签分回 |
| 端口号 + 校验和 + 复用分用 + IP 分组 | 报文段(传输层 PDU) | 贴源/目的端口(供分用)+校验封(查错),自己不认路,套进 IP 分组 | **进程到进程**的可寻址单元 | 素面小包裹套进网络层大信封 |
| 报文段 + 复用分用 + 校验和 | UDP 用户数据报 | 只多加长度字段,不握手/不编号/不回执/不重传;要的就是轻 | 零建立时延、保留消息边界、开销极小;代价是可能丢/乱/重 | 明信片:只写窗号+长度+校验封,正文晾在外面 |
| 序号 + 确认 | 确认号机制(累积确认) | 每字节带序号发,收方回「已连续收到第 N、下个发 N+1」 | 发端获知对面到底收到哪了——可靠传输地基 | 号牌与绿印章咬合的棘轮,只进不退 |
| 确认号机制 + 定时器 | 超时重传 | 发出即翻沙漏,漏干还没等回对应印章就判丢,照存根按同序号补寄 | 丢了能自己发现、自己补回,无人提醒 | 沙漏叮一响,咕噜抽出那号又封一个送出 |
| 确认号机制 + 定时器 + RTT 采样 | ★ RTT 估计与自适应超时(Karn) | 太短乱重传太长恢复慢;加权平均 EstimatedRTT+偏差 DevRTT→Timeout,重传样本不计入(Karn) | 超时时长随网络自适应,不再拍脑袋 | 咕噜边记来回耗时边动态调沙漏容量 |
| 确认号机制 + 重复 ACK 计数 | ★ 快速重传 | 收到 3 个冗余 ACK 就立刻补发那个失序包,不干等超时 | 独立于超时重传的更快恢复 | 同号印章咚咚咚弹回三下,咕噜立刻补那一号 |
| 确认号机制 + 超时重传 | 停止等待 | 发一个就杵门口等印章,回来才发下一个;路上最多一个包 | 「可靠但慢」第一次现身,把吞吐这个新问题亮出来 | 只雇一名跑腿的驿站,门口包裹永远干等 |
| 序号 + 确认号机制 | 滑动窗口 | 允许一段连续号段同时在路上飞,收一枚印章窗口挪一格 | **流水线吞吐**,解开停等的慢 | 卡在编号纸带上的镂空滑尺 |
| 滑动窗口 + 确认号机制 + 接收缓存 + 定时器 | ★ 选择重传 SR / 回退 N GBN | GBN 累积确认、错一个后面全重发;SR 逐包确认+每包独立定时器+接收缓存暂存乱序,只补真正丢的;SR 发送窗口≤序号空间一半 | 接收缓存第一次派上排序重组用途 | GBN 一错全退;SR 只挖空位补那一格 |
| 校验和 + 序号 + 确认号机制 + 超时重传 + 滑动窗口 | **可靠传输** | 铅封挡磕坏、号牌排序去重、印章+沙漏补丢、滑尺塞满不掉速;缺一环都不叫可靠 | 会丢会坏会乱序的 IP 上,两头感觉共享一根永不丢件、按序到达的完美字节管 | 会自愈的暖光气动传输管,少一个立刻从存根补 |
| 序号 + 确认(报告已收区间) | ★ 选择确认 SACK | 累积确认只能说「连续到 N」;SACK 回报已收非连续区块,重传只补真正缺的 | 现代 TCP 普遍启用的优化 | 印章上多画一条「这几段已收」的区间尺 |
| 滑动窗口 + 接收缓存 | 流量控制 | 窗口大小由接收方说了算:把「还空 N 格」(rwnd)写回执,发端滑尺≤N,桶满报 0 就停 | 慢的一方绝不被灌爆的端到端自适应限速 | receiver 举「还空 N 格」木牌,死死卡住 sender 滑尺 |
| 流量控制 + 定时器 | ★ 坚持定时器/零窗口探测 | rwnd=0 后若「窗口重开」的 ACK 丢了会互等死锁;发端周期发零窗口探测逼对方回报当前窗口 | 打破零窗口死锁 | 木牌翻到 0 后,咕噜每隔一会敲一下问「还堵着吗」 |
| 定时器 + 确认 | 拥塞信号 | 网络内部堵没堵看不见,只能嗅两种症状:超时、或同号 ACK 连回三次 | 隔着黑箱推断网络内部状态 | 两块警示灯:漏干沙漏、三下重复印章 |
| 滑动窗口 + 拥塞信号 | 慢启动 | cwnd 从 1 个 MSS 起,每 RTT 翻倍,直到门限 ssthresh 或撞拥塞信号 | 从安全小流量快速探到可用带宽 | 起步只放 1 个,每轮翻番,盯 ssthresh 红线 |
| 滑动窗口 + 拥塞信号 | 拥塞避免 | 越过 ssthresh 改加性增(每 RTT +1),嗅到拥塞就乘性减(砍半);即 AIMD | 多连接长期公平共享、网络不崩溃 | 缓慢加速,警示灯亮就猛砍半,画出锯齿 |
| 快速重传 + 拥塞避免 | ★ 快速恢复(TCP Reno) | 快速重传后不退回 cwnd=1,而是窗口减半直接留在拥塞避免(区别于 Tahoe) | Reno 对轻度丢包更平滑 | 砍半后不归零,稳在半空继续小步爬 |
| 慢启动 + 拥塞避免 + 拥塞信号 + 流量控制 | 拥塞控制 | 发端心里也开 cwnd:不堵就长、堵就退;真正发的取 cwnd 与 rwnd 更小者 | 千万条 TCP 共处一网不发生拥塞崩溃的全局秩序 | 脚下 cwnd 油门,旁边 rwnd 翻牌,取小者踩 |
| 比特 + 确认 + 序号 | 连接控制标志(SYN/ACK/FIN/RST) | 封口安几面 1 比特小旗:SYN 对齐起始序号、ACK 确认号有效、FIN 我说完了、RST 推倒重来;带内信令 | 一个比特翻不翻被赋予开/关/作废连接的重量 | 封口 S/A/F/R 四面小三角旗 |
| 序号 + 确认 + 连接控制标志 | 三次握手 | A 亮初始序号+SYN;B 确认 A 的号+亮自己序号(SYN+ACK);A 再 ACK 认下 B 的号;少一下就有一方序号没被确认 | 两台本无瓜葛的机器凭空建立双方都记下的共享连接状态 | 隔空对暗号击掌三下,各自小本子记下对方起算号 |
| 确认 + 连接控制标志 + 定时器 | 四次挥手 | 一根管两向各自关:A 发 FIN,B 先 ACK(半关还能说),B 也 FIN,A 回 ACK 并守 TIME_WAIT | 全双工不丢数据优雅收场,吃掉迟到的旧残包 | 各卷各半根管,A 回 ACK 后守一会沙漏再走 |
| 报文段 + 序号 + 确认号机制 + 连接控制标志 + 滑动窗口 | TCP 报文段 | 把可靠/连接/限速的控制信息全焊进包头:端口、序号、确认号、旗、窗口、校验和,肚里才是数据 | 一个单元同时携带寻址+排序+确认+连接控制+流量通告 | 武装到牙齿的挂号信封 |
| 套接字 + 复用分用 + TCP 报文段 + 三次握手 + 可靠传输 + 流量控制 + 拥塞控制 + 四次挥手 | **TCP 连接** | 四元组(源 IP+源端口, 目的 IP+目的端口)唯一锁定;握手接通、挥手拆除;规格(MSS/窗口)当场定死 | 无连接会丢包的网上,两程序独享的按序可靠、全双工字节流虚拟电路 | 两扇窗间的双向气动传输管,四元组挂牌,握手点亮挥手熄灭 |

### 3.5 应用层反应

| 反应物 | → 产物 | 反应规则(必须懂) | 涌现性质 | 变态后形象 |
|---|---|---|---|---|
| 内容/数据 + 名字 | 资源 | 一个可被指名、可被取回的东西;「可被指名」用到名字,「内容」才是真原子 | 「被命名、可寻址、可取回的内容」 | 系丝带的暖黄包裹,吊牌写名、里面是内容 |
| 进程 + 副本 | 中间人 | 既非源头也非终点,插在两端替它们转手/代存,凡经过的都看得见、可留副本 | 拓扑凭空多出中间一跳(代理/中继/缓存/递归解析器) | 系围裙、左右手各接一件的驿站小二 |
| TCP 字节流 + 元数据 + 内容/数据 + 约定码 | 报文 | 把 TCP 连续水流按约定切成有边界的信件,空行/长度分首部(元数据)与主体 | 边界感:可独立理解、独立处理的意义单元 | 信封写旁注、里面夹信纸 |
| 进程 + 端口 + 发起(listen/connect) | ★ 套接字 Socket | 进程绑到一个端口再监听或连接,才「可被找到/可被连接」;应用层与传输层的接缝 | 进程从「在运行」变成「可被寻址连接」 | 程序把水管咔哒插进墙上编号插座 |
| 进程 + 发起 + 资源 | 客户端-服务器 | 一方常驻守资源被动应答(服务器),另一方按需先开口索取(客户端) | 角色分工+固定找得到的服务窗口 | 小卖部:柜台后老板,门外拿发令枪的顾客 |
| 进程 + 发起 + 副本 | 对等网络 P2P | 每节点既客又服,谁有副本谁供给,发起权人人有,无中心柜台 | 去中心+自扩容(人越多供货源越多,与 C/S 相反) | 一圈手拉手互递复印件的小人 |
| 发起 + 报文 + 客户端-服务器 | 请求-响应事务 | 客户发恰一条请求,服务器回恰一条响应,配成一笔;问完才答、答完闭合 | 事务边界:可配对、可独立重试、可各自计时 | 柜台前一递一收 |
| 约定码 + 资源 | 方法 | 从固定清单取记号盖在请求上:GET 取/PUT 存/POST 提交/DELETE 删 | 语义分流:同一地址靠动词分读/写/删 | 一排彩色印章盖在信件额头 |
| 约定码 | 状态码 | 服务器取三位数告结局:2xx 成/3xx 改道/4xx 你错/5xx 我错 | 机器可判的结局分类,不读正文只看号 | 三色信号灯宝石,浮着 200/301/404/500 |
| 报文 + 方法 + 状态码 + 元数据 | HTTP 报文 | 请求=方法+URL+首部+空行+主体;响应=状态码+首部+空行+主体 | 自描述:一条报文自带要干嘛/结果/内容多大类型能否缓存 | 标准信件,抬头盖动词或信号灯,内衬首部便利贴 |
| TCP 连接 + HTTP 报文 + 状态 + 元数据 | 持久连接 | 一条 TCP 取完不立刻关,记住「还能再用」,同连接连发多对请求响应,省反复握手+慢启动 | 复用带来低时延高吞吐 | 来回不停运信的传送带,不再每封信重架桥 |
| 约定码 + 名字 + 资源 + 端口 | URL | scheme(http/https)+host(名字)+path 写成一行可点地址,端口可省有默认 | 一串字符全球唯一定位并直达一份资源 | 三段涂色的路牌:协议头/主机名/路径 |
| 名字 + 权威 | 域名 | 名字按点分级,每级把下级解释权委派给下级权威,最右是根 | 全球不撞名+分区自治,无需中央登记所 | 倒挂名字树,每枝节点挂一枚蜡封图章 |
| 名字 + 映射 + 约定码 + 有效期 | 资源记录 | 「名字→值」登记,类型码定值:A/AAAA=IP、MX=邮局、CNAME=别名、NS=下级权威,带 TTL | 把人类名字挂接到机器目标,绑定可缓存有保质期 | 档案卡四栏:名字/类型印章/值/沙漏 |
| 域名 + 资源记录 + 映射 + 中间人 + Web 缓存 | **DNS 解析** | 名字交本地解析器,替你从根→顶级→权威顺委派链问下来,拿 A 记录回给你并按 TTL 缓存 | 人只念名字就拿到 IP,多数查询就近命中缓存 | 接线员拿名字树顺蜡封章一站站打电话,末了递门牌灯 |

| 资源 + 元数据 + 超链接 | HTML 超文本 | 成对标签把内容标注结构/语义,浏览器照标记渲染;标记是元数据 | 机器解析结构、人看排版、内嵌跳转与资源 | 乐高说明书,文字外套彩色标签框 |
| URL + HTML 超文本 + 超链接 + HTTP 报文 + 客户端-服务器 | **WWW 万维网** | 统一命名(URL)+统一传输(HTTP)+可互链超文本(HTML)三件套织成全球网 | 一张网:任意资源可命名、取回、互链跳转,靠点击漫游 | 暖色毛线球星球,表面爬满发光丝线 |
| 内容/数据 + 编码/表示 | (序列化字节) | 同一份内容按 ASCII/UTF-8/Base64 序列化成可传字节;MIME、字符集协商建其上 | 「内容↔可传字节」的可逆转换,跨系统能读懂 | 打字机把内容敲成一排标准符号 |
| 密钥 + 报文 | 对称加密 | 收发共享同一把密钥,发前搅成噪声,收后同钥还原 | 机密性:中间人看得见字节读不懂内容 | 暗箱,信塞进咔哒上锁变花纹 |

| 名字 + 非对称密钥对 + 数字签名 + 权威 | 数字证书 | CA 用私钥签「此域名的公钥就是这个」,你信这 CA 就接受这条绑定 | 把飘着的公钥可靠钉到具体域名上 | 带钢印身份证:照片=公钥,姓名=域名,钢印=CA 签名 |
| 数字证书 + 权威 + 数字签名 | 信任链 | 叶证书由中级 CA 签、中级由根签,根 CA 预装被无条件信任,逐级上溯到根 | 有限几个根信任撑起全网可信 | 一串套娃图章,最外层根章早钉在你怀里 |
| 非对称密钥对 / DH | ★ 密钥交换/协商(DH) | 双方在公开信道各自算出同一共享秘密、谁都没把它发出去(前向保密),≠用公钥加密传密钥 | 握手的心脏,前向保密基础 | 两人各调一半颜料,当众混合却算不出对方那半 |
| 数字证书 + 信任链 + 非对称密钥对 + 对称加密 + 数字摘要(HMAC) + 密钥交换 + 发起 + 约定码 | **TLS 安全信道** | 握手用证书+非对称验身份并 DH 协商临时对称密钥,此后每条报文对称加密(保密)+HMAC(防改);HTTPS=HTTP 跑在里面 | 公开不可信网络上同时得机密+完整+身份认证的三合一私密管道 | 暖色安全气管:入口验身份证,管壁不透明,每节带蜡封 |
| 报文 + 名字 + 资源 | 电子邮件与信箱 | 带信封头(发/收/主题)的报文;user@domain 左=信箱名右=域名(靠 MX 找邮局) | 异步留言:对方不在线也能先替他收着 | 带地址窗口的信封,右上贴邮票 |
| 编码 + 元数据 + 报文 | ★ MIME | SMTP 原生只走 7-bit ASCII;MIME 用 Content-Type+Base64+multipart 支持中文/附件/多媒体 | 邮件能装非 ASCII、附件、多媒体 | 信里塞进 Base64 编码的图片和多段内容 |
| 客户端-服务器 + 发起 + 内容/数据 + 两条连接 | ★ FTP | 控制连接(21)与数据连接(20)分离=带外信令;主动/被动模式决定谁发起数据连接 | 控制与数据分离(别的组件都没有) | 一根管发命令、另一根管专运货 |
| 电子邮件与信箱 + 中间人 + 副本 + 约定码 + DNS 解析 + 推 | SMTP 投递 | 按 MX 找收件域邮局,用 HELO/MAIL/RCPT/DATA 把信**推**过去,每台先存底再转发 | 跨域异步可达,可多跳中继,某跳不通能存着重试 | 一队驿站接力,每站先抄存一份再上路 |
| 电子邮件与信箱 + 中间人 + 约定码 + 状态 + 副本 + 拉 | POP/IMAP 收信 | 用户从邮箱**拉**信:POP 多下载即删;IMAP 留服务器只同步状态,多设备一致 | 收信与投递解耦,IMAP 多端看同一份状态 | POP 把筒掏空带走;IMAP 信留筒里手上只是同步镜子 |

## 四、合成链(到唯一实物)

> 每条链从原子一路合成到一件有真实规格的唯一实物,末尾标注该实物的**唯一规格由哪个组件决定**。

### 链 A:一台「千兆 8 口路由器」

```
比特 · 电平 · 时间 · 介质 · 双工
   └─(NRZ/曼彻斯特编码 · 载波调制 · 同步 · FDM/TDM)→ 物理链路
        └─(封装 · 界标 · MAC 地址 · CRC/FCS)──────────→ 帧 → 以太网帧
             └─(转发表 · 自学习 · 全双工多口)────────→ 交换机(以太网口)
                  └─(IP 首部 · 尽力而为)───────────────→ IP 分组
                       └─(路由表 · 最长前缀匹配 · ARP)──→ 分组转发
                            └─(OSPF · BGP · 默认网关 · ICMP)
                                 └────────────────────→ 【千兆 8 口路由器】
```

- **唯一规格来源**:接口数量与速率(8 口 · 1000BASE-T)由**物理链路 + 网卡/接口**型号决定;能跨哪些网、懂哪些路由由**路由表 + 分组转发 + OSPF/BGP** 决定;能否 ping 通与诊断由 **ICMP** 贡献;家用款附带的 NAT/DHCP 由那两个组件决定(骨干款去掉、加 BGP)。

### 链 B:一台「2U8G+100G 的服务器」(跑 Web 服务)

```
[继承链 A 的以太网口，主机侧网卡]
   端口号 + IP 地址 ──────────────→ 套接字 socket
        └─(复用分用)──────────────→ 报文段
             ├─(轻:UDP)───────────→ UDP 用户数据报
             └─(重:序号+确认+定时器+校验和+滑动窗口)
                  └─ 可靠传输 + 流量控制 + 拥塞控制 + 三/四次握手
                       └──────────→ TCP 连接
                            └─(报文 · 方法 · 状态码 · 持久连接)→ HTTP 报文
                                 └─(TLS 安全信道 = 证书+信任链+DH+对称加密+HMAC)
                                      └──────────────────→ 【2U8G+100G 服务器】
```

- **唯一规格来源**:机箱形态 **2U**、内存 **8G**、存储 **100G** 是硬件底座;它能同时扛多少并发连接由**套接字 + 复用分用 + TCP 连接**(四元组区分)决定;不丢数据、按序到达由**可靠传输**贡献;不淹网络、多连接公平由**拥塞控制**贡献;不淹自己由**流量控制 + 接收缓存**贡献;对外提供 HTTPS 网站由 **HTTP 报文 + TLS 安全信道** 决定;它的「进程如何被外部找到」由 **socket 绑定端口(如 443)** 决定。

### 链 C:一个「全球 CDN 边缘节点 + 权威 DNS」

```
名字 · 内容/数据 ──────────────→ 资源
名字 + 权威 ───────────────────→ 域名
     └─(映射 · 约定码 · 有效期 TTL)→ 资源记录(A/AAAA/CNAME/NS/MX)
          └─(中间人:递归解析器 · Web 缓存)
               └─ 迭代/递归查询 ──→ DNS 解析
                    └─(副本 · TTL · 元数据 · 中间人)→ Web 缓存
                         └─(全球边缘 + DNS 按位置引流)
                              └──────────────────→ 【全球 CDN 边缘节点】
```

- **唯一规格来源**:能被人念名字访问由**域名 + 资源记录**决定;「解析到最近节点」由 **DNS 解析 + CDN** 的位置引流决定;命中率与新鲜度由 **有效期(TTL) + Web 缓存的条件请求** 决定;抗高并发由**副本**在全球边缘的铺开数量决定。

### 链 D:一间「百兆办公室 LAN · 1 广播域 · 划 3 VLAN」

```
以太网帧 · MAC · CRC
   └─(交换机:转发表+自学习+多口全双工)
        └─(网卡 × N 台主机)
             └─(广播地址 → 广播域)
                  └─(VLAN Tag / 802.1Q)
                       └─(ARP 把 IP↔MAC · DHCP 发地址 · 默认网关出门)
                            └──────────────────→ 【百兆办公室 LAN】
```

- **唯一规格来源**:内部谁能直达谁由**交换机 + ARP**(同广播域)决定;广播能传多远由**广播域**边界(路由器/VLAN)决定;被切成几个逻辑子网由 **VLAN** 决定;新机器插上就能上网由 **DHCP** 决定;对外统一出口由**默认网关**决定;「百兆/千兆」由底层**以太网物理层型号**决定。

## 五、跨层复用的母规则

> 同一条原理在多层反复重演——这是合成树里的「横向重演」,也是整张知识图谱的骨架。评审时可据此检查:某层缺了母规则的某次复现,往往就是漏了组件。

1. **分层封装/解封装**——把上层数据当黑盒裹进本层信封,只认本层首尾,对方同层原样拆开。
   复现:物理层比特→数据链路层**帧**→网络层**IP 分组**→传输层**报文段**→应用层**报文**;PPP/以太网各自成帧;网络层再自我嵌套成 **VPN/隧道**(IP 包封进 IP 包)。

2. **间接寻址三级跳(名字→地址→下一跳→进程)**——没有谁一步到位,都是一次次查表指路。
   复现:应用层 **DNS**(域名→IP)、传输层**端口/套接字**(IP→进程)、网络层**路由表 + 最长前缀匹配**(IP→下一跳)、数据链路层 **ARP**(IP→MAC);每一跳都是 `映射` 原子的化身。

3. **翻译/接线口**——两套地址体系之间的桥。
   复现:**ARP**(逻辑 IP ↔ 硬件 MAC)、**NAT**(私网 ↔ 公网)、**DNS**(人名 ↔ 机器 IP)、**数字证书**(域名 ↔ 公钥)、**编码/表示**(内容 ↔ 可传字节)。

4. **校验与纠错(加冗余对账)**——由数据自算一笔冗余,收方重算判断路上坏没坏,更强的还能纠。
   复现:物理层 **BER**、数据链路层**奇偶/校验和/CRC**(检)与**海明码**(纠)、网络层 **IP 首部校验和**、传输层 **TCP/UDP 校验和**、应用层**数字摘要/HMAC**。同源母原子:`冗余校验`(链路)与 `校验和`(传输)、`哈希`(应用)是跨层同族。

5. **窗口/反馈控制(以回执调节发送)**——发送方按对面/网络反馈动态收放流量。
   复现:数据链路层**滑动窗口/流量控制**、传输层**滑动窗口 + 流量控制(rwnd) + 拥塞控制(cwnd,AIMD)**;物理层的**同步**也是一种「按反馈对齐」的低配版。

6. **复用/分用(一条底层共享给多路)**——多路汇成一股走同一底层,再按标签分回。
   复现:物理层 **FDM/TDM/CDM/WDM**、数据链路层**信道划分 + CSMA**、传输层**端口复用分用**(一根网线给全机程序共享)。

7. **缓存 + 有效期(TTL)**——存一份副本就近用,到点作废重取。
   复现:数据链路层**转发表/ARP 表老化**、网络层**路由表**、应用层 **DNS TTL / Web 缓存 / CDN**;共同母原子:`副本` + `有效期`。

8. **随机退避打破对称**——大家同时动手就都失败,用随机数错开。
   复现:数据链路层 **CSMA/CD**(有线)与 **CSMA/CA**(无线);共同母原子:`退避`。

9. **权威委派树(信任可传递、收束到少数锚点)**——把「谁说了算」分级委派,逐级上溯到根。
   复现:应用层 **DNS 域名树**(根→顶级→权威)、**证书信任链**(根 CA→中级→叶)、网络层 **AS/BGP**(域内 IGP 细算、域间 EGP 谈策略);共同母原子:`权威`。

10. **广播喊话再定位(先一对全体,再一对一)**——不知道对方在哪,先朝全体喊一嗓子,应答者暴露自己。
    复现:数据链路层 **ARP**(广播问 MAC)、应用层/网络层 **DHCP**(广播 Discover 求配网);共同母原子:`广播地址` / `发起`。

11. **定界/成帧(在连绵流里划出「一件」)**——底层只给连绵字节,靠约定记号切出可独立处理的单元。
    复现:物理层**同步**(切出比特边界)、数据链路层**界标 + 透明传输**(切出帧)、应用层**报文**(空行/长度切出信件)。

---

*（评审提示:第三节各分表合起来即完整「反应表」,可逐行核对「反应规则」是否写成了玩家必须理解的那一句;第二节带 ★ 的原子与第三节带 ★ 的组件为本轮按 verify 判决新增/改判项,重点复核。）*

## 六、完备性审查(机器自检 · 待人工裁决)

> 这是最后一道审查 agent 找出的地基缺口,按严重度排。不是结论,是给你逐条拍板用的。

**总评:** 地基总体扎实、可据此启动玩法设计,但crafting规则引擎先别急着落地,要过一遍「反应图规范化」再动。优点很实:向下探到比特/量化/PCM/香农,横向把复用、拥塞控制全家桶、NAT、v4/v6、TLS、DNS都覆盖到位,没有整块漏掉的大概念;形象几乎无偷懒、具体可画且贴暖色手绘吉祥物基调,是明显强项。真正要返工的不是内容而是结构一致性:(1)地址族的原子/组件判据自相矛盾(IP/端口当原子却把MAC拆成组件)、校验族一名两义;(2)反应图有环(广播域↔局域网、网桥↔生成树)且有一批未定义反应物(窗口、生成多项式、共享信道…),在「先拼原子再涌现」的范式下会直接不可合成;(3)少数「假反应」(虚电路/SDN/IP组播)反应物即产物重述;(4)两处规格溯源/重复问题(服务器招牌规格2U8G100G凭空写死、socket两套配方)。这些都是一次有纪律的归一化清理即可解决,不是概念级推倒重来。建议:美术与UX可并行推进,但把整张反应表跑成一张无环、已拓扑排序、每个反应物都能在库存中找到出处的DAG,并统一地址族与校验族的原子/组件边界之后,再冻结并开工合成规则引擎。

| 区域 | 缺口 | 严重度 |
|---|---|---|
| 原子/组件判据·地址族 | 同为「标识+比特」,MAC地址被拆成组件(标识+48位→MAC地址),而IP地址、端口号却当原子。按文档自己的 verify 判据(能用已列概念定义出来就不是原子),IP地址=标识+比特(32/128)+可软配置、端口号=「16位纯标识」都应是组件。地址族的原子/组件边界自相矛盾——这正是全游戏立身的分类,必须统一:要么「标识」是唯一地址原子、MAC/IP/端口全降为组件;要么三者都当原子并明说判据例外。 | 🔴 高 |
| 反应图有环·不可合成 | 广播域 的反应物含 局域网(广播地址+交换机+局域网→广播域),而 局域网 的反应物又含 广播域(以太网+交换机+网卡+广播域+VLAN→局域网)——互为原料。合成游戏「先拼原子再涌现」的范式下这是死锁,先有谁都造不出。类似地 网桥↔生成树 也互为反应物。必须打断成单向。 | 🔴 高 |
| 校验族命名与判据 | 校验和 在传输层列为原子,同一个「校验和」在链路层又是组件(冗余校验+比特→校验和)——同名既是原子又是产物。且检错原语在链路层叫「冗余校验」、传输层叫「校验和」(一个原语两个名),而「校验和」还另作链路层组件名。校验族(冗余校验/校验和/哈希)需一次正名:定一个原语原子,具体算法(奇偶/Internet校验和/CRC/海明)统一为组件。 | 🟡 中 |
| 帧的载荷层级倒置 | 帧 的反应物写死「IP分组(载荷)」,但IP分组是更上层、且到3.3才定义;帧实际还承载ARP、IPv6等(ARP根本不是IP分组)。这既是向上层的倒置依赖,又与「封装=把上层数据当黑盒」的原子设定冲突。应改成通用「上层数据/载荷」,像IP分组那样(IP首部+尽力而为+上层报文)。 | 🟡 中 |
| 假反应·反应物即产物 | 虚电路服务(连接建立+每跳VC状态表+VC标签转发)、SDN(控制器+流表)、IP组播+IGMP(组管理+组播转发)这几行,反应物基本是把产物名拆开重述,并未从已有原子/组件真正合出来——是「说不通的假反应」。需补出真正的前置原子(如「连接状态」),或改写反应物使其可从库存拼出。 | 🟡 中 |
| 未定义反应物散落 | 多处反应物既非原子也非前面产物:窗口(链路层「ARQ+序号+窗口→滑动窗口」直接用,全表却无定义,导致该核心组件不可合成)、生成多项式、共享信道、MTU、网络位边界、聚合规则、轮流规则、RTT采样、重复ACK计数、两条连接、BPDU帧/无环树等。crafting 中每个反应物必须已在库存;需给其中真概念补原子/组件,把纯参数(生成多项式/MTU)显式挂到某原子上。 | 🟡 中 |
| 套接字重复定义 | 套接字/Socket 被定义两次:传输层=IP地址+端口号,应用层=进程+端口+发起(listen/connect),配方与语义都不同却同名。合成里同一产物两张配方会打架。应确定 socket 是「传输层端点」还是「应用/传输接缝」,只合成一处,另一处引用它。 | 🟡 中 |
| 端口概念一词多用 | 端口号原子明确是「16位进程级地址」,但链路层 转发表/自学习 又拿「端口」当交换机物理口用(标识+端口+帧→转发表)。同名不同物,会把进程端口错当成交换口的合成原料。交换/接口口应另起名(接口/网卡口),与传输层端口号区分。 | 🟡 中 |
| 规格溯源断裂·服务器链 | 链B终态「2U8G+100G服务器」的招牌规格(机箱2U/内存8G/存储100G)被直接当「硬件底座」写死,无一由拼进去的网络组件决定——违反「规格由拼进去的组件决定」。对比链A路由器「千兆8口」确由 物理链路+网卡型号 定出。服务器作为网络终态,其可溯源规格应是并发连接数/吞吐/是否HTTPS,而非RAM/磁盘;要么换招牌规格,要么补非网络硬件组件的来源。 | 🟡 中 |
| 依赖图未拓扑排序 | 多处前向引用:CIDR 用了后定义的 最长前缀匹配、局域网 用了后定义的 以太网、DNS解析 用了后定义的 Web缓存、VLAN 用了同表后一行的 广播域。单看是排序问题,但「自底向上逐步解锁合成」的玩法要求整张反应图是无环且已拓扑排序的 DAG,建议出一版自动依赖校验挡住环与前向引用。 | 🟢 低 |
| 跨层原子未标全 | 序号 在链路层 ARQ/滑动窗口 就被用到,却只列为传输层原子;应像 确认、定时器 那样显式标为跨层原子,否则链路层那几行的反应物悬空。 | 🟢 低 |
| 缺概念·排队与交换范式 | 拥塞的物理成因(路由器缓存/排队时延、丢包=队列溢出)没有对应组件——拥塞信号在传输层被「嗅出来」,但网络层没有产生它的队列实体;四种时延只落了传播与传输,缺排队。此外电路交换 vs 分组交换这一根本二分只落了虚电路/数据报(都属分组交换),经典电路交换缺席。均非阻塞项,但地基完整性上值得补。 | 🟢 低 |
| 封装:原子还是母规则 | 封装 既作数据链路层原子,又是母规则#1「分层封装/解封装」那条贯穿全层的重演规则。作为「根本动作」它更像跨层的操作/规则而非某层原子;需言明:是把它当唯一封装原子、各层封装皆其复现,还是各层各有封装组件。不影响玩法,属概念层级收口。 | 🟢 低 |
| 个别反应欠力度·原语重叠 | IPv6=IP地址+IP首部+ICMP,反应物撑不起128位/自动配置/取消途中分片等关键涌现;随机 被 噪声 与 退避 都用到却无「随机」原子(仅对噪声承认);有效期(应用)与 定时器、TTL 三个「到点作废」原语语义重叠、有效期可由定时器派生。都是小的收口问题。 | 🟢 低 |
