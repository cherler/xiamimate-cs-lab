# v2 玩法升级提案

> 起因(试玩原话):**「我过一关,就发现卡牌内容比较重复。找不到更爽的点。」**
> **「我们算法除了排序算法,其实还有算法。」**
>
> 本文只收**能落到算法卡牌场景上**的机制。好玩但落不下来的,在第 6 节明确排除。

---

## 1. 诊断:重复感是算出来的,不是错觉

| 事实 | 数字 |
|---|---|
| 起始牌组 10 张里只有 **两种**效果 | 遍历×5 + 批处理×4 + 观察×1 → **90%** |
| 第 1 关手上 16 张,起始牌占 | **63%** |
| 打完 8 关牌组也只有 | **23 张**(每关只 +1) |
| 起始牌能去掉几张 | **0 张 —— 没有除牌机制** |
| 全卡池 | **25 张**,只覆盖 4 个算法家族 |

**你第一关的体验,literally 就是「遍历、批处理、遍历、批处理」。** 这不是内容不够,是结构缺了三样东西:**除牌、被动、乘法爆点**。

## 2. 竞品拆解 —— 五条,逐条判定能不能落地

### 2.1 除牌 / 精简牌组(《杀戮尖塔》)

> 「每加一张牌,就多一次你抽到它而不是抽到真正想要那张的机会。」
> 「删掉一张 Strike 对胜率的贡献,大过加进大多数普通卡。」
> 「大多数 run 你想要 12–20 张牌 —— 少到还能打死 Boss 为止。」
> —— [Cloudfall Studios](https://www.cloudfallstudios.com/blog/2020/12/7/why-card-removal-is-strong-in-deckbuilding-games-quick-perspectives) · [MetaBot.GG](https://metabot.gg/en/slay-the-spire-2/guides/deck-thinning-and-deck-size) · [sts2front](https://sts2front.com/tips/deck-thinning-strategy/)
>
> 关键设计:StS 的商店**每次只能删一张,要花钱,而且价格每删一次永久上涨** —— 让删牌成为有代价的取舍,而不是无脑操作。

**落地判定:✅ 直接能落,而且是当前最痛的一处。**

做成关卡之间的「**重构**」节点:删掉一张牌。代价照抄 StS —— 次数有限、越删越贵。
主题上完全自洽:**重构就是把代码里的冗余删掉**。

### 2.2 遗物 / 局定被动(《杀戮尖塔》)

> 「遗物坐在每一次成功 run 的正中心 —— 它们塑造牌组策略、定义构筑方向,常常决定这一局能不能活过第二章。」
> 「最好的遗物做三件事之一:产能量、不用出牌就能被动成长、或者免疫新的负面状态。」
> —— [GAMES.GG](https://games.gg/slay-the-spire-2/guides/slay-the-spire-2-relics-tier-list/) · [Pro Game Guides](https://progameguides.com/slay-the-spire-2/slay-the-spire-2-relics-tier-list/)

**落地判定:✅ 能落,而且算法领域的被动名字天然好听。**

叫「**编译器优化**」或「**工程直觉**」。概念图里 AI 自己想出来的六个名字都能直接用:
`摊还直觉` · `单调性` · `惰性求值` · `平衡取舍` · `随机化边` · `缓存友好`

它们**不占牌位**,所以不加重上面那个「牌组被稀释」的问题 —— 这正是遗物之于除牌的互补关系。

### 2.3 X-Mult 叠乘(《小丑牌》)—— **这是「爽点」的答案**

> 「X-Mult 小丑是指数缩放的:两个 ×3 叠出 ×9,三个叠出 ×27 —— 这就是 Balatro 能跑到十亿分的原因。」
> 「甜点是三件套:一个强 chip、一个成长型 mult,然后能叠多少 X-Mult 就叠多少。」
> —— [Balatro Wiki 缩放指南](https://balatrowiki.org/w/Guide:_Scaling) · [TheGamer](https://www.thegamer.com/balatro-best-joker-combos-tips-strategy/) · [ejaw.net](https://ejaw.net/balatro/)

**落地判定:✅✅ 不只是能落 —— 这是算法卡牌比别的卡牌游戏更该有的机制。**

**我们现在四个乘区(有序层数 / 段数 / 预处理值 / 债务)全是加法叠加。** 有序层数 +1 → 二分查找多移除 2 个。永远线性,所以永远没有爆发。

而 Balatro 的爽点在算法领域有一个**字面意义上的对应物:复杂度降阶**。

```
O(n²)  →  O(n log n)  →  O(n)  →  O(log n)
        每降一阶,全部输出 ×2 —— 四阶就是 ×8
```

**这不是比喻,这是真的数学。** 而且它是可教的:你会亲身体会到「先花三回合排序,然后一回合结束战斗」凭什么强过「每回合砍一点」—— 那正是 O(n log n) 打 O(n²)。

四条流派各有降阶条件,互不相同:

| 流派 | 降一阶的条件 | 对应的真实道理 |
|---|---|---|
| 排序 | 有序层数打满 4/4 | 排好序才能二分 |
| 拆解 | 段数到 4 | 分治 |
| 复利 | 预处理值 ≥ 当前规模 | 空间换时间 |
| 激进 | 债务清零的那一刻 | 接受近似解 |

而精英可以**把你升回去**(最坏用例、状态爆炸现在有了更狠的身份)。降阶—被打回—再降阶,这就是节奏。

### 2.4 数据结构 = 随从,算法 = 法术(《炉石传说》)

炉石的核心是**场上有东西**:随从留在场上持续生效,法术一次性。我们现在**没有「场」** —— 只有你的手牌和敌人的柱子,所以每回合都在原地重复。

**落地判定:✅✅ 这是结构性最大的一块,而且理论上无比自洽。**

**算法是作用在数据结构上的。** 你先建一个堆,堆排序才快;先建哈希表,查找才 O(1);先建并查集,连通性才近乎常数。

做成「**结构区**」:4 个槽位,你花回合建数据结构,它们**留在场上**、有耐久、能被敌人打掉:

| 结构 | 建在场上之后 |
|---|---|
| 最小堆 | 每回合末自动移除最小的 1 个元素 |
| 哈希表 | 查表类卡改为 O(1):不再摊平,直接点杀 |
| 并查集 | 稠密图的连线惩罚失效;分治的段数上限 +2 |
| 前缀和数组 | 摊平类卡的处理量改为「区间求和」,不随规模衰减 |
| 单调队列 | 每回合保留一张手牌不进弃牌堆 |

而**内存是有限的**(见 2.6)—— 建得越多,时间预算越紧。这就是取舍。

### 2.5 Discover / 发现(《炉石传说》)

> 「Discover 是随机与玩家自主权之间的精妙平衡……它引入随机但用『你来选』对冲,避免玩家觉得被坑。」
> —— [Dominic Calkosz](https://dominic-calkosz.com/blog/discover-the-design) · [cardsrealm](https://hs.cardsrealm.com/en-us/articles/hearthstone-the-story-behind-discover-the-mechanic-that-came-to-stay)

**落地判定:✅ 能落,成本低。**

叫「**查文献**」:从全卡池(不限流派)随机三张里选一张。它解决的是**「我这局永远只能玩这一条流派」** —— 给一条跨流派的口子,又不破坏构筑的确定性。

### 2.6 双流派(《怪物列车》)

> 「开局选两个派系组成牌组……五个派系组合出 20 种牌池,而每个派系还有两张不同的冠军牌可选。」
> 「哪怕你玩同样两个派系,也不会有两局是相似的。」
> —— [Loot Level Chill](https://lootlevelchill.com/reviews/monster-train-2-review/) · [GamePassPod](https://www.gamepasspod.com/blog/monster-train-2-a-deep-dive-into-new-clan-synergies/)

**落地判定:✅ 能落,而且几乎免费 —— 我们已经有四条流派,只差允许选两条。**

4 选 2 = **6 种组合**,立刻把「一局一种体验」变成六种。而且组合本身有真实的算法含义:

- 排序 + 拆解 = **归并排序**(切开、各自排、合并)
- 排序 + 复利 = **索引**(排好序再建索引,查找 O(log n))
- 拆解 + 复利 = **记忆化递归**(分治 + 缓存子问题)
- 复利 + 激进 = **启发式剪枝搜索**(估价函数 + 贪心走)
- 排序 + 激进 = **区间调度**(按结束时间排序后贪心 —— 教科书级的经典)
- 拆解 + 激进 = **随机化快排**(随机选主元)

**每一种组合都是一个真实存在的算法。** 这是这个题材白送的礼物。

## 3. 第二条资源轴:内存

概念图里 AI 自己加了 `COMPUTE 12` 和 `MEMORY 18/32` 两个资源 —— 这个点子比我原本想的好。

现在只有一条轴:**预算(时间)**。加上**内存(空间)**之后:

- 数据结构占内存,留在场上就一直占
- 预处理值、建表、记忆化都吃内存
- 内存满了要拆结构,或者用「压缩」类卡

**空间换时间是算法里最基本的一条取舍,而现在游戏里完全没有它。** 有了它,「建三个结构」不再是无脑好事。

## 4. 算法家族:从 4 个扩到 10 个

现在只用了 排序 / 分治 / 记忆化 / 贪心。真实的算法版图大得多:

| 家族 | 代表卡 | 它带来什么现在没有的东西 |
|---|---|---|
| **图与连通性** | 广度优先 · 深度优先 · 并查集 · 拓扑排序 · 最短路 | 敌人可以真的是**图**,不是带标志位的数组 |
| **哈希与索引** | 哈希表 · 布隆过滤器 · 一致性哈希 · 字典树 | O(1) 查找 —— 点杀不看规模 |
| **双指针 / 滑动窗口** | 两端逼近 · 滑窗 · 单调队列 · 前缀和 · 差分 | **区间**操作:一次处理一段而不是一个 |
| **堆与 Top-K** | 最小堆 · 堆排序 · 中位数流 | 持续性:每回合自动干活 |
| **位运算** | 状态压缩 · 位图 · 异或消消乐 | 极低成本的批量操作 |
| **随机化** | 蒙特卡洛 · 水塘抽样 · 跳表 · 随机主元 | 高方差高回报,和「稳定」流派形成对立面 |
| **摊还** | 动态扩容 · 路径压缩 · 势能法 | 前期亏后期赚 —— 一条新的成长曲线 |
| **字符串** | KMP · 后缀数组 · AC 自动机 | 模式匹配:对「重复页」这类敌人特化 |
| **缓存** | LRU · 预取 · 局部性 | 和内存资源直接挂钩 |
| **并发** | 无锁 · CAS · 分片 | 多线程 = 一回合多次结算,天然的爆发牌 |

**每个家族给 4~6 张卡,卡池从 25 张变成 50~70 张。** 配合双流派(4 选 2 → 10 选 2),重复感的根就断了。

## 5. 我的排序:先做哪三件

按 **性价比 = 效果 ÷ 工作量**:

| 优先级 | 做什么 | 工作量 | 为什么排在这 |
|:-:|---|:-:|---|
| **1** | **除牌节点** | 小 | 直接打在最痛的地方(63% 起始牌)。改 RUN 结构 + 一个界面,半天 |
| **2** | **复杂度阶(降阶 = 全局 ×2)** | 中 | 唯一的「爽点」来源,而且是这个题材独有的。要重调全部数值 |
| **3** | **双流派 4 选 2** | 小 | 几乎免费:牌池已有,只差允许选两条。一局一种 → 六种 |
| 4 | 结构区 + 内存资源 | **大** | 效果最大但是重写引擎级别 —— 要有「场」的概念、耐久、敌人打结构 |
| 5 | 查文献(Discover) | 小 | 锦上添花 |
| 6 | 算法家族扩到 10 个 | 大但可分批 | 每个家族独立,可以一次做一个 |

**建议顺序:1 → 3 → 2,先用小成本把重复感压下去,再动数值大工程。**

## 6. 明确不做的

| 机制 | 为什么落不下来 |
|---|---|
| **随从互相攻击 / 站位** | 我们的敌人是一堆数据不是一队怪。硬做要发明「数据会打人」,主题立刻崩 |
| **对手也是一副牌组(PvP 式)** | 算法没有「对手在出牌」这个概念。对抗性输入已经是这件事的正确形态 |
| **抽卡 / 开包 / 集换** | 商业模式不是这个,而且会把构筑的确定性打碎 |
| **法力水晶逐回合增长** | 我们的预算是「时间开销」,按剩余规模收 —— 那个语义比炉石的水晶更准,不该退回去 |
| **嘲讽 / 圣盾 之类的关键词堆叠** | 这些是为「场上随从互殴」服务的。没有那个场就没有意义 |

# 第二轮:两个不同角度的思考

> 第一轮(上面 1–7 节)走的是**竞品移植**路线:把 StS / Balatro / 炉石 / 怪物列车的机制搬过来。
> 这一轮换两个角度重新问一遍。**两个角度都和第一轮的结论不完全一致,先不合并。**

---

## 角度一 · 问题可能不是「卡少」,是「不需要你」

第一轮我默认了「重复 = 内容不够 → 加内容」。先验证这个默认对不对。

### A1 · 策略溢价:精心出牌比乱打多赢多少

三种出牌方式跑同样的局面 —— **精心策略**(现有 AI)/ **乱打**(能出就随机出)/ **出第一张**(永远出手牌最左边能出的):

| 对局 | 深度 | 精心策略 | 乱打 | 出第一张 | **策略溢价** |
|---|:-:|:-:|:-:|:-:|:-:|
| 排序流 vs 乱序数字 | 5 | 86% | 11% | 8% | **+75 点** |
| 分治流 vs 乱序数字 | 6 | 81% | 24% | 22% | **+57 点** |
| 贪心流 vs 乱序数字 | 4 | 84% | 33% | 34% | **+50 点** |
| **复利流 vs 乱序数字** | 5 | 82% | **75%** | 72% | **+7 点** |

两个结论:

**① 复利流(预处理→查表)几乎不需要思考。** 乱打 75%,精心 82%。它的最优解就是「堆预处理值,然后查表」,**顺序无所谓、时机无所谓**。四条流派里它最像「重复」。

**② 更要命的是深度 0:三种打法全部 100%。**

> **你玩的第一关,策略溢价是 0。怎么打都赢。**
>
> 你说「打一关就觉得重复」—— 那不是卡重复,是**那一关根本不需要你**。
> 新玩家的第一印象恰恰在这里形成,而这里是整局里唯一没有决策的地方。

### A2 · 25 张卡里,真正在被玩的有几张

深度 5、每流派 300 局,统计每张卡的出牌占比 和「抽到之后真的出掉的比例」:

| 流派 | 出牌量第一名 | 占比 | 几乎不出的卡 |
|---|---|:-:|---|
| 排序流 | **遍历** | **32.6%** | 观察 **0%** · 批处理 抽到后只出 **11%** |
| 拆解流 | **遍历** | **34.4%** | 观察 **0%** · 批处理 **9%** |
| 复利流 | **遍历** | **33.1%** | 观察 **4%** · 批处理 **25%** |
| 激进流 | **遍历** | **35.3%** | 观察 **2%** · 批处理 **23%** |

**你每出三张牌,就有一张是「遍历」—— 四条流派全都一样。** 这就是重复感的算术来源。

而起始牌组的另外两种:**「观察」在三条流派里一次都没出过,「批处理」抽到之后 75~91% 的时候烂在手里。**

10 张起始牌 = 1 张统治 + 1 张鸡肋 + 1 张废牌。

### A3 · 这个角度指向的对策(和第一轮方向相反:先减不先加)

| | 做什么 | 为什么 |
|:-:|---|---|
| 1 | **第 1 关就要有决策** | 现在岔口在深度 0 形同虚设(两边都白给)。要么第 1 关就给真实压力,要么把岔口的后果做实(比如选哪边决定你后面能遇到什么) |
| 2 | **重做起始牌组,而不是加新卡** | 与其把卡池从 25 张扩到 70 张,不如让现有 10 张每张都有出的理由。「观察」这张牌现在等于不存在 |
| 3 | **给复利流一个时机决策** | 现在「先堆后兑现」顺序无所谓。让预处理值有衰减 / 让查表有冷却 / 让规模增长和预处理赛跑 —— 立刻产生「什么时候兑现」的判断 |
| 4 | **删牌** | 第一轮就提了,这个角度只是又一次指向它 |

**这条路线全部不动引擎,成本远低于第一轮的提案。**

## 角度二 · 这个题材独有的、别人抄不走的是什么

第一轮问的是「别人有什么好机制」。反过来问:**算法卡牌有什么是别的卡牌游戏结构上做不到的?**

### B1 · 我们的敌人是完全透明的

炉石你不知道对手手牌;StS 你只看得到意图图标。**而我们的敌人是一堆你能看见每一根柱子的数据。**

透明性通常被当成缺点 —— 没有信息不对称就没有紧张感。但它恰恰是这个题材唯一别人抄不走的东西:

> **难点不是「我不知道会发生什么」,而是「我看得见全部,却不知道该用哪个方法」。**

这就是做算法题的真实体验:**题目全给你了,难的是选对方法。**

### B2 · 但这个维度现在是空的

查了生成柱子的那一行:

```js
bars: Array.from({length:E.n}, () => ({v: 3 + Math.floor(R()*(vmax-3+1))}))
```

**11 个敌人里,除了「重复页」改了 vmax,其余全部是同一个均匀随机分布。**

| 敌人 | 初始有序度 | 分布 |
|---|:-:|---|
| 一团乱序数字 / 磁带 / 价格流 / 六度关系 / 五个精英 / Boss | 全部 ~50% | 全部均匀随机 |
| 爬虫抓回来的重复页 | ~50% | 均匀随机,只是值域窄 |

**名字讲了十一种数据,形状只有一种。** 我上一轮加的形态标记(磁带走带、连线网、焊死的块)是**画上去的**,不是数据本身长出来的。

### B3 · 如果押这一条,设计往完全不同的方向走

**让数据的形状本身成为谜面。** 敌人不再是「均匀随机 + 标志位」,而是真的有形状:

| 数据形状 | 一眼看过去 | 正确解法 | 教的东西 |
|---|---|---|---|
| **几乎有序**(只有几个错位) | 阶梯,少数几根跳出来 | **插入排序 O(n)** | **笨办法有时候更快** —— 快排在这里反而慢 |
| **全是重复值** | 一片等高柱子 | 三路快排 / 计数排序 | 值域决定算法 |
| **有序但被旋转过** | 两段阶梯 | 二分找断点 | 结构没坏,只是移了位 |
| **长尾** | 少数极高 + 一大片矮 | 堆取 Top-K | 不必全排 |
| **稀疏** | 大片接近零 | 位图 / 跳表 | 空的地方不该占时间 |
| **对抗性构造** | 看着像随机,其实专挑你的主元 | 随机化 | 最坏用例的真正含义 |

**看一眼柱子的形状,就知道该出哪张卡。** 这是「看懂」不是「记住」—— 正是设计文档里 R2「卡面可推,不许查表」的延伸。

而且**换皮测试满分**:换成任何别的题材,「几乎有序」这件事立刻失去意义。

### B4 · 和旧结论的冲突,必须讲清楚

设计文档第 1 节写过:**敌人不做 LeetCode 题,因为有唯一解会退化成「识别题型 → 出对应卡」,构筑就死了。** B3 看起来正在往那条线上走。

区别在这里:

| | LeetCode 题 | 数据形状 |
|---|---|---|
| 解 | **唯一** | **多种都可行,只是快慢不同** |
| 玩家做的事 | 识别题型 → 查表出卡 | 看形状 → **判断哪条流派更划算** |
| 对构筑的影响 | 杀死构筑(必须带那张卡) | **强化构筑**(你的牌组决定你能吃哪些形状) |
| 重玩价值 | 一次性(知道答案就没了) | 形状 × 流派 = 组合空间 |

关键是**几乎有序的数组用归并排序也能过,只是要多花三回合**。有次优解,构筑就活着。

### B5 · 这条路线还带来一个别人没有的东西:最优解可判定

别的卡牌游戏没有「正确答案」。**我们有。** 战斗结束可以给:

```
你用了 14 回合 · 这个数据的最优解是 6 回合(插入排序 + 二分)
```

这是 Zachtronics 的核心循环 —— 通关后给你看你排在所有解法的哪一段。**它是另一种「欲罢不能」:不是数字爆炸,是「我还能更好」。**

## 两个角度和第一轮的分歧:爽点类型是个选择题

三条路线其实押在三种**不同类型**的爽点上,而它们的设计要求互相冲突:

| 爽点类型 | 代表作 | 我们的对应 | 要什么 | 忌讳什么 |
|---|---|---|---|---|
| **数字爆炸** | 小丑牌 | 复杂度降阶 ×8(**第一轮**) | 大量叠乘 · 视听反馈 · 越滚越大 | 信息完整、解法唯一 |
| **构筑顿悟** | 杀戮尖塔 | 「这套牌成型了」 | 卡池大 · 除牌 · 遗物 | 单局内决策过重 |
| **理解顿悟** | Zachtronics · 见证者 | 「哦这堆数据几乎有序」(**角度二**) | 信息完整 · 事后评分 · 鼓励重玩同一关 | 随机性、越滚越大 |

**第一轮我直接押了「数字爆炸」,但从来没有论证过这是不是对的选择。**

而**角度一是三条路线都要做的地基** —— 无论押哪种爽点,「第一关不需要玩家」和「每三张牌一张遍历」都得先修。
