# 算法卡牌 · 设计与实现规格

> **这份文档 = 设计意图 + 当前实现的真实规格。** 数值全部从 `index.html` 提取,与代码一致。
> 原型:`index.html`(单文件,无构建)· 操作:**1–5 换流派重开** · **A 键自动演示** · 点卡出牌
> 旧版《net-deck.md》(网络故障对症思路)已废弃。

---

## 1. 定位与核心取舍

**普通卡牌玩法,血条胜负。卡 = 有行为的算法,敌人 = 有性质的数据。**

### 1.1 三条不许破的规则

| # | 规则 | 为什么 |
|---|---|---|
| **R1** | **知识做「规则」,不做「答案」** | 若盘面写着「这是 X → 出 Y 卡」,就退化成读标签配对,构筑和思考同时消失 |
| **R2** | **卡面可推,不许查表** | 金铲铲劝退的原因是三层纯记忆(技能/羁绊/组合)。本作任何卡、任何组合,玩家须能从名字和卡面推出来 |
| **R3** | **屏幕上没有怪物,只有数据** | 飘字飘「处理了 12 个元素」,不飘「造成 12 点伤害」 |

### 1.2 为什么不用 LeetCode 题当敌人

一道 LeetCode 题**有唯一解**(两数之和→哈希、爬楼梯→DP)。做成敌人就变回「识别题型→出对应卡」,并且**杀死构筑**——每场只需要那一张对的卡。

而且**谜题一次性,战斗要可重复**。这是品类冲突,不是难度问题。

**正解:敌人是「有性质的数据」。** 性质的组合 = 无限场战斗,每种组合有多个可行打法。
这也恰好是 LeetCode 教不了的那部分:**数据长什么样,决定用什么算法。**

### 1.3 「有名」的正确用法

有名的**经典问题**(背包/旅行商/指数爆炸)→ **当 Boss**(一次性、考范式、名气红利最大)
有名的**场景**(乱序日志/只能从头读的磁带)→ **当小怪**(名字自带数据性质,不用查表)

## 2. 核心机制(实现规格)

### 2.1 一场战斗 = 一道题

| | 传统卡牌 | 这里 |
|---|---|---|
| 敌人血条 | 生命值 | **规模 N = 存活元素个数** |
| 你的血条 | 生命值 | **预算(时间)** |
| 你输了 | 被打死 | **算不完(预算耗尽)** |

### 2.2 常量(代码 `const T`)

| 常量 | 值 | 含义 |
|---|:-:|---|
| `BUDGET` | 60 | 每场预算(**每关重置**) |
| `STEPS` | 3 | 每回合步数(能量) |
| `HAND` | 5 | 每回合抽牌数 |
| `HANDMAX` | 9 | 手牌上限 |
| `COST_DIV` | 6 | **回合末开销 = `ceil(N/6)`** |
| `DEBT_PEN` | 2 | 每点债务回合末额外扣 2 预算 |
| `VMIN`/`VMAX` | 3 / 20 | 元素值域(每个元素要多少处理量才消失) |

### 2.3 回合流程

```
抽到 5 张 → 花 3 步出牌 → 结束回合(弃掉手牌)
  → 敌人结算:打乱 / 预处理衰减 / 规模×倍率 / 涌入新元素
  → 预算 −= ceil(N/6) + 债务×2(反悔陷阱下 ×4)
  → 抽 5,判定
```

**赢** = N 归零 · **输** = 预算 ≤ 0

### 2.4 四个乘区(上瘾引擎)

加法不上瘾,乘法才上瘾。每条流派各有一个可累积的乘区:

| 标记 | 位置 | 谁吃它 |
|---|---|---|
| **有序度 / 有序层数(0–4)** | 敌人 | 二分查找、中位数 |
| **段数(1–4)** | 盘面 | 逐层合并、并行处理 |
| **预处理值** | 你 | 查表、动态规划 |
| **债务** | 你 | 启发式、模拟退火(但每点回合末 −2 预算) |

有序度 = 相邻有序对比例,**归一化**为 `(比例−0.5)×2`(随机数组期望是 50%,不归一化会浪费一半量程)。

> **v4 起「排序」是真的排序。** 早期 `addSort()` 只给一个抽象数值 `sortBonus` 加值,柱子顺序纹丝不动——
> 于是排序卡打出去画面上什么都不会发生,而且有序度是**加出来的**不是**算出来的**,盘面和数值两张皮。
> 现在排序卡执行 `n × 6` 趟真冒泡,敌人的「打乱」也执行真随机交换。**有序度纯粹由数组算出。**

### 2.5 区(zones)

牌库 / 手牌 / 弃牌堆 / **消耗区**。牌库空自动洗回弃牌堆。
**消耗卡**打完移出本局:中位数、模拟退火、回溯。

## 3. 卡池(22 张,与代码一致)

### 3.1 起始牌组(每条流派各一套,10 张)

| 流派 | 起手牌 |
|---|---|
| base 不构筑 | 遍历×5 · 批处理×4 · 观察 |
| 排序流 | 遍历×4 · 批处理×4 · 预读 · 整理牌库 |
| 拆解流 | 遍历×3 · 批处理×4 · 预读 · 复用上一步 · 整理牌库 |
| 复利流 | 遍历×3 · 批处理×4 · 预读 · 复用上一步 · 整理牌库 |
| 激进流 | 遍历×4 · 批处理×4 · 预读 · 复用上一步 |

| 卡 | 步 | 效果 |
|---|:-:|---|
| 遍历 | 1 | 16 点处理量,平均分给每个元素 |
| 批处理 | 1 | 预算 +5 |
| 观察 | 1 | 抽 2 |
| 预读 | 0 | 看牌库顶 3 张,最贵的一张进手,其余放回 |
| 整理牌库 | 1 | 牌库按费用排序 —— 接下来先抽到便宜的 |
| 复用上一步 | 1 | 立刻重放你这回合打出的上一张牌 |

### 3.2 流派一 · 排序 → 查找(秩序流)

> 先整理再动手。前期慢,整理好之后每一击都放大。

| 卡 | 步 | 效果(**逐字取自代码**) |
|---|:-:|---|
| 冒泡排序 | 1 | 有序 +1 |
| 归并排序 | 2 | 有序 +3 |
| 快速排序 | 2 | 有序 +4(最坏用例下只 +1) |
| 二分查找 ×2 | 1 | 移除 1+有序层数×2 个(顺序访问下打七折) |
| 中位数 | 2 · **一次性** | 需有序≥3:移除 1/3 元素 |

### 3.3 流派二 · 分治 → 逐层(拆解流)

> 切段,然后每段同时处理。

| 卡 | 步 | 效果(**逐字取自代码**) |
|---|:-:|---|
| 分治 ×2 | 2 | 段数 +1(最多 4) |
| 逐层合并 ×2 | 1 | 每段移除 2 个 |
| 并行处理 | 2 | 段数×14 点处理量,平均分给每个元素(不可分下只剩四成) |
| 递归到底 | 2 · **一次性** | 需段数≥3:移除 1/3 元素 |

### 3.4 流派三 · 预处理 → 查表(复利流)

> 一次投入,永久收益。前期最弱,后期最强。

| 卡 | 步 | 效果(**逐字取自代码**) |
|---|:-:|---|
| 预处理 ×2 | 1 | 预处理值 +8 |
| 建表 | 2 | 预处理值 + 10+规模/4 |
| 查表 ×2 | 0 | 处理量 = 预处理值,平均分给每个元素;不消耗预处理值 |
| 动态规划 | 2 | 处理量 = 预处理值×2,平均分给每个元素 |

> **「查表不消耗预处理值」是这条流派的命门。** 早期写成消耗品时它比基础卡差 4 倍,胜率 3%。

### 3.5 流派四 · 贪心 → 近似(激进流)

> 不求最优,只求现在最好。快,但欠债 —— 每点债务回合末额外 −2 预算。

| 卡 | 步 | 效果(**逐字取自代码**) |
|---|:-:|---|
| 贪心 | 0 | 移除 2 个,债务 +1 |
| 局部最优 | 1 | 移除 5 个,债务 +2 |
| 启发式 ×2 | 1 | 移除 2+债务 个(债务按 6 封顶) |
| 模拟退火 | 2 | 移除 债务×2 个,清空债务 |
| 近似算法 | 2 · **一次性** | 移除 1/4 元素,债务 +3 |

### 3.6 通用工具(奖励池独有)

| 卡 | 步 | 效果 |
|---|:-:|---|
| 剪枝 | 1 | 增长倍率 −0.25;涌入 −1 |
| 回溯 | 2 · **一次性** | 预算 +12(每场限一次) |
| 边界条件 | 1 | 解除死循环;本回合免疫失误 |
| 哈希 | 1 | 抽 1;移除 2 个 |

> **剪枝是 Boss 的唯一解。** 不带剪枝打「指数爆炸」:分治/预处理 0%、排序 11%。

## 4. 敌人(11 种 + 6 失误,**本表由 `npm run doc` 从 `index.html` 生成**)

**三类必须分清:问题是本体,失误是干扰,对抗性输入是精英。**

> 表中 N 是 **depth 0 的基准值**,实战按 `n × (1 + 0.085 × depth)` 放大。

### 4.1 第一类 · 问题(战斗本体,岔口从这里抽两个)

| 敌人 | N | 涌入 | 性质(**逐字取自代码**) |
|---|:-:|:-:|---|
| 一团乱序数字 | 36 | 1 | 每回合涌入 +1、自我打乱(有序 −1) |
| 只能从头读的磁带 | 38 | 2 | 顺序访问:二分查找效果打七折 |
| 爬虫抓回来的重复页 | 40 | 2 | 值域窄、量大:平铺处理占便宜 |
| 实时价格流 | 38 | 2 | 数据在变:预处理值每回合 −6 |
| 社交网络的六度关系 | 38 | 1 | 稠密:每多切两段,每回合多涌入 1 |

### 4.2 第二类 · 失误(关卡环境效果,不是独立敌人)

挂在关卡上,概率 `min(0.8, 0.35 + 0.07×关号)`,第 1 关不挂。挂了的关卡**预算 +10** 作为补偿(见坑 #11)。

| 失误 | 效果(**逐字取自代码**) |
|---|---|
| 差一错误 | 移除 ≥6 时 −1 个、处理量 −10%(边界都差一格) |
| 空指针 | 每回合随机一张手牌不可用 |
| 竞态条件 | 你出的平铺类卡有 25% 概率只生效一半(顺序乱了) |
| 内存泄漏 | 每回合末额外 −1 预算 |
| 栈溢出 | 段数 ≥3 时每回合末额外 −2 预算 |
| 死循环 | 每三回合有一回合的第一张卡只生效 70%,除非出「边界条件」 |

### 4.3 第三类 · 对抗性输入(精英,不设岔口)

**没有这一层,流派就只是皮肤。** 五个精英 = 四个专克 + 一个通用。

| 敌人 | N | 涌入 | 性质(**逐字取自代码**) |
|---|:-:|:-:|---|
| 最坏用例 | 42 | 1 | 专克排序流:所有排序卡趟数打两五折 |
| 哈希碰撞 | 42 | 1 | 通用:每回合末随机丢 1 张手牌(键撞了,取不回来) |
| 反悔陷阱 | 41 | 1 | 专克贪心流:债务惩罚 ×2.2 |
| 状态爆炸 | 42 | 1 | 专克预处理流:预处理值上限 20 |
| 不可分问题 | 45 | 1 | 专克拆解流:段数上限 2、并行处理只剩四成 |

### 4.4 Boss

| 敌人 | N | 涌入 | 性质(**逐字取自代码**) |
|---|:-:|:-:|---|
| 指数爆炸 | 22 | 0 | 每回合末规模 ×倍率 — 加输出没用,得剪枝降阶 |

## 5. RUN 结构(v6 重写)

```
关1 岔口  关2 岔口  关3 精英  关4 岔口  关5 岔口  关6 精英  关7 岔口  关8 Boss
 (小怪)   (小怪)   无岔口    (小怪)   (小怪)   无岔口    (小怪)   无岔口
```

- **8 关**,形状写死在 `SHAPE`;小怪/精英从池里随机抽且**不重复**(`RUN.used`)
- **小怪关是岔口:两个候选二选一**,进关前看情报页对比。精英/Boss **不设岔口**
  —— 「对抗性输入」的定义就是冲你这套牌来的,能绕过去等于没有克制系统(见 12.3)
- 每关后 **三选一,可跳过**
- **难度轴只有一条:规模随深度连续放大** `n × (1 + 0.085 × depth)`。第 8 关约 +60%
- **玩家侧同步成长**:预算上限每过一关 **+3**(60 → 81),牌组 +7 张

## 9. 把知识送到玩家手里(A + B,已实现)

**问题**:「排序流碰上磁带从 73% 掉到 6%」这条结论,原本只有跑批量模拟才看得见。
玩家一局只经历一个敌人,输了心里想的是「运气不好」而不是「我这副牌不适合顺序访问的数据」。
**结论没被传达,只有惩罚被传达** —— 这是教育游戏最典型的失败方式。

### 9.1 A · 进关前情报页

进入每一关前显示:敌人身份 / 规模 / 涌入 / **逐条数据性质 × 你牌组里受影响的张数** / 总适配度。

```
第 1/5 关 · 小怪
一团乱序数字
规模 36 · 每回合涌入 1
─────────────────────────────────────────
 数据性质                          你的牌组
 ▼ 自我打乱:有序度每回合 −1 层     受影响 3 张
─────────────────────────────────────────
            牌组适配度:吃亏
```

**实测适配度矩阵(对角线即克制关系):**

| 牌组 | 磁带 | 最坏用例 | 哈希碰撞 | 反悔陷阱 | 稠密图 | 指数爆炸 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| 排序流 | **吃亏** | **不利** | 中性 | 中性 | 中性 | 吃亏 |
| 复利流 | 中性 | 中性 | **吃亏** | 中性 | 中性 | 吃亏 |
| 激进流 | 中性 | 中性 | 中性 | **不利** | 中性 | 吃亏 |
| 拆解流 | 中性 | 中性 | 中性 | 中性 | **吃亏** | 吃亏 |
| 排序流 + 剪枝×2 | 吃亏 | 不利 | 中性 | 中性 | 中性 | **中性** |

**每条牌组都在自己的克星那格亮红,带剪枝后 Boss 那格从「吃亏」转「中性」。**

判定表在 `PROPS`(代码),按敌人 flag 逐条匹配:
`seqOnly / shuffle / antiSort / antiMemo / memoCap / memoDecay / antiGreedy / dense / mult`,
另加正向项:窄值域 → 平铺类卡占便宜。

### 9.2 B · 失败后诊断

引擎全程埋点(`S.diag`),记录**被克制掉的量**:

| 埋点 | 记什么 |
|---|---|
| `lostKill` | 二分查找因顺序访问少移除的元素数 |

## 12. v6:难度曲线与关卡分配(本轮主攻)

### 12.0 起因:曲线是被量出来的,不是设计出来的

上一版有 5 关、路线写死、每关预算重置、敌人规模硬编码。**问它「难度怎么递增」的时候答不上来** —— 于是逐关量了一次(每流派 400 局,统计「到达该关的人里通过的比例」):

| 关 | 敌人 | base | sort | dc | memo | greedy |
|:-:|---|:-:|:-:|:-:|:-:|:-:|
| 1 | 乱序数字 | 100 | 100 | 100 | 100 | 99 |
| 2 | 磁带 | **21.8** | **57** | 94 | 99 | 90 |
| 3 | 精英 | 91 | 90 | 80 | 73 | 78 |
| 4 | 稠密图 | 98 | 100 | 97 | 100 | 98 |
| 5 | Boss | 73 | 78 | 67 | 65 | 85 |

结论很难看:

- **第 1 关和第 4 关是空气**(97–100%)
- **第 2 关是全场最难的关** —— 难度倒挂
- 曲线形状是「平 → 尖 → 平 → 中 → 尖」,不是递增
- 唯一随关卡递增的量是失误挂载概率(50%→75%);敌人规模不涨、预算每关回满、玩家每关 +1 张卡
  → **净效果是难度递减**,尖峰全部来自「特定敌人克特定流派」而非关卡深度

### 12.1 改成一条连续的难度轴

| 项 | 旧 | 新 |
|---|---|---|
| 关卡数 | 5(写死顺序) | **8**(形状写死、敌人随机不重复) |
| 敌人规模 | 硬编码 | `n × (1 + 0.085 × depth)`,第 8 关 +60% |
| 涌入 | 固定 | 固定(试过随深度 +1,**到第 5 关会断崖**,见 12.4) |
| 预算 | 每关回到 60 | 上限每关 **+3**(60→81),玩家侧同步成长 |
| 岔口 | 无 | 小怪关**二选一** |

### 12.2 敌人类型的实情(回答「现在就是乱序数组吗」)

**底层表示确实只有一种**:一排带数值的柱子。所有敌人共用这个结构,差异全在**标志位**上:

| 标志 | 含义 | 谁在用 |
|---|---|---|
| `shuffle` | 每回合自我打乱 N 次 | 乱序数字 / 实时价格流 / 最坏用例 |
| `inflow` | 每回合涌入几个 | 全部 |
| `vmax` | 值域上限(窄值域 = 平铺占便宜) | 重复页 |
| `seqOnly` | 顺序访问,二分查找打七折 | 磁带 |
| `dense` | 每多切一段就多涌入 | 稠密图 |
| `memoDecay` | 预处理值每回合衰减 | 实时价格流 |
| `mult` | 规模每回合乘以倍率 | Boss |
| `antiSort` / `antiGreedy` / `memoCap` / `noSplit` / `evict` | 五个精英各一 | 精英 |

**「社交网络的六度关系」不是真的图**,它是一个带 `dense` 标志的数组。这是原型的真实边界 —— 如果以后要做「树/图/矩阵」这类真正不同的数据结构,那是渲染层和 kill/work 语义都要改的另一件事,不是加个字段。

三层敌人的落地状态:

| 层 | 设计里的定义 | 实现 | 数量 |
|---|---|---|:-:|
| 问题 | 有规模可削减的本体 | ✅ 小怪 | 5 |
| 失误 | 攻击「你的执行」,没有可削减的对象 | ✅ **做成关卡环境效果**,不是独立敌人 | 6 |
| 对抗性输入 | 专克某一条流派 | ✅ 精英 | 5 |
| Boss | 增长率型 | ✅ | 1 |

### 12.3 岔口:一个差点把克制系统架空的设计

一开始**所有关都设岔口**,AI 按情报页的适配度选低难度那边。结果:

> **分治流死于「不可分问题」的次数 = 0** —— 它的克星,一次都没遇到。

岔口让玩家永远能绕开克你的精英,于是整个克制矩阵变成装饰。改成**只有小怪关设岔口**之后:

| 流派 | 头号死因 | 次数 / 400 |
|---|---|:-:|
| 排序流 | **最坏用例** | 121 |
| 分治流 | **不可分问题** | 129 |
| 预处理流 | **状态爆炸** | 132 |
| 贪心流 | **反悔陷阱** | 114 |

四条流派的头号死因,全部是它 designated 的克星。

### 12.4 三个隐藏的「非连续难度」

量出来才发现的:

1. **涌入的深度加成是整数** —— `+floor(depth/4)` 让第 5 关所有小怪突然多涌入 1 个,那一关胜率断崖到 50%。删掉,难度只走连续的规模缩放。
2. **自我打乱的次数写成 `ceil(N/14)`** —— 规模缩放让它二次放大(规模 +60% → 打乱也 +60%)。这是老坑 #2「效果随 N 放大」的复发。改成固定强度。
3. **Boss 的增长倍率随深度 +0.015/关** —— 让「需要几张剪枝」变得不可预期。倍率是 Boss 唯一的机制,不该再叠深度,只放大规模。

### 12.5 关键设计修复:每条流派都得有「随规模成长」的收尾卡

难度改成规模缩放之后,四条流派全崩,只有排序流活着(24.8%,其余 0–4%)。原因:

| 流派 | 收尾卡 | 是否随 N 成长 |
|---|---|---|
| 排序 | 中位数 = 移除 **N/3** | ✅ |
| 分治 | 并行处理 = 段数×14 | ❌ 固定 |
| 预处理 | 查表 = 预处理值 | ❌ 固定 |
| 贪心 | 全部按固定个数移除 | ❌ 固定 |

**规模缩放只养了唯一有比例型输出的流派。** 这不是数值问题是设计缺口。补:

- 分治 **递归到底**(2,一次性):需段数 ≥3,移除 N/3
- 贪心 **近似算法**(2,一次性):移除 N/4,债务 +3
- 预处理 **建表** 改成 `预处理值 + 10 + N/4` —— 表的大小本来就取决于输入规模

一改完:31.3 / 24.8 / 23.3 / 27.3,四条全部回到同一档。

### 12.6 哈希碰撞改成通用精英

5 个精英 4 条流派,预处理流被 `antiMemo`(哈希碰撞)和 `memoCap`(状态爆炸)**克两次**,通关率明显低一档。把哈希碰撞改成不针对流派的通用压力:

> **每回合末随机把 1 张手牌丢进消耗区**(键撞了,取不回来)

实测对四条流派 68% / 70% / 72% / 81% —— 均匀。同时删掉了已无敌人使用的 `antiMemo` 死代码和情报页里那条永不触发的规则。

## 13. v7:可读性 —— 卡面说不清「这一下会怎样」

试玩反馈原话:**「有些卡牌是做什么看不出来」「二分查找有的消一半数据,有的消一点点」「数据动画要不太快、要不就没效果」「灰色卡牌无法打出是因为?」**

三条都指向同一件事:**规则写在卡面上了,但规则算出来是多少、这一下到底改了什么,全靠玩家自己去右栏找数心算。**

### 13.1 卡面加一行「此刻的实算值 ← 由谁决定」

`live(id)` 拿当前战斗状态把公式算出来。不是替换规则文本,是加在它上面 —— 规则教你怎么推,实算值告诉你推出来是多少。

| 卡 | 原来卡面只有 | 现在多一行 |
|---|---|---|
| 二分查找 | `移除 1+有序层数×2 个` | **`现在移除 5 个 ← 有序层数 2/4`** |
| 逐层合并 | `每段移除 2 个` | `现在移除 6 个 ← 段数 3 × 每段 2` |
| 并行处理 | `总处理量 = 段数×14` | `现在处理量 42 ← 段数 3 × 14` |
| 启发式 | `移除 2+债务 个` | `现在移除 7 个 ← 债务 5(按 6 封顶)` |
| 查表 | `处理量 = 预处理值` | `现在处理量 24 ← 预处理值 24,而且不消耗它` |
| 建表 | `预处理值 + 10+规模/4` | `预处理值 12 → 32(按规模 38 算)` |

**「← 由谁决定」是关键。** 「有的消一半、有的消一点点」不是随机,是有序层数在变;不指名,玩家只会觉得这卡不稳定。

### 13.2 会落空的卡标红

六张卡在条件不满足时**能出、能花步数、但什么都不做**:中位数(有序层数<3)、递归到底(段数<3)、查表 / 动态规划(预处理值=0)、模拟退火(债务=0)、分治(段数已满)、边界条件(这关没挂失误)、剪枝(倍率和涌入都到底)。

现在这些情况卡面直接标红:`有序层数 1,不到 3 —— 现在出会落空`。**没有改判定规则**(改了会动平衡),只是把陷阱说出来。

### 13.3 出不了的卡要说明是哪一种

原来 `cardFace(..., canPlay(S,i) && !anim)` —— 有两个问题:

1. **`&& !anim` 让整排手牌在动画期间全变灰**(620–900 ms)。出完一张牌整只手灰掉大半秒,看着像卡死。**这是 bug**,去掉了。
2. 变灰不说原因。现在分两种,各有底栏文字:
   - 步数不够 → `步数不够 · 需 2,只剩 1`(琥珀色)
   - 空指针锁住 → `空指针锁住了这张`(红色)

### 13.4 动画:三类里有两类根本没有分支

查代码才发现 `arena()` 里只有 `sweep` 和 `split` 两个视觉分支。

| kind | 卡 | v6 的实际表现 |
|---|---|---|
| `sweep` | 遍历 / 查表 / DP / 并行处理 | ✅ 扫描线 |
| `split` | 二分查找 / 中位数 / 分治 / 递归到底 | ✅ 刀口 |
| `sort` | 冒泡 / 归并 / 快速排序 | ⚠️ 只有柱子插值,没有专属视觉 |
| `burst` | 贪心 / 局部最优 / 启发式 / 模拟退火 / 近似算法 / 逐层合并 / 哈希 | ❌ **没有分支** |
| `gen` | 批处理 / 观察 / 预处理 / 建表 / 剪枝 / 回溯 / 边界条件 | ❌ **没有分支,而且这 7 张根本不碰柱子 —— 屏幕上一动不动** |

补的东西:

- **`burst`**:被打掉的位置炸白光 + 扩散环 + 更多粒子
- **`sort`**:仍然逆序的相邻对在底部标红条 —— **能看见「还剩哪些没排好」**,配合柱子往阶梯收敛
- **飘字读数(`floatRead`)**:出牌前后各拍一次状态快照,差分出人话。这是 `gen` 那 7 张唯一的反馈来源,也顺便让另外三类多一层确认。
  `−5 个元素` · `有序层数 0 → 1` · `预算 60 → 65` · `抽 2 张` · `债务 +1` · `增长倍率 1.35 → 1.10` · `段数 1 → 2`
  一张牌什么都没改时,它会直说 **`这张没起作用`**。

- **时长**:sweep/split/burst 620 → 860 ms,sort 900 → 1150 ms,gen 700 ms;步数归零后的自动结算从 `+60 ms` 放宽到 `+300 ms`,留一拍看清楚。

### 13.6 「摊平」和「点杀」是卡池最基本的分野,却从没讲过

试玩第二轮:**「遍历卡牌的效果是什么『处理量 16 摊到 39 个元素上』?看不懂。」**

卡池里有两类完全不同的伤害:

| | 怎么算 | 谁 |
|---|---|---|
| **摊平** | 总处理量 ÷ 元素数,**每根柱子矮一点** | 遍历 · 并行处理 · 查表 · 动态规划 |
| **点杀** | **直接整根移除**,不看它多高 | 二分查找 · 中位数 · 贪心 · 逐层合并 · 启发式… |

摊平型「规模越大越吃亏」正是 `O(n)` 的手感来源 —— 但从没在界面上说过,`平铺` 这个词也没有任何地方解释。

改法:

1. **图例里加「两类卡」小节**,写清算法和各自属于哪些卡
2. **卡面把除法算出来**:`16 ÷ 28 个 = 每根矮 0.57 · 血条 −6%`
3. **别写「打掉 0 个」** —— 摊平型的贡献在血条上不在个数上,只说打掉几个会冤枉它。个数为 0 时不显示那一项,改说血条百分比
4. **规则那行不再用「平铺」**:`总处理量 16(平铺)` → `16 点处理量,平均分给每个元素`

## 16. v10:一个点击 bug,牵出三个更深的问题

试玩报告:**「点不动批处理这个卡了。上一把点击『遍历』,点好几下才有反应。是不是因为我直接双击 index.html?」**

**不是 `file://` 的问题。** 是三个叠在一起的真 bug,而且第一个从第一天就在。

### 16.1 命中框存在「卡」上,不是「手牌槽位」上

```js
C[id].box=[x,y,cw,ch]                                    // 画卡时:写在卡的定义上
for(let i=0;i<ids.length;i++) if(inBox(mx,my,C[ids[i]].box)){...}   // 点击时:按 id 取
```

**手牌里有两张同名卡时,后画的那张会把前一张的 `box` 覆盖掉。** 于是:

- 点左边那张 → 命中框在右边,整个循环走完都不匹配 → **什么都没发生**
- 点右边那张 → 循环从 `i=0` 起,`ids[0]` 就是同一个 id、`box` 又恰好是右边那张的 → 命中,但调用的是 `uiPlay(0)` → **打出的是左边那张**

「点好几下才有反应」就是这么来的:你点右边,左边那张飞了。

**起始牌组是 5×遍历 + 4×批处理 —— 重复是常态,这个 bug 每局都在发生。** 复现日志:

```
手牌 batch scan merge batch quick   点槽位 0 的 batch → 什么都没打出
```

改法:命中框按槽位存(`HITBOX[slot]`),不按卡存。修复后逐槽位点 17 次,17 次全部命中正确的那张。

### 16.2 空指针的锁定下标不跟着手牌左移

`S.locked` 是槽位下标。你打出一张比它靠前的牌,`hand.splice(i,1)` 让后面的牌全部左移,**但 `S.locked` 没动 —— 它现在锁在别人头上了。**

改法:`play()` 里 `if(S.locked!=null&&i<S.locked)S.locked--`。

### 16.3 动画期间的点击被静默吞掉

`uiPlay` 开头是 `if(anim||!canPlay(S,i))return`。v7 我把动画从 620 ms 拉长到 860~1150 ms,**等于把这个吞点击的窗口拉长了一倍。**

改法:点击时如果动画还在跑,**直接把它收尾**(`anim=null`),让这一下立刻生效。连点两下实测两下都生效。

### 16.4 修好 16.2 之后,空指针露出了原形

修复前后跑一遍才发现:**空指针实际上是「专克贪心流」**。

| 流派 | 无失误 | 挂空指针 | 掉点 |
|---|:-:|:-:|:-:|
| 排序 | 98% | 94% | −4 |
| 分治 | 100% | 99% | −1 |
| 预处理 | 100% | 100% | 0 |
| **贪心** | 89% | **55%** | **−34** |

原因:它锁「手牌里**最贵的**那张」,而贪心流的贵卡正是它的收尾牌(模拟退火 / 近似算法,都是 2 费)。以前 16.2 那个下标漂移的 bug 恰好把它抵消掉了 —— 贪心流每回合出的牌最多,漂移也最厉害。

**按设计,专克是精英的活(反悔陷阱已经克贪心了),失误只该攻击执行。** 改成随机锁一张,四条流派掉点回到 0~1 的均匀水平。

### 16.5 顺手量出来:失误是「净收益」,方向整个反了

改完之后重新扫 `FLAWBONUS`(挂失误的关卡补多少预算):

| 补偿 | 失误平均掉点 | 四流派通关率 | 极差 |
|:-:|:-:|---|:-:|
| +0 | **12.5** | 22.7 · 24 · 17.3 · 12 | 12.0 |
| +3 | 5.0 | 24.7 · 24 · 18.7 · 16.7 | 8.0 |
| +5 | 0.4 | 25.3 · 24.7 · 20.7 · 19.3 | 6.0 |
| +7 | −3.5 | 25.3 · 25.3 · 21.3 · 21.3 | 4.0 |
| **+10(v5–v9)** | **−7.9** | 26 · 31.3 · 23.3 · 25.3 | 8.0 |

**+10 时挂了失误的关卡反而更好打 7.9 个点。** v5 加这个补偿是为了解决「失误没补偿 = 直接判死」(坑 #11),但那是在吃紧对局上量的;放到中等难度的基线上就补过头了 —— **同一个数,在两个不同的基线上量出两个相反的结论。**

定 **+4**:既不判死,也确实更难。最终 24 / 27 / 19 / 18.5,极差 8.5(比之前的 12 更紧)。

## 17. v11:一个卡面小 bug,表现成「打赢了但游戏卡死」

试玩报告:**「我这样是成功了吧。怎么卡死了」** —— 截图里元素数 0、血条 0/100、回合 20,但没有进三选一。

### 17.1 从截图就能定位

不用猜。那张图上有两个异常:

1. **右下角的「结束回合」按钮和弃牌堆都没画出来**
2. **手里那张「遍历」只画到图标就停了** —— 没有实算值那一行,也没有「步数不够」的底栏,而旁边的批处理和观察两样都齐

`fightScreen()` 的顺序是 `handRow()` → `btn('结束回合')` → `discardPile()`。**画到遍历时抛异常,后面的全没画。**

### 17.2 根因:`wprev()` 会返回 null,四个调用点从没判空

这是 v7 修「遍历看不懂」时自己埋的雷:

```js
function wprev(tot){const a=alive(S); if(!a.length)return null   // ← 这里
 ...}
case 'scan': {const w=wprev(16)
  return ['16 ÷ '+w.n+' 个 = …']}                               // ← 直接取 w.n
```

**你打赢的那一刻元素数归零 → `wprev` 返回 null → 手里的遍历/并行处理/查表/DP 任意一张触发 `TypeError`。**

### 17.3 真正致命的是第二层:一次异常掐断整条 rAF 链

```js
const req=()=>requestAnimationFrame(draw)
```

`draw()` 末尾调 `req()` 排下一帧。**一旦 `draw()` 中途抛出,`req()` 就永远不会被调到 —— 渲染循环彻底死掉,画面永久冻结在那一帧。**

所以你看到的「卡死」其实是:游戏逻辑跑得好好的(700 ms 后 `afterFight` 正常执行、三选一也生成了),只是**没有任何一帧再画出来**。

一个卡面上的小空指针,被这条链路放大成了「游戏卡死」。

改法两层:

1. `live()` 开头加 `if(!alive(S).length)return null` —— 一处守住四个调用点
2. **`req()` 包 try/catch,保证循环无论如何都继续**,并且把错误摆到屏幕底部而不是只躺在控制台里:
   `渲染出错(游戏还在跑,按 1–5 可重开):<message>`

### 17.4 加了 G5:每张卡 × 5 种极端局面

光修这一处不够 —— `live()` 里有 25 个分支在读战斗状态,任何一个碰到边界值都会重演一次。所以把它钉进 `npm run check`:

```
25 张卡 × { 元素清零 · 全新开局 · 预算见底 · 段数满格 · 债务很高 } = 125 次渲染
```

**按纪律,新检查必须拿炸过的数据自检能失败** —— 临时撤掉 17.2 的判空重跑:

```
✗ G5 每张卡 × 5 种极端局面能渲染   元素清零/parallel: Cannot read properties of null
```

抓住了。恢复后 27 项全绿。

### 17.5 v11 踩的坑

| # | 坑 | 后果 |
|:-:|---|---|
| 41 | **`return null` 写了,调用点没接** | 「没有存活元素」和「算不出来」被塞进同一个返回值,四个调用点全都直接解引用 |
| 42 | **`req()` 在 `draw()` 末尾** | 渲染只要抛一次异常,rAF 链就永久断开。**兜底必须在循环外层**,不能指望被兜的那段自己不出错 |
| 43 | **异常只进控制台** | 玩家看到的是「卡死」,没有任何线索。现在错误直接印在屏幕底部 |
| 44 | **UI 崩溃这一整类以前完全没测** | 26 项检查全在测平衡,一条都没测「画得出来吗」。G5 补上 |

## 18. v12:把算法用在自己的牌库上

试玩追问:**「你没有加更多的卡牌玩法,也没有改变敌人是一个可视化的直方图?」**

对。上一轮我在修「不难受」,而问的是「更好玩」。

### 18.1 先量清楚:25 张卡其实只有 10 个动词

| 动词 | 用它的卡 |
|---|---|
| **移除 N 个元素** | 二分查找 中位数 递归到底 近似算法 贪心 局部最优 启发式 模拟退火 哈希 |
| **加/清债务** | 近似算法 贪心 局部最优 启发式 模拟退火 |
| **处理量摊到每个元素** | 遍历 并行处理 查表 动态规划 |
| 加有序度 / 加预处理值 / 加段数 / 加预算 / 抽牌 / 改成长率 / 免疫一回合 | 各 1~3 张 |

**三个动词占了 18 张卡。** 换名字换数字,做的是同一件事 —— 这才是「重复」的来源,不是卡的数量。

而且更大的空白:

> **排序、二分、哈希、记忆化 —— 25 张卡全部只对敌人用。**
> 作用在自己身上的动词只有两个:加预算、抽牌。而这两张正好是最没存在感的卡。
>
> **可你的牌库本身就是一个数据结构。**

### 18.2 新动词:对自己的牌库用算法

| 卡 | 费 | 效果 |
|---|:-:|---|
| **整理牌库** | 1 | 牌库按费用排序 —— 接下来先抽到便宜的 |
| **按需检索** | 1 | 从牌库里直接翻出最贵的一张到手上 |
| **预读** | 0 | 看牌库顶 3 张,最贵的一张进手,其余放回 |
| **复用上一步** | 1 · 一次性 | 立刻重放你这回合打出的上一张牌 |
| **压缩** | 1 | 弃牌堆立刻洗回牌库,再抽 1 |

**「预读」把牌库顶三张的名字直接印在卡面上** —— 游戏里第一次出现「你能看见接下来会抽到什么」这种决策。

### 18.3 第一次尝试失败了:放进奖励池 = 白加

先把五张牌加进奖励池,实测:

| 流派 | 牌库卡出牌占比 | 遍历占比 |
|---|:-:|:-:|
| 全部四条 | **1%** | 仍然 31~33% |

原因很直白:**奖励池里已经有 26 张卡,一局只加 7 张 —— 新卡根本抽不到,而那 10 张起始牌永远在。**

**新玩法必须进起始牌组。** 这一条对以后所有「加卡」的提案都成立。

### 18.4 换起始牌组时炸出的东西:牌库操作 = 除牌

换成 `遍历×3 + 批处理×4 + 预读 + 复用 + 整理` 之后,27 项检查挂了 6 项 —— 而且**克制矩阵全线松动**(排序 vs 最坏用例 30% → 69%)。

我先怀疑是「复用上一步」让专克失效(复用一次等于把两五折变成五折)。**猜错了** —— 三种限制方案下都还是 71%。逐张换才找到元凶:

| 起始牌组 | 排序 vs 最坏用例 | 拆解 vs 不可分 |
|---|:-:|:-:|
| 原版(遍历5 批4 观察1) | 30% | 9% |
| 只删观察(9 张) | 34% | 5% |
| **只删 2 张遍历(8 张)** | **64%** | **31%** |
| 观察→预读 | 24% | 10% |
| 观察→整理 | 24% | 7% |
| 全套 F | 69% | 38% |

**是「删了 2 张遍历」。** 而三张新卡单独换进去反而让它更难。

这正是我自己在 v2 提案里引用过的那条:**每删一张牌,抽到关键牌的概率就上升**。我以为在「换废牌」,实际做的是**精简牌组** —— 三条提案里效果最大的那一条。两件事一起做,数字当然爆。

> **推论:牌库操作卡本质上就是除牌。** 预读/整理/复用都是在提升抽牌质量,和「删掉一张烂牌」是同一类效果。所以加它们必须同时加强敌人。

### 18.5 落地:精英 +2 血 + 每流派各自的起手牌

- **五个精英血量 +2** —— 单这一项就把克制矩阵拉回目标内(44/24/30/36,上限 45/25/45/55)
- **起始牌组改成每条流派各一套**(杀戮尖塔每个角色起手牌就不同)

第一次统一换牌组时,排序流冲到 39%、激进流掉到 14%,极差 25。原因是新卡吃步数,而激进流靠「一回合出一堆便宜牌」。给它多留一张遍历、不给整理牌库就平了。

```
sort   遍历×4 批处理×4 预读 整理牌库
dc     遍历×3 批处理×4 预读 复用上一步 整理牌库
memo   遍历×3 批处理×4 预读 复用上一步 整理牌库
greedy 遍历×4 批处理×4 预读 复用上一步
```

### 18.6 结果

| | 改之前 | 改之后 |
|---|:-:|:-:|
| **遍历出牌占比** | 32~35% | **18~25%** |
| **牌库操作占比** | 0% | **12~16%** |
| 通关率(排/拆/复/激) | 25.5 / 30 / 17.5 / 19.5 | **26 / 31 / 22 / 27** |
| **四流派极差** | 12.5 | **9** |
| 检查 | 27 项达标 | **27 项达标** |

**拆解流和复利流的出牌量第一名不再是「遍历」了** —— 变成了「逐层合并 22%」和「查表 19%」,也就是它们自己的核心牌。
