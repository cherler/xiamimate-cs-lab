# ADR 0001 · 四层流水线与五条接缝

**日期**：2026-08-17
**状态**：接缝 1/2/4 已落地并验证；3/5 已定义未实现

## 背景

要做的不止 408。造物型（手搓 CPU、逆向拆解、PCB→实体）和机器人学都在计划里，
而且**造物型才是最终想去的地方**。如果只按 408 设计，到那一步要重写。

## 关键区分

**408 只需要仿真，造物型必须要编辑。** 这是两种不同的核心循环：

| | 仿真 | 编辑 |
|---|---|---|
| 状态是什么 | 随时间演进的**轨迹** | 一份被修改的**文档** |
| 核心操作 | `step()` → 下一个状态 | `apply(edit)` → 新文档 |
| 后退 | 轴上拖动 | undo / redo 栈 |
| 正确性怎么判 | 跟参考实现比对轨迹 | 规则检查（DRC / 类型检查） |

## 决定：一条流水线，不同的路从不同位置进入

```
文档 Document ──compile()──▶ 仿真模型 SimModel ──run()──▶ 轨迹 Trace ──▶ 渲染 / 验证
     ▲                            ▲
造物型从这里进                408 从这里进
```

## 五条接缝

### 1. `compile(doc) → simModel` 必须现在就存在

408 阶段几乎是恒等映射 —— 但**函数存在**。
到手搓 CPU 时，`compile` 从恒等映射变成网表提取 + 拓扑排序，**上下游一行不用改**。

> 这是预留扩展点的正确做法：**不是提前实现，是提前把接缝划在正确的位置。**

**已落地**。`sweep.ts` 里由外层 doc 派生 N 个内层 doc，算是第一次轻度拉伸。

### 2. 验证器四种比较器

`exact` / `tolerance(eps)` / `structural` / `property`，共享同一个 `Violation` 结构。
现在只用 `exact`，但四种都已定义 —— 不分开的话，到 PCB 那条路时 DRC 会另起炉灶。

**已落地**（`src/core/verify.ts`）。`tolerance` 已有测试；`structural` / `property` 已定义未用。

### 3. `Exporter` 接口

```ts
interface Exporter { format: string; export(doc, trace?): Blob }
```
408 导出视频素材和分享链接；手搓 CPU 导出 Verilog；PCB 导出 **Gerber**；机器人导出 **URDF**。

**未实现**。Gerber / URDF 都是开放格式，不受 GPL 约束，自己写。

### 4. `Axis` 泛化 + `entities` 支持嵌套

轴不能硬编码成"时间"：`time` / `step` / `parameter` / `depth`。

这条的成本是零 —— **408 自己就需要两种轴**：逐步执行（`time`/`step`）和参数扫描（`parameter`，
命中率随组数变化的曲线就是它）。逆向拆解的 `depth` 只是白搭一程车。

**已落地并验证**。四种轴里三种已实测（`step`/`time`/`parameter`），`depth` 未用。
`entities` 嵌套未实现。

### 5. 渲染层可替换

408 走 SVG+DOM，机器人学走 three.js。多视图架构本来就要求渲染可替换。

**未实现**（还没有视图层）。

## 代价

现在多花 1–2 周，换六条路共用底座。
不做的话，到造物型那一步是重写文档层、重写验证器、重新设计导出 —— 那是几个月。
