# 标准

三类：架构验收 · 内容标准 · 依赖准入。

原则：**不会失败的检查等于没有检查。** 每条架构标准都配一个"故意做错的版本"，
必须先确认那个版本能把检查弄红，这条标准才算立住。

---

## 一、架构验收（六条）

### 1. Model 不知道 View

把渲染层整个删掉，仿真还能在 Node 里跑完并输出轨迹。

> **为什么是硬要求**：验证器要在服务端跑仿真。这条不过关，验证器根本做不了 ——
> 而验证器是整个产品的护城河。

**自检必须能红**：故意在内核里读一次 `document` 或 `window`，Node 环境下必须立刻炸。

**现状**：✅ 三个内核零 DOM 依赖，`npm test` 在纯 Node 下跑通。

---

### 2. 状态可序列化 + 确定性重放

任意时刻 dump 状态 → JSON 往返 → 重新载入 → 继续跑，结果跟没中断过完全一致。

> 时间轴 scrub、回放、分享链接、断点续做 —— 共同前提。

**自检必须能红**：往 `step()` 里塞 `Math.random()`，或在状态里放不可序列化的东西
（闭包 / Map 里的对象引用 / `Date`），重放结果必须对不上。

**现状**：✅ `tests/phase0-convergence.test.ts` 测试 2；自检在测试 3b。

> ⚠️ **这条抓到过真问题**：三个独立参考实现全都违反了它 —— Cache 把 `sets` 藏在闭包、
> 调度把 `sliceLeft` 藏在闭包、TCP 把"push 之后才更新的 cwnd"藏在控制流里。
> 三个跑起来都对，但都没法中途存档。见 `logs/2026-08-17-phase0.md`。

---

### 3. 单向数据流

加第四个视图，不用改前三个视图的任何代码。视图永不直接改视图。

**自检必须能红**：故意让视图 A 直接写视图 B 的状态，架构检查或 lint 规则必须拦下来。

**现状**：✅ 已验（`scripts/web-smoke.mjs` 测试 2）。
点一个时间轴刻度 → **读数 / 轴 / 日志 / 舞台四处同时更新**，实测确认。
架构上唯一的真相来源是 `doc` + `index`，其余全部派生；视图之间零互写。
新增一个实验只需往 `web/src/registry.ts` 加一条，宿主框架一行不用改。

---

### 4. 输出是轨迹，不是结果

仿真返回每一步的状态快照序列，不是最终答案。

> 这是教学产品和工具产品的分界线，也是验证器逐步比对的前提。

**自检必须能红**：拿一个"最终结果对、中间过程错"的伪实现喂给验证器，必须被判失败。

**现状**：✅ 自检在 `tests/phase0-convergence.test.ts` 测试 3a（抓到 5 处）。

---

### 5. 内核可插拔

换一个领域内核，宿主框架一行不用改。

**自检必须能红**：写一个什么都不做的空内核塞进去，框架必须正常起来并显示空轨迹；
起不来说明框架里藏了对具体内核的假设。

**现状**：✅ 两重验证。
- **高阶内核**：`sweep.ts` 的 `step()` 里跑了一整个子仿真，外层 `run()` 完全无感 ——
  "step 内部是内核私事"这条抽象扛住了压力测试。
- **极端退化内核**：空内核 / 单步 / 永不结束 / 靠 null 收尾，四种都不崩
  （`tests/kernel-pluggable.test.ts`）。
- 自检：一个"假设每个内核至少有个初始状态"的坏 `run()`，在空内核上给出 1 步（正确 0 步）。

---

### 6. DSL 是唯一入口

删掉所有实验代码，只留 JSON，能完整重建。

> AI 生成的前提。

**自检必须能红**：造一个"从模块常量读配置"的内核，改 doc 对它无效，必须被抓住。

**现状**：✅ 三重验证（`tests/dsl-sole-entry.test.ts`）。
- **JSON 往返**：序列化 → 丢掉原对象 → 从字符串重建，三个实验轨迹全一致。
  *一个 Cache 实验只要 210 字节* —— 对 AI 生成是好消息。
- **每个参数都真的起作用**：7 项改动（相联度 / 替换策略 / 块大小 / 调度算法 / 到达时刻 /
  TCP 变体 / 丢包轮次）逐个改，轨迹必须跟着变。
- 自检：写死轮次的"泄漏内核"，改 `rounds` 14→30 纹丝不动，被抓住。

## 二、内容标准：一个实验算合格的四条

1. **有参考实现比对通过** —— 不是"看起来对"，是跟第三方实现逐步对齐。
2. **有"边界"栏** —— 诚实标注失真范围。粒子先生写"二维截面近似""忽略边缘效应"；
   我们写"不含 TLB""假设指令与数据共用 L1""忽略预取"。
   *这是竞品最容易省掉的一步，也是专业信任建立最快的地方。*
3. **有逐步文字日志，跟轴联动** —— CS 相对物理的独有优势：每一步的"为什么"都能说清楚。
   拖轴日志高亮，点日志跳到那步。
4. **至少挂一道真题** —— 没有题的实验是玩具，有题的实验是产品。

## 三、依赖准入：引入任何第三方前必须过

| 检查 | 不过怎么办 |
|---|---|
| 许可证是 MIT / Apache 2.0 / BSD？ | GPL 系一律不进产品代码；**但可以当验证器的外部参考基准**（跑它、比对输出，不链接代码） |
| 看的是仓库里的 LICENSE 文件，不是 GitHub 侧栏的 SPDX 标签？ | 标签错的不少，必须开文件确认 |
| 还在维护？（星速 = 星数 ÷ 开源月数，另看停更月数） | 停更超一年的重依赖不进主链路 |
| 能不能只用一小块，不整包吞？ | 不能就重新评估 |

许可证台账见 [research/licenses.md](research/licenses.md)。
