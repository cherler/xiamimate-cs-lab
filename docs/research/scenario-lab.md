## 一、为什么是这三块（而不是物化生）

**护城河只在计算机领域成立。** 去做物理，验证器当场消失 ——
物理的"对不对"程序判不了，赛道退化成"谁美术好谁赢"，那是必输的一项。
计算机是唯一一个正确性能被**程序自动判**的领域。这不是偏好，是结构。

**而这条线有一个物化生给不了的性质：用户会长大。**

| 段 | 谁 | 凭证 | 载体 |
|---|---|---|---|
| **408 专业课** | 在校生 / 考研 | 我考过了 | 真题 + 判题 + 进度 |
| **算法应用** | 求职 / 在职 | 我能做这个决策 | 目标 + Pareto + 可追溯的实验记录 |
| **大模型** | 在职工程师 | **还没有** —— 见第四节 | 先做教学，凭证后找 |

高中物理学完就不学了，用户到点流失。**这条线上，毕业不是终点。**

## 二、唯一共用的纪律：真值来源

三块共用的不只是 `step()`，是**同一种"真值来源"的写法**：

- 408 的真值来自**教材参考实现**
- 算法应用的真值来自**公认的工业实现**（NMS 对 OpenCV、检索对 hnswlib）
- 大模型的真值来自**数学定义或真分词器**

**都是"跟一个第三方实现逐步比对"**，只是把教材换成工业。这才是三块共用一条护城河的原因，
而不只是"都用同一个 `step()`"。

### 把它变成门禁，不是文档里的建议

> **说不出真值来源的场景，不进。**

落成 `Experiment` 上一个**必填字段** + 一条会红的判据。理由：
408 有考纲，做完就是做完了；**「算法应用」和「大模型」没有考纲，也没有边界** ——
16 个场景能变成 60 个，每个都要新内核、新舞台、新资产，永远做不完，
而且过程中会一直觉得"再加一个就完整了"。

这道闸能挡掉大部分诱惑，因为绝大多数"看起来很酷的场景"
（模拟真实用户、预测留存、复刻生产系统）都答不出这一问。

## 三、算法应用：怎么算「务实」

定下的方向是**从工业应用上找真实场景，不务虚**。落成两条可判定的闸。

### 闸一：说得出「谁、在什么时候、做这个决定」

这条比"有没有工业参考实现"更前置，也更好用：

- NMS 分数阈值 → **视觉算法工程师上线前必调** ✓
- 寻路启发式权重 → **AGV / 游戏 AI 调** ✓
- A/B 实验的样本量与能否提前停 → **每个做增长的人都会撞** ✓
- "模拟一个推荐系统" → **没有哪个岗位在做这件事** ✗
  （真实决策是"探索率设多少""多样性惩罚加多重"，题目就得写成那个样子）

### 闸二：真值来源分档

| 档 | 来源 | 例子 |
|---|---|---|
| 硬 | 公开工业实现，可逐步比对 | OpenCV NMS · hnswlib · tiktoken |
| 硬 | 公开标准 / 数学定义 | MTU · IEEE 754 · 统计功效公式 |
| 需标出处 | 公开论文 / 行业数据 | 缺陷漏检成本 · 缩放定律 |
| **不进** | "业内一般这么做" | — |

### 16 个候选过完闸之后

**第一梯队（真值硬 + 决策真，六个）**

| 场景 | 真实决策是什么 | 真值来源 | 比较器 |
|---|---|---|---|
| **视觉后处理** | 分数阈值 / NMS 阈值 / TopK 怎么定 | OpenCV，逐框比对 | `exact` |
| **传感器异常检测** | 窗口长度、报警阈值、冷却时间 | Z-score / EWMA / CUSUM 公式 | `exact` |
| **检索排序** | BM25 与向量各占多少权重 | 公开实现 | `exact` |
| **RAG 分块** | chunk 大小、重叠、TopK | 检索是确定性的 | `exact` |
| **A/B 实验设计** | 样本量算多少、能不能提前停 | 统计功效公式 · CUPED | `exact` |
| **网格寻路** | 启发权重、斜向代价 | 数学定义 | **`property`**（路径合法 + 代价最优） |

> A/B 实验那条是"信息流与商业决策"一组里**唯一真值站得住的** ——
> 其余（推荐、电商、广告、反欺诈）的数都出自自己编的用户模型。

**第二梯队（决策真，但真值是编的）**：信息流推荐 · 电商推荐 · 广告投放 · 反欺诈 · AGV 调度 · 流式背压

这些**不叫实验，叫沙盘**。实验承诺"这个数是算出来的"，沙盘承诺"在这套假设下会这样"。
名字不同，承诺就不同，用户不会误读。**招牌换掉，它们仍然值得做。**

**第三梯队（已有内核，换个问法就是职业层）**：缓存策略 · 任务调度 · 负载均衡 · 数据库查询计划

**另加一组 · 大模型 infra**：KV cache 显存账 · 并行切分后每卡显存 · Flash Attention 的 HBM 访问量 ·
**Radix Cache 前缀命中率** · MoE 路由。前四条真值硬（算术 / 论文公式 / 前缀树），
性能那一档（吞吐 · 延迟 · TTFT · 调度）归**第三档「需标出处」+ 沙盘招牌**，滞后做。
细节见 [`llm-lab-inventory.md`](llm-lab-inventory.md) 第九节。

408 里已经有 Cache / 调度 / 页面置换 / 磁盘调度。区别只是**问法**：
以前问"答对这道题"，以后问"在这个约束下选哪个策略"。**这一组的边际成本接近零** ——
它也是"三块一体"最直接的证据：同一个内核，两段人生。

### 目标怎么顶替真题

| 真题有 | 目标怎么补 |
|---|---|
| 唯一答案 | 不需要唯一，要**可判定的达成 / 未达成**（`goal.met`） |
| 外部权威（考纲） | 换成**真实工程约束**：4ms · 24GB · P95 200ms。**数字必须说得出来源** |
| 有界范围 | 旋钮 3–8 个 |
| 可自动判分 | 验证器 |

**好目标的形状是固定的**：「在 X 不劣于 Y 的前提下，把 Z 压到最低」。

**三种坏目标（这条路上的主要死法）**：

1. **单目标最大化**（"把命中率调到最高"）→ 扫一遍取最大就完了，没有权衡就没有工程判断
2. **约束不咬合**（约束太松，随便都满足）→ 退化成第 1 种
3. **阈值是拍的**（说不出 4ms 从哪来）→ 用户一问就露馅，"职业感"当场崩

**目标相对真题的优势**：真题有一个答案，目标有**一条 Pareto 曲线**。
用户学的不是"哪个数最高"，是**"我在曲线上选了哪个点，为什么"** —— 这是真题教不了的。

## 四、大模型：先教学，但探索要有停损线

方向定的是：**先把原理用可视化模拟出来；后续再做真实公司场景。这块大家都在探索，我们就当探索。**

清单已经有 —— [`llm-lab-inventory.md`](llm-lab-inventory.md) 53 个实验，**89% 落在甲带**
（算术 / 数学 / 算法，浏览器现算、`exact` 可验），只有 6 个要预计算轨迹。

**它能进这套引擎的唯一理由，是它不需要 GPU、不需要在线模型。**
一旦某个实验开始需要"跑真模型"，它就不属于这个实验室了 —— 这条是硬边界。

### 凭证还没有，所以要有停损线

"我看懂了 attention"不构成凭证，没人为看懂付钱。探索是对的，但探索也要有停下来的判据：

1. 先做第一批 5 个（优化器赛跑 · 决策边界 · 卷积扫描 · 中文分词 · 采样旋钮台）
2. 看传播数据 —— 这几个是上镜度表里的 ★★★
3. 再决定往"公司场景"走，还是就停在造物层当免费引流

**做不出凭证不等于失败**：造物层本来就是付时间不付钱那一层，跟应试层共用内核、边际成本接近零。
要认的只是别指望它变现。

## 五、「一体」落到哪三个接口

说三块一体，得落到具体的东西上，否则只是三个并排的产品：

1. **同一个 `Experiment` 协议** —— kernel / params / stage / readouts / bounds / **真值来源** / goal
2. **同一条流水线** —— `Document → compile → step → Trace → 渲染 + 验证`
3. **同一套学习状态** —— 进度、错题本、目标达成

第 3 条最容易被忽略，但它是"用户会长大"的**技术落点**：
一个人从 408 走到算法应用时，**他的进度是连续的**，不是换了个产品从零开始。
现在 `progress` 只认 139 道真题，要提前想清楚它怎么容纳"目标达成"这类记录。

## 六、现在就能做的 / 必须等的

先后关系不是"做完 A 才碰 B"，是**分清 B 的哪一部分现在就能做**：

| 现在就能做（不抢 408 的资源） | 成本 |
|---|---|
| `Experiment` 加「真值来源」必填字段，30 个实验各填一句 | 约一天 |
| 场景清单按两条闸过筛 | 已完成，见第三节 |
| `progress` 预留"目标达成"的位置 | 跟 `goal` 一起想，不单独花时间 |

| 必须等 | 等什么 |
|---|---|
| 新内核 / 新舞台 / 新资产 | 26 个实验单 + `goal` 铺完（现在 4/30） |
| 第一个场景实验 | 建议 **视觉后处理**（`exact` 可验，跟现有 30 个同档）。**不是寻路** —— 寻路会把 `exact` 打破，第一块试金石该证明"新领域也能进严格档"，不是"新领域逼我们放宽标准" |

## 七、未决

- **规模不会因为多两块就上一个台阶。** 蓝图已认"大概率年营收百万级"。
  三块乘出来大概率仍在同一量级，除非算法应用真打进企业培训 —— 那是另一门生意（有销售、有交付），别提前算进预期。
- **模块至今没有真实用户。** `status` 还是 `planned`、入口藏着。这一条一天都没验过。
- **名字。** 蓝图写了"不叫考研 408"。三块并线后更要紧，但**不急着改** ——
  等算法应用有一个跑通的实验再说；现在改名是给一个还不存在的东西起名。
- **第二梯队那六个"沙盘"的用户模型怎么写、假设怎么标**，完全没想。
- **视觉后处理的图片资产从哪来没定。** 一个出口是**合成图**（代码画的划痕/污点/缺角）：
  零资产、可按种子无限生成，而且 Ground Truth 是画的时候就知道的 —— 比标注真图的真值还硬。没验。
