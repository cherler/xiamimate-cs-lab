## 一、诊断：不是配色，是布局的前提

`web/src/styles.css:229`

```css
.grid{grid-template-columns:178px minmax(0,1fr) 236px}
```

左右两列固定吃掉 **414px + 间距 ≈ 436px**。1440 宽的屏幕上中列只剩约 1000px，
中列里还依次摞着 tabs、序列编辑器、实体编辑器（`max-height:30%`）、舞台、轴。
**舞台实际拿到的面积约占全屏 30–35%。** 样板里同样内容量下量到 **63.4%**。

更能说明问题的是 `styles.css:258` 那段注释 —— 编辑器从 34% 压到 30%，还写着"再往下压不划算"。
**在跟布局搏斗，说明前提本身有问题**：前提是「参数、读数、编辑器必须常驻可见」。

三条病：

| # | 病 | 后果 |
|---|---|---|
| 1 | **九个同级容器**（目录卡 / tabs / 序列编辑器 / 实体编辑器 / 舞台 / 轴 / 参数面板 / 读数面板 / 底部坞），每个都有边框和标题栏，全部等权重 | 没有主次 = 后台管理系统 |
| 2 | **控件离它作用的对象很远** —— 参数在右列，舞台在中列，拧一个旋钮眼睛要横跳 600px | 因果链断了 |
| 3 | **tabs 是平铺切换，不是 zoom** | 27 张讲解卡只能是"平的"，没有层级可挂 |

对照 Transformer Explainer 论文自述的三条设计原则（多层次抽象平滑过渡 · 交互 · 浏览器内真实推理），
cs-lab 缺的是**第一条**。

**第三次跟布局搏斗**（2026-08-18 `aec03bc`）：实验单最后选择**盖住整个中列**，
`logs/2026-08-18-brief.md` 给的理由是「只盖舞台那一块，实测 276px 的框装 570px 的内容，藏掉一半还多」，
以及「反正没动手之前，页签、编辑器、轴也都还没有意义」。
连同编辑器 34%→30%、底部坞从三块竖摞改成三选一 —— **三次都在绕开同一个前提。**

**但要先承认一件事：** 主干式样板做出来后，用户的反馈是"说不上好还是坏"。
这句话本身是最有用的反馈 —— **布局好看解决不了"看不看得懂、留不留得住"**。
所以下面第二、三节才是主线，本节只是主线的容器。

## 二、任务层：实验单已经做了一半，只差「达成判定」

> ⚠️ 本节 2026-08-18 晚重写。原稿提议"新建任务层、写 30 条判定"——
> 写完才发现**另一条工作线当天已经把前半截做掉了**（`aec03bc`）。原估算作废。

### 2.1 已经有的：实验单（`web/src/brief.ts` + `shell/Brief.tsx`）

起因是同一句话：「实验是什么？我还是不知道。不知道要做什么？为什么要做？」

| 段 | 内容 | 判据 |
|---|---|---|
| ① 为什么在乎 | 不懂这个会在哪儿吃亏 | `brief-content.test.ts` 卡「不许短于 80 字」——废话和真话在代码里长得一样，只有长度挡得住占位符 |
| ② **先猜一下** | 押注；不押不给往下走，押了**不马上揭晓** | — |
| ③ 动手 | 两三条具体动作，复用 `TryStep` | 冒烟核对页面上真有那个旋钮/预置 |
| ④ 结论 | `verdict(ctx)` **从当前轨迹现算** | 喂两组假数据，**结论文本与对错判定都必须跟着变**——挡「是函数、返回常量」 |

**②那一条比本文件原稿提的强**：押注是行为承诺，不是说明文字。原稿没想到这一层。
④现算的理由跟本文件同源：写死一句话印在一个保证正确的仿真旁边，是最坏的位置。

### 2.2 还缺的两点

1. **「调出来」那一档没有。** ③ 是照着做的动作，④ 是事后结论 ——
   中间没有一个**「你还没达成 / 你达成了」的持续状态**。这一档才是把验证器接到用户面前的那个。
2. **实验单是入场一次性的**（`刷新不再自来`），关掉目标就消失了。

### 2.3 最小形态：给 `Brief` 加一个 `goal`

**判定所需的一切已经在了** —— `VerdictCtx` 里有 `doc` / `trace` / `runDoc`，`verdict` 已经在用它重算。
所以不是新建一层：

```ts
goal?: {
  say: string                        // 「把命中率提到 80% 以上」
  met: (ctx: VerdictCtx) => boolean  // 跟 verdict 共用同一次 runDoc
}
```

常驻显示（主干上方 / 现有页眉的 chips 位），形如 `目标 80% · 现在 62.5%`。

三档目标里，只有中间那档是新的：

| 档 | 靠什么 | 现状 |
|---|---|---|
| 跟着做 | 走到末步 | 轴回放已有；`bb9c5cb` 之后到末步会自动停 |
| **调出来** | `goal.met` | **新的**，也最像游戏 |
| 讲出来 | 已有判题 | 139 个问题已有 |

「调出来」把参数面板从"设置"变成"解谜"，而它**只有在验证器在场时才成立** ——
没有自动判定，"调出来"就没有终点。这是绝大多数教育产品做不了真游戏化的原因，
它们只能发徽章。cs-lab 能判。

### 2.4 时效性：必须跟任务 #10 同时做

下一步是把实验单铺到其余 29 个实验（样板 `brief.ts`，验收在 `brief-content.test.ts` + 冒烟第 15 组）。

**`goal` 晚一步加，就要把 29 个实验再过一遍。**
而 ④ 的 `verdict` 本来就在算命中率这类数，`goal.met` 多半是同一个数上加一个比较 ——
同时写几乎不增加成本，分开写要翻倍。**这是个现在说才有用的判断。**

### 2.5 不做的六条

积分 · 徽章 · 连续登录 · 排行榜 · 剧情 · 角色 · 关卡美术。
前四个是外在动机 —— 对"明天要考试"的人没用，对"好奇点进来"的人反而扫兴，还要做账号体系与防作弊；
后三个跟内核零复用、成本极高、做不好就是尬，而且没有美术。

### 2.6 一条硬边界

**目标必须是可选的邀请，不能是门。**
408 学生很多是来查一个知识点的，"通关才能自由玩"会直接赶走他们。
实验单已经守住了这一条（关掉之后刷新不再自来），`goal` 也要照办。

## 三、图鉴：按共享原语组织，且是任务的副产品

### 3.1 它的作用是总览与欲望，不是解释

图鉴解释不了什么（那是讲解卡的活）。它真正能干的事是：**让人第一次看见"这几个实验其实是同一件事"。**

所以**按共享原语组织，不按课程**。`BitField.tsx` 的注释自己写着这句话：

> IEEE754 的符号/阶码/尾数、虚地址的 VPN/页内偏移、CRC 的被除数、
> 海明码的校验位/数据位、子网掩码的网络号/主机号 —— 都是同一件事。

教材按课程切，永远给不出这张表；**cs-lab 的引擎结构天然能给**。
大模型那批直接接上去：BPE 合并与 Huffman 是同一个原语，在图鉴里就该在同一格。

候选原语轴：**位串 / 队列 / 表 / 树 / 图 / 窗口 / 缓冲 / 时空图**。
（哪些原语真的成立，要拿 30 个实验逐个过一遍才知道 —— 见未决。）

### 3.2 收集与理解绑在一起

**素材是在任务里被用到的时候才被看懂的。**
所以图鉴不是入口，是任务的副产品：**用过的原语自动点亮，灰的是还没碰过的**。
免费复用现有的进度机制，不新建一套状态。

## 四、主干式布局

### 4.1 主干

**每个实验都有一条主干，主干就是这个实验的数据流。** 不是新概念，是把舞台从"一张图"改成"一条流水"。

| 实验 | 主干 |
|---|---|
| Cache | 地址 → 拆位域 → 定组 → 比 tag → 命中/缺失 → 淘汰 |
| 调度 | 就绪队列 → 选中 → 运行 → 时间片/阻塞 → 完成 |
| TCP | 发送窗口 → 网络 → 接收 → ACK → 窗口滑动 |
| 数据包封装 | HTTP → +TCP 首部 → +IP 首部 → +以太网首部/FCS |
| Huffman | 频率表 → 合并 → 树 → 编码 |

**参数旋钮长在它作用的那一段上，读数长在它产生的那一段上** —— 不是把右列缩小，是把它拆开贴回去。

```
┌──────────────────────────────────────────────────┐
│ 实验名 · 一句话                    [巡演][沉浸][目录▾]│
├──────────────────────────────────────────────────┤
│ ◎ 目标：把命中率调到 80% 以上          现在 62.5%  │  ← 主角是任务，不只是数据流
├──────────────────────────────────────────────────┤
│   ①输入 ─▶ ②拆解 ─▶ ③查找 ─▶ ④结果      读数 ▤▤▤ │  ← 主干 55%+
│            ▲旋钮      ▲旋钮                       │
├──────────────────────────────────────────────────┤
│ 拆解深度 ━━●━━━  ·  封装步骤 ①②③④  ·  视角 ━●━   │  ← 轴（可多根）
├──────────────────────────────────────────────────┤
│ 逐步日志 · 真题 · 边界（收起时只一行）              │
└──────────────────────────────────────────────────┘
```

**左侧目录收成下拉** —— 30 个实验的目录不该常驻占一列，它是"换实验"时才用一次的东西。

**顺序很重要：任务层先定，前端再动。** 主干最上面那一行放什么，取决于任务长什么样；
反过来做要返工一次。

### 4.2 三层 zoom

| 层 | 是什么 | 讲解卡挂哪 |
|---|---|---|
| **L0 概览** | 主干四五个方块 + 箭头，什么都不展开 | 讲整体。**这一屏就是封面和截图** |
| **L1 展开一段** | 点一段，它就地长大露出内部结构，其他段缩小变暗（同一屏此消彼长，不是切页） | 讲这一段 |
| **L2 钻到一格** | 点内部某一格，给这一格的数字来源与公式 | 讲这一格 |

27 张平的卡不用重写，**是重新挂位置**。锚点机制（`guide.ts` 那套一处定义两个方向用）现成的。

### 4.3 三种动画，别的一律不动

**流动**（推进一步，数据沿主干走一段，180ms）· **长大/缩小**（zoom 切换，320ms）· **点亮**（当前步涉及的元素，120ms）。

### 4.4 两个为素材而设计的功能

- **沉浸模式** —— 一键藏掉目录、chips、坞，只留主干 + 轴铺满窗口。
- **自动巡演** —— 不用人操作，自己按节奏走完一遍并在关键步停顿。**这是 4 秒抓手的前提**：录屏时鼠标不该出现在画面里。

参照的地球日夜四季那支录屏就有「沉浸模式」和「全屏」两个按钮 —— 它知道自己要被录屏。

### 4.5 配色

深底为主（发光和连线只在深底上成立）。语义色三个：当前（琥珀）· 成功/命中（绿）· 失效/缺失（红），其余全灰阶。
现有的 `npm run contrast` 门槛（浅色 0 处不达标、深色不新增欠账）不能松。

## 五、伪 3D 爆炸（"逆向拆解"提前到场）

蓝图第六条路「逆向拆解」写的是 `轴换成 depth`、`entities 嵌套` —— **接缝 4 就是为它划的**。
爆炸不是新功能，是给现有的轴换一个语义：拖动滑块 = 层间距从 0 拉到最大。
它跟 `time` 轴**正交**（一根管时间推进，一根管拆解深度），样板里两根轴同时在底栏。

### 5.1 只对真有层级的东西做

| 类 | 例子 | 判断 |
|---|---|---|
| 甲 · 真实空间层级 | 网络封装、多级页表、存储层次、磁盘几何、整机拆解、文件系统块 | 天然成立 ★★★ |
| 乙 · 约定图示层级 | Cache 组×路×行、B+树、AVL | 能做，空间是虚构的 ★★ |
| 丙 · 纯时序无结构 | 调度、信号量、银行家、排序、KMP | **别硬做**，会变成为动画而动画 |

大模型那边：**权重体积**（Q/K/V/O/FFN 按真实参数量做成体积块）· **张量形状**（`[batch,seq,heads,dim]` 切片）·
**层堆叠**。第一个尤其值得做 —— 参数量计算器在上镜度表里只有 ★，同一份数字换成体积块就跳到 ★★★，
**数据一行没变，只换了渲染**。

### 5.2 爆炸图不进验证器

它是**渲染**，不产生轨迹，没有对错可判 —— 是素材价值和教学价值，**不是护城河**。
好处是接缝 4 的 `entities` 嵌套让它能从同一份 doc 派生，不用另建一套数据。

## 六、渲染选型：一条死线

| 库 | 是什么 | 结论 |
|---|---|---|
| **GSAP** | 动画时间线编排库（一串动画按什么顺序、重叠多少、什么曲线播）。**不做 3D** | **不引。** 三种动画用 CSS transition 就够 |
| **three.js** | WebGL 3D 引擎：真几何、材质、光照、相机 | **不引**，留给蓝图原本安排它的地方（机器人学） |

**对"平板堆叠"这类，伪 3D 不是次优解，是更优解**：

|  | 伪 3D（CSS `preserve-3d`） | three.js |
|---|---|---|
| 依赖 | 0 | 现在 `dependencies` 只有 react，这会是第一个重依赖 |
| 单文件 HTML | 不受影响 | 文件涨一大截 |
| 手机 | 流畅 | 要挑机器 |
| 文字标注 | DOM，清晰可选中 | 3D 里的文字是老大难 |
| 现有 SVG 舞台 | **直接复用** | 全部重画 |

three.js 只在三种情况赢：真实曲面与光照（地球那种）、需要绕到任意角度看的实体、成千上万个物件。
**408 与大模型的实验里一个都不属于。** 所以：

> **除非要渲染一个真实存在的物体，否则不引 three.js。GSAP 一直不引。**

`BitField.tsx` 的注释写着"一串位，按语义切成几段"—— 网络封装的每一层就是一条位域带，
四条带堆起来错开就是爆炸图。**基本是白捡的。**

## 七、样板里实测到的三个坑（不是推理，是撞出来的）

| # | 坑 | 现象 | 解 |
|---|---|---|---|
| 1 | **`backdrop-filter` 会强制 `transform-style:flat`** | 整块板被压平，反向旋转的标注全是斜的 | 3D 链路上任何祖先都不许有 filter / backdrop-filter |
| 2 | **`overflow:hidden` 同样压平 3D 上下文** | 同上 | 圆角改用 `:first-child/:last-child` 的 border-radius，不靠 overflow 裁 |
| 3 | **`setPointerCapture` 会劫持随后的 `click`** | 浮层里的「返回主干」按钮永远点不动，且**不报错** | 只有位移 > 4px 真的拖起来才捕获；`onclick` 里判 `dragging` |

第 3 条最值得记：**它没有任何报错，靠看是看不出来的**，只有点一下才发现。
真做的时候冒烟脚本要有"每个浮层的返回按钮都点一遍"这一条。

3D 里的文字唯一不糊的做法：**反向旋转**（`rotateZ(-rz) rotateX(-rx)`，顺序反着写），
标注永远正对相机。样板里的层名牌、位域名、旋钮全用这个。

## 八、TE 抄什么，不抄什么（许可证逐个开 LICENSE 核过）

| 拿走什么 | 载体 | 许可证 |
|---|---|---|
| 流线画法：连线宽度由真实数字驱动，不是装饰 | `d3-sankey` | BSD-3-Clause（Mike Bostock, 2015）✓ |
| 公式随手展开 | `KaTeX` | MIT ✓ |
| 交互语法与信息架构 | 看就行 | MIT（Polo Club of Data Science, 2022）✓ |
| （动画时间线，暂不用） | `GSAP` | GreenSock "no charge"，Webflow 赞助后含全部插件、商业可用 ✓ |

**框架不同，组件搬不过来** —— TE 是 SvelteKit 2 + Svelte 5，cs-lab 是 React。抄的是思路。

**明确不要 `onnxruntime-web` + `transformers.js`**（都是 Apache-2.0，许可证没问题）：
TE 是学术站，用户在电脑前专门来看它，等几十上百 MB 模型下载没关系。
**cs-lab 的分发是短视频 → 手机点开**，首屏几百毫秒不出画面就没了。
所以在这儿**预计算轨迹优于浏览器内实时推理** —— 同样的画面，几十 KB 的 JSON 就够。
这不是技术偏好，是被分发场景逼出来的。

## 九、"用素材 DIY 一个模型"

落在**接缝 1（`compile(doc) → simModel`）**上：408 的文档层是退化的（一组参数），DIY 就是把它升级成一张结构图。

| 档 | 用户做什么 | 验证器 | 判断 |
|---|---|---|---|
| **① 搭结构，看形状与参数量** | 拖入 embedding / attention / FFN / norm，设维度 | `structural`（形状接不接得上）+ `exact`（参数量算术） | **做这个** |
| ② 搭小网络并在浏览器里真训练 | MLP / 小 CNN，玩具数据 | `property` + `tolerance` | 第二步（TF Playground 已证可行，Apache-2.0） |
| ③ 搭 Transformer 跑真前向 | 需要权重 | 随机权重只能验形状；真权重进丙带 | 只做"看结构不跑推理" |

**为什么押①**：DIY 的乐趣是"我搭的东西对不对"，①就能给这个反馈 —— 维度接不上就红，参数量当场算出来。
成本是②③的十分之一，而且每个初学者都算错过形状。

**顺带一个发现**：蓝图说接缝 1 要等"手搓 CPU"那步才真正用上。
**大模型 DIY 比手搓 CPU 更早、更便宜地把 `compile()` 激活** —— 一张层的堆叠图编译成计算图，
比网表提取 + 拓扑排序简单一个量级，却同样证明那一刀划对了。要验接缝，这是最便宜的验法。

诚实说：DIY 出来的模型没有唯一正确答案，比较器从 `exact` 降到 `structural`。
它是**造物层**（免费引流），不是应试层。

## 十、「无需联网、白板能开」要不要追

`npm run web:single` 已经有这个能力，现在只是没被当卖点讲。但"卖给学校"是另一回事：
需要销售、教材对齐、采购流程、发票、售后 —— 跟现有的强项（内容）和弱项（分发）都不匹配。

**判断：能力留着，说法改掉，市场别追。**
单文件对我们的真实价值不是白板，是**零摩擦分发** —— 短视频下面挂链接点开就玩（不注册、不加载），
整个实验室能塞进一个文件发给同学。所以卖点写成「点开就玩 · 能转发」，
不是「支持一体机白板」—— 后者会引来接不住的售前问题。

## 十一、未决

- **「给目标能提升留存」没有证据**，只是推理。最便宜的验法：拿 Cache 一个实验加 `goal`，
  跟不加的版本比停留时长。**做之前先想清楚怎么量**（见 [[measure-before-tuning]] 那条纪律）。
- **两条工作线在同一个仓库里。** 本文件与 `llm-lab-inventory.md`、`mockups/spine-encap.html`
  只动 `docs/`；`web/` 与 `src/` 归任务 #10 那条线。**改之前先确认分工没变。**
- **原语轴还没验。** 「位串 / 队列 / 表 / 树 / 图 / 窗口 / 缓冲 / 时空图」是拍的，
  要拿 30 个实验逐个过一遍，看哪些真的落得进去、哪些是硬塞的。
- **主干是每个实验一条，不是一套模板套 30 遍。** 真实工作量在这儿，样板只证明了一个实验成立。
  30 个里有多少抽得出主干、抽不出的该长什么样，没逐个过。
- **样板只在 Chromium 上跑过。** Safari 的 `preserve-3d` 层级排序另有坑，没测。
- **移动端完全没测。** 现有窄屏策略是"退回可滚长页"，主干横向铺开在手机上怎么办，没想。
- **「游戏」这个词对外怎么说没定。** 对学生不是问题，但如果任何时候要面对老师/家长，是减分项。
