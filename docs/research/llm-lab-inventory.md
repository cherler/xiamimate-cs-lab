# 大模型实验清单与素材台账

> 2026-08-18 调研。回答一个问题：**大模型有没有足够多的"实验"可做？**
> 结论：有 53 个。不缺素材，缺的是筛子 —— 判断哪些能进 `文档→编译→仿真→轨迹→渲染+验证` 这条流水线。

---

## 一、筛子：三条带

物理化生的实验多，是因为每个实验对应一个**可操作的现象**。大模型里能对应"可操作现象"的知识点，
按**真值从哪来**分成三带 —— 这直接决定用哪个比较器、要不要 GPU、能不能进离线产物。

| 带 | 真值来源 | 比较器 | 在浏览器里 | 数量 |
|---|---|---|---|---|
| **甲** | 算术 / 算法 / 数学定义，有第三方参考实现可逐步比对 | `exact` · `tolerance` | 现算 | 47 |
| **丙** | 只能跑真模型才知道（注意力图谱、残差流） | 「与冻结产物一致」 | 预计算轨迹随包发 | 6 |
| **丁** | 没有独立真值，或已排除 | 无 | — | — |

**丁带明确不做**：推理引擎 / 调度 / 吞吐 / 并行 / 成本沙盘（用户已定，不碰）；
"模型为什么这么答"的归因（没有验证器，违反 AI 只放作者侧那条）；任何需要运行时调 API 的东西。

**甲带占 89%** —— 这是大模型相对 408 的意外优势：408 的内核要一个个手写，
大模型这边一大半是**公式与算术**，参考实现是现成的开源库，验证器比 408 还好接。

## 二、甲带：47 个（浏览器现算，`exact` 可验）

### A. 分词（9 个）——「中文为什么更贵」

| # | 实验 | 拧什么 | 看什么变 | 参考实现 | 轴 |
|---|---|---|---|---|---|
| A1 | BPE 编码逐步 merge | 输入文本 · 分词器 | 每一步合并了哪两个符号 | tiktoken / HF tokenizers 离线跑，逐 token 对 | `step` |
| A2 | BPE merge 表训练 | 语料 · 目标词表大小 · 最小频次 | merge 规则逐条产生 | HF `tokenizers` trainer | `step` |
| A3 | 中/英/日同义句 token 效率并排 | 句子 · 模型集合 | 同一句话在各模型里几个 token | 同上 | — |
| A4 | UTF-8 字节化与 byte fallback | 生僻字 · emoji · 全角符号 | 一个字符碎成几个字节几个 token | 同上 | `step` |
| A5 | 空格与大小写敏感 | `" the"` / `"the"` / `"The"` | token id 完全不同 | 同上 | — |
| A6 | 数字切分 | 数字 · 小数 · 日期 | `1234` → `123`+`4`，算术为何出错 | 同上 | — |

### B. 结构与算术（7 个）——「7B 为什么要 14G」

| # | 实验 | 拧什么 | 看什么变 | 参考 |
|---|---|---|---|---|
| B1 | 参数量计算器 | 层数 · d_model · 头数 · FFN 倍数 · vocab | 各部分参数量堆叠条 | 与真实模型公布值对账（算出来必须等于 6.7B） |
| B2 | MHA / MQA / GQA | KV 头数 | 参数量与缓存量同时变 | 算术 |
| B3 | KV 缓存显存公式 | 层数 · 头数 · 序列 · batch · dtype | 显存条 | 算术（**只做公式，不做调度**） |
| B4 | 注意力 O(n²) | 序列长度 | FLOPs 与内存的面积图 | 算术 |
| B5 | LoRA 秩 | r = 1→256 | `W = W₀ + BA` 的矩阵形状与可训练占比 | 算术 |
| B6 | 量化舍入 | FP32/FP16/BF16/INT8/INT4 | 逐数值误差 + 权重直方图 | IEEE 754 + 量化公式 |
| B7 | dtype 位域拆解 | 符号 / 指数 / 尾数 | 位翻转对数值的影响 | **复用现有 `float.ts`** |

### C. 位置与注意力（6 个）

| # | 实验 | 拧什么 | 看什么变 |
|---|---|---|---|
| C1 | 注意力手算 | 3–5 个 token 的 Q/K/V 小矩阵 | 每格数字点开看来源 |
| C2 | 为什么除 √d_k | 维度 d · 除或不除 | softmax 饱和、熵塌陷 |
| C3 | causal mask | mask 开关 | 概率如何重分布 |
| C4 | 正弦位置编码 | 维度 · 波长 | 热力图条纹 |
| C5 | RoPE 旋转 | 位置 · base θ | 一对分量在单位圆上转；改 base 看长程衰减 |
| C6 | ALiBi 线性偏置 | 斜率 | 偏置矩阵与远距离衰减 |

### D. 采样与解码（6 个）——「温度到底是什么」

| # | 实验 | 拧什么 | 看什么变 |
|---|---|---|---|
| D1 | logits → softmax | 一组 logits | 分布形状 |
| D2 | 温度扫描 | T = 0.1→2.0 | 分布与熵（轴 = `parameter`） |
| D3 | top-k / top-p 截断 | k · p | p 与实际保留个数的非线性关系 |

| D6 | 似然陷阱 | beam 宽 | 越大越无聊（玩具语言模型） |

### E. 训练机理（9 个）——CS 基础，也是 408 的自然延长

## 三、丙带：6 个（要离线跑真模型，产出冻结轨迹）

| # | 实验 | 需要什么 |
|---|---|---|
| 丙1 | 真实注意力头图谱（每层每头） | 预置句子 × 小模型，冻结成数据文件 |
| 丙2 | attention sink（首 token 吸走注意力） | 同上 |
| 丙3 | logit lens / 残差流逐层成形 | 同上 |
| 丙4 | 词向量空间导航（king−man+woman） | 公开小词向量表 |
| 丙5 | 中英同义句的真实 loss / 成本对比 | 同上 |
| 丙6 | 同 prompt 不同分词器的真实输出差异 | 同上 |

**这引入了第三类资产：预计算轨迹。**
现有的两类是「手写 preset」和「内核现算」。预计算轨迹介于两者之间 ——
作者侧离线跑一次真模型，把 trace 冻成数据文件随包发，运行时零模型调用。
它符合"AI 在作者侧、产出审过的静态资产"那条纪律，但会牵动仓库体积与构建流程，
**所以排在甲带之后，不要一起做**。

## 四、跟现有内核的复用清单

大模型这条路不是从零堆内核。32 个现有内核里至少 6 个能直接换皮：

| 现有内核 | 用到哪 |
|---|---|
| `float.ts` | B7 dtype 位域 · B6 量化舍入 |
| `huffman.ts` | A1/A2 BPE 也是频率驱动的合并，渲染几乎同构 |
| `dijkstra.ts` `topo.ts` `mst.ts` | G1 HNSW 图搜索 |
| `hashtable.ts` | G4 相似度 / LSH |
| `sort.ts` `compare.ts` | D3 top-k 截断 |
| `cache.ts` | B3 的讲解侧类比（KV 复用 ≈ 命中率） |

## 六、第一批做哪 5 个

全在甲带 · 零 GPU · 零预计算 · 验证器全是 `exact` · 至少一半复用现有内核：

1. **A1 中文分词逐步**（复用 `huffman` 的合并渲染）
2. **A3 token 成本并排**（中 / 英 / emoji / 代码）
3. **D2+D3 采样旋钮台**（温度 · top-k · top-p 一屏）
4. **B1+B3 参数量与显存计算器**（复用 `float.ts`）
5. **C1 注意力手算 5×5**

合起来正好回答四个每天被问、却没人讲清的问题：
中文为什么更贵 · 它为什么数不清字 · 温度到底调的是什么 · 7B 为什么要 14G。

**在这 5 个跑通之前不碰丙带。**

## 七、未决 —— 不能当结论的

- **中文空地这个判断，一组关键词都没搜过。** 按「搜索面本身就是结论」，动手前要跑满 20 组，
  且直接翻 B 站 / 知乎 / 小红书，不只搜网页。分词可视化不是空地（tiktokenizer 一类已存在），
  空地在于「中文 + 逐步过程 + 可验证 + 讲解层」，而不是"显示 token 边界"。
- **付费假设未验证。** 见 `blueprint.md` 的三层定价 —— 大模型这条线自然落在**造物层**（免费），
  因为全球最好的同类（Transformer Explainer / TF Playground / GAN Lab）都是学术免费产物。
  它可能带来一个新的**应试层 SKU：AI / 算法岗笔面试**（手撕 attention、推参数量与显存），
  跟 408 的"题库 + 判题 + 进度"完全同构 —— 但这个市场的规模、支付意愿、竞品全未验证。
- **丙带的仓库体积没估过。** 冻结轨迹随包发，多大、要不要按需加载，没算。

## 八、第二个判据：上镜度（2026-08-18 补，看完地球日夜四季那支录屏）

参照物：`xiamimate-h3-lab/references/douyin/manual/地球日夜变化与四季交换.mp4`
（58s · 2160×2160 · 60fps · 个人作者 Jason Wong · URL 路径写着「销售版」）。

### 它为什么好拍 —— 四条，都不是美工

| # | 它做对的 | cs-lab 现在的反面 |
|---|---|---|
| 1 | **渲染的是所有人认得的实体**：地球、晨昏线、四季 | Cache 行、进程条、TCP 窗口 —— 必须先讲是什么，才能看。4 秒里没时间讲 |
| 2 | **变化连续、大幅、自己会动**：球在转，晨昏线在扫，不点也有画面 | 离散步进，要点「下一步」才动，一步只变一格颜色 |
| 3 | **有一个美的底子**：真实纹理、城市灯光、大气辉光 | 抽象结构图没有底子可借 |
| 4 | **字幕直接说卖点**，不讲原理：「超真实光影拟真」「360 度全自由视角」「3D 互动方式展现抽象的教学内容」 | — |

**所以结论是：选题决定素材，不是美工决定素材。**
想要能拍的东西，就得选**渲染真实图像或连续空间**的实验，而不是渲染表格的实验。

### 它顺手证明的两件事

- **「HTML 单文件 · 浏览器打开 · 无需联网 · 支持一体机 / 电脑 / 平板 / 白板」是它字幕里的卖点。**
  cs-lab 的 `npm run web:single` 早就有这个能力，但从没当卖点讲过。白捡的一条。
- **它的付费对象大概率是老师和学校**（路径里是「销售版」，还专门做了「教材同步视角」——
  切成教材里那张太阳-地球轨道图）。这提示 `blueprint.md` 那张三层定价表缺一格：
  **老师可能比学生更愿意付钱**，且不需要做题库判题，只需要「跟教材那张图长得一样」+ 能离线在白板上打开。

### 双判据矩阵：验证器强度 × 上镜度

两个判据是**打架的** —— 对验证器最友好的（B 带算术），对镜头最不友好。必须分开选，不要指望一个实验两头占。

| 实验 | 验证器 | 上镜 | 说明 |
|---|---|---|---|
| E3 优化器赛跑（SGD/Momentum/Adam 同曲面） | `exact` | ★★★ | 四条彩色轨迹在等高线上冲向谷底，像赛车。**双判据都满分** |
| F1 决策边界随训练扭动 | `exact` | ★★★ | 彩色区域自己在动，不用操作 |
| F2 卷积核扫描 + 特征图点亮 | `exact` | ★★★ | 真图片上滑窗，人人认得 |
| F5 扩散去噪（玩具 2D） | `exact` | ★★ | 点云聚成形状；**真图片扩散更震撼但要进丙带** |
| 丙4 词向量空间 3D 导航 | 冻结产物 | ★★★ | 做成「语义星图」，视觉量级跟地球同档 |
| 丙1 注意力连线在一句话上亮起 | 冻结产物 | ★★ | — |
| A1/A3 分词与 token 成本 | `exact` | ★★ | 画面一般，但**问题本身是钩子**（「中文为什么更贵」） |
| D2 温度扫描 | `exact` | ★★ | 要有真文字输出才好看 |
| B1/B3 参数量与显存计算器 | `exact` | ★ | 最好验、最难拍。留着做内容，不做素材 |
| C1 注意力手算 5×5 | `exact` | ★ | 同上 |

**一条不舒服的观察**：最上镜的（优化器、决策边界、卷积、词向量）恰恰是**最经典**的那批；
最"大模型"的那批（分词、注意力、采样）反而不上镜。
这不是坏事 —— **经典那批拍片引流，大模型那批留人**。

## 九、Infra 一组（2026-08-19 补，看完 LLM-Infra-Explorer）

参照：[LLM-Infra-Explorer](https://github.com/skyliulu/LLM-Infra-Explorer)（**AGPL-3.0，只看形态，代码一行不碰**）。
它覆盖八块：推理全景 · 并行策略（DP/TP/PP/CP/EP/ETP）· Flash Attention · Flash Decode ·
Engram · Radix Cache · Linear Attention · DP Attention。

### 它做对的三件事

1. **选的是 infra 不是架构图** —— KV cache、并行切分、分块注意力、前缀复用，
   都是推理引擎工程师**每天在调的东西**，天然过「说得出谁在什么时候做这个决定」那道闸。
2. **交互是 compose + compare** —— 组一个配置跟另一个比，正是职业层要的「目标 + Pareto」形状。
3. **张量切分 + GPU rank 映射** —— 把抽象变成**可数的东西**：`[b,s,h,d]` 被 TP 切成几块、落在哪几张卡上，
   纯算术、画得准。跟本清单 B 组「结构与算术」同源。

### 它弱在两条 —— 恰好是我们已经有的

- **不告诉你哪张图是算的、哪张是画的。** 读者不知道该信到什么程度，就只能整个不信。
  这正是「真值来源」门禁要治的病（见 [`scenario-lab.md`](scenario-lab.md) 第二节）。
- **不问你任何问题。** 没有目标、没有押注、没有判定 —— 看完只知道"有这么个东西"。
  这是实验单 ② 和 `goal` 要补的。

> **它的内容比我们深得多，但它的框子比我们弱。**

### 该做哪些：两档，都要做，先后不同

**第一档 · 算术（真值硬，浏览器现算，`exact`）**

| 实验 | 真值来源 | 备注 |
|---|---|---|
| KV cache 显存账 | 形状 × dtype 的算术 | 本清单 B3 已有 |
| TP / PP / DP 切分后每卡显存 | 算术，可跟公开模型配置对账 | |
| Flash Attention 的 HBM 访问量 | **论文给的公式**（标出处） | 算的不是跑的 |
| **Radix Cache 前缀命中率** | 前缀树，确定性匹配 | ⭐ 见下 |
| MoE 路由与负载均衡 | 给定路由器输出，top-k 确定 | |

> ⭐ **Radix Cache 是这一组里最值钱的一条**：它本质就是一棵**前缀树** ——
> 跟 408 已有的 KMP / 哈夫曼 / B+ 树是同一个家族，`exact` 可验，
> 而且回答一个真实问题：**多轮对话与批量请求，共享前缀能省掉多少 prefill**。
> 真值硬 · 决策真 · **跟 408 的内核同源** ——「三块一体」最漂亮的一个例子：
> 学生在数据结构学过前缀树，工程师在推理服务里用它省钱，**同一棵树**。

**第二档 · 性能（吞吐 / 延迟 / TTFT / 调度 / 并行通信）**

> ⚠️ 2026-08-19 修正。原来这一档被写成"明确不进"，理由是"真值只能实机测"。
> **那是判错了**：把"真值弱"说成了"没有真值"。

- **它的真值来源是「公开的解析模型」** —— roofline、Little 定律、论文里的公式、
  引擎文档里写明的调度行为。落在 [`scenario-lab.md`](scenario-lab.md) 第三节的
  **第三档「需标出处」**，不是没有真值。
- 给定模型之后，那些数**确实是精确算出来的**；不确定的是**模型合不合真机** ——
  而那正是 `bounds` 要写的东西（"不含 kernel 启动开销 · 不含通信重叠 · 不含 NCCL 拓扑"）。
- **招牌用「沙盘」不用「实验」**：沙盘承诺"在这套假设下会这样"，不承诺预测真机。

**为什么要做**：AI 基础设施是正在成形的高薪岗位，而这一档正是那个岗位每天在权衡的东西 ——
它属于职业层，付费意愿比应试层强。开源项目能做，我们也能做，而且我们多两样东西：
真值来源的分档，和会红的判据。

**排序**：第一档先做（真值硬、成本低）；第二档**滞后**，等前面跑通再上。

### 一条只有我们有的升级路径

第二档最弱的一点是"模型不一定合真机"。而**本机那台 4060 Ti 能把它标定** ——
拿 vLLM 之类实测一组 TTFT / 显存曲线，回来校准解析模型，并在页面上标明
"这条曲线在 4060 Ti + 某版本上量过，误差 ±X%"。

全世界的推理可视化都是纸上模型，**没有一个是拿真机量过的**。
这条从「需标出处」升到「有实测标定」，是别人抄不走的那一段。⚠️ 没验，只是路径。

### 明确不进的

- Flash Attention 的 **GPU 内核时序**（真值只能靠 profiler，进来就把验证器废了）
- 任何需要**在线调模型 API** 的东西（成本地板 + 运行时不确定，见 [[explain-not-runtime-ai]]）
